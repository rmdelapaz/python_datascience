🏭 Think in Whole Arrays

In Lesson 1.1 you wrote week * 2 and revenue / visitors, and you measured how much faster those are than a loop. This lesson turns that one trick into a way of working. The goal is that by the end, when someone asks "which days beat $15,000, and what was the average on sale weekends?", your first thought is an array expression and not a for statement.

💡 Mental Model: The Workbench and the Assembly Line

A Python loop is a craftsperson at a workbench: pick up one item, inspect it, work on it, put it down, pick up the next. Careful, flexible, and slow.

A vectorized operation is an assembly line. You set the machine up once ("multiply by 1.08") and the whole batch flows through it. The machine can be fast precisely because every item on the belt is the same kind of thing, which is the one-dtype rule you met in Lesson 1.1.

"Vectorized" simply means one operation, applied to a whole array, with the loop running inside NumPy's compiled code. You get three things from it: speed, shorter code, and code that reads like the question you are asking.

Start a new notebook. Every column of daily_sales.csv will be useful today, so a small helper saves typing. It is the np.genfromtxt call from Lesson 1.1 with the column number as a parameter.

import numpy as np

    """Read one column of daily_sales.csv into an array."""
    return np.genfromtxt("data/daily_sales.csv", delimiter=",",
                         skip_header=1, usecols=col, dtype=dtype)

visitors = load(2)
transactions = load(3)

print(visitors.shape, transactions.shape, revenue.shape)

Four arrays, each with one value per store per day, all in the same order. Position 0 in every array describes the same store-day (Asheville on January 1, 2024), position 1 the next, and so on. Arrays that line up like this are sometimes called parallel arrays, and they are what makes the next section work.

➗ Array-with-Array Arithmetic

When both sides of an operator are arrays of the same shape, NumPy pairs them up by position: first with first, second with second. Two retail measures fall straight out of that.

conversion = transactions / visitors     # share of visitors who bought something
basket = revenue / transactions          # dollars per purchase

print(conversion[:4].round(3))
print(basket[:4].round(2))

Output

[0.254 0.26  0.204 0.229]
[98.37 79.48 87.68 92.78]

On the first day in Asheville, 51 of 201 visitors bought something (25.4%), and the average purchase was $98.37. You computed that for all 2,903 store-days in two lines.

You can chain as many operations as you like in one expression. Each step produces a new array, and the originals are left alone. Here is the profit on a list of products, given a price, a cost, and how many of each were sold:

price = np.array([299.95, 82.95, 24.50, 149.00])
cost = np.array([187.74, 41.20, 11.76, 80.46])
sold = np.array([12, 40, 115, 22])

profit = (price - cost) * sold
margin_pct = (price - cost) / price * 100

print(profit.round(2))
print(margin_pct.round(1))
print(price)                 # unchanged

Output

[1346.52 1670.   1465.1  1507.88]
[37.4 50.3 52.  46. ]
[299.95  82.95  24.5  149.  ]

⚠️ * Is Not Matrix Multiplication

* between two arrays multiplies matching positions. It is not the row-times-column multiplication you may remember from a math class. That operation exists too, it is written @, and it has its own lesson (Lesson 1.5).

🧮 Universal Functions

Operators cover arithmetic. For everything else (square roots, logarithms, rounding, absolute values) NumPy provides universal functions, or ufuncs: functions that take an array and apply themselves to every element. In fact a + b is just a shorthand for the ufunc np.add(a, b).

To keep the output small, here is Boise's first week of 2024 again.

week = np.array([5962.00, 6583.13, 3866.59, 7667.88, 9570.46, 12388.57, 9361.59])

print(np.sqrt(week).round(1))
print(np.log10(week).round(2))
print(np.round(week, -2))                     # nearest hundred
print(np.abs(week - week.mean()).round(0))    # distance from the weekly average

Output

[ 77.2  81.1  62.2  87.6  97.8 111.3  96.8]
[3.78 3.82 3.59 3.88 3.98 4.09 3.97]
[ 6000.  6600.  3900.  7700.  9600. 12400.  9400.]
[1952. 1331. 4048.  246. 1656. 4474. 1447.]

The last line is worth reading slowly, because it is three vectorized steps in a row. week.mean() is one number. week - week.mean() subtracts that number from every day. np.abs(...) removes the minus signs. No loop anywhere.

Functions of Two Arrays

Some ufuncs take two inputs. np.maximum compares two arrays position by position and keeps the larger value from each pair. Suppose Boise has a daily target of $8,000 and you want to know how far short each day fell, counting days that beat the target as zero.

target = 8000
shortfall = np.maximum(target - week, 0)
print(shortfall)

print(np.clip(week, 5000, 10000))    # nothing below 5,000 or above 10,000

Output

[2038.   1416.87 4133.41  332.12    0.      0.      0.  ]
[ 5962.    6583.13  5000.    7667.88  9570.46 10000.    9361.59]

💡 Three Things Named "max"

week.max() (or np.max(week)) collapses one array to its single largest value. np.maximum(x, y) compares two arrays and returns an array. Python's built-in max(week) also works on a 1-D array, but it loops in Python, so it is slow on large arrays. When in doubt, use the method: week.max().

🎭 Comparisons and Boolean Masks

Comparison operators are vectorized too. Comparing an array with a number asks the question of every element and gives back an array of answers.

busy = week > 9000
print(busy)
print(busy.dtype)

Output

[False False False False  True  True  True]
bool

An array of True and False like this is called a boolean mask. Think of it as a sheet of cardboard with holes punched where the answer is True. It is useful in three ways.

1. Count and Measure

In arithmetic, True counts as 1 and False as 0. So the sum of a mask is how many are true, and its mean is the fraction that are true.

print(busy.sum())      # how many days beat 9,000?
print(busy.mean())     # what fraction of days?

big = revenue > 15000
print(big.sum(), "store-days above $15,000")
print(f"{big.mean():.1%} of all store-days")

Output

3
0.42857142857142855
101 store-days above $15,000
3.5% of all store-days

2. Filter

Put a mask inside the square brackets and you get only the elements where the mask is True. Lay the cardboard over the data and read what shows through the holes.

print(week[busy])
print(week[week < 6000])           # the mask can be written in place

print(revenue[big][:5])            # the first five of the big days
print(revenue[big].mean().round(2))

Output

[ 9570.46 12388.57  9361.59]
[5962.   3866.59]
[16262.39 15993.3  19117.36 17442.78 22093.08]
17683.61

The mask and the array it filters must have the same shape, but they do not have to be the same array. That is where parallel arrays shine: build the mask from one column and use it on another.

stores = load(1, dtype=str)
promo = load(7)

print(stores[:5])

is_boise = stores == "Boise"
print(is_boise.sum(), "Boise rows")

print(visitors[is_boise].mean().round(1))         # mean visitors on Boise days

Combining Masks: &, |, ~

Real questions usually have two parts: "Boise and a sale day". Masks combine with three operators.

Whether the sale caused all of that difference is a harder question (sale weekends are also holiday weekends), and Module 4 gives you the tools for it. Counting and comparing is where every such investigation starts.

⚠️ Two Rules for Combining Masks

Use & and |, not and and or. Python's words want a single true-or-false value, and an array is many.

Put parentheses around each comparison: (revenue > 10000) & (promo == 1). Python evaluates & before >, so without parentheses it tries to compute 10000 & promo first. Both errors are shown in Common Mistakes.

To test membership in a set of values, np.isin is tidier than a chain of |:

west = np.isin(stores, ["Boise", "Bend"])
print(west.sum())

Output

1451

3. Assign

A mask on the left side of = changes only the selected elements. Here every day above $10,000 is capped at $10,000. Working on a copy keeps the original safe.

capped = week.copy()
capped[capped > 10000] = 10000
print(capped)
print(week)

Output

[ 5962.    6583.13  3866.59  7667.88  9570.46 10000.    9361.59]
[ 5962.    6583.13  3866.59  7667.88  9570.46 12388.57  9361.59]

💡 A Mask Gives a Copy, a Slice Gives a View

In Lesson 1.1 a slice such as week[1:4] was a view: a window onto the same memory. Selecting with a mask is different. The chosen elements can be scattered anywhere, so NumPy has to gather them into a new array. Changing picked = week[busy] afterward does not touch week. Assigning through the mask in one step, as in capped[capped > 10000] = 10000, does change the array, because there the mask is on the left of the =.

picked = week[busy]
picked[0] = 0
print(week)                              # still intact
print(np.shares_memory(week, picked))

Output

[ 5962.    6583.13  3866.59  7667.88  9570.46 12388.57  9361.59]
False

🔀 Choosing Values with np.where

A mask answers "which ones?". Often you want the next step: "use this value where the condition holds, and that value where it does not". That is an if/else for every element, and np.where(condition, value_if_true, value_if_false) is its vectorized form.

print(np.where(week > 9000, "strong", "normal"))
print(np.where(week > 9000, week * 0.02, 0).round(2))    # a 2% bonus pool on strong days

Output

['normal' 'normal' 'normal' 'normal' 'strong' 'strong' 'strong']
[  0.     0.     0.     0.   191.41 247.77 187.23]

The two "value" arguments can be single values, arrays, or one of each. A common use is filling in missing values. Here the six missing revenues are replaced by the average of the rest. (Whether that is a wise way to fill a gap is a question for the data-cleaning lesson. The mechanics are what matter now.)

filled = np.where(np.isnan(revenue), np.nanmean(revenue), revenue)

print(np.isnan(revenue).sum(), "missing before")
print(np.isnan(filled).sum(), "missing after")

Output

6 missing before
0 missing after

More Than Two Outcomes: np.select

For three or more outcomes, np.select takes a list of conditions and a matching list of values. Conditions are checked in order and the first one that is true wins, exactly like an if/elif chain.

conditions = [np.isnan(revenue), revenue >= 12000, revenue >= 6000]
labels = ["missing", "high", "medium"]
tier = np.select(conditions, labels, default="low")

print(tier[:8])

names, counts = np.unique(tier, return_counts=True)
print(names)
print(counts)

Output

['low' 'low' 'low' 'low' 'low' 'low' 'medium' 'low']
['high' 'low' 'medium' 'missing']
[ 260 1120 1517    6]

np.unique returns the distinct values in sorted order, and with return_counts=True it also tells you how many times each appears. It is the quickest way to tally a column of categories in NumPy.

📐 Summaries and the axis Argument

Operations so far kept the array's shape: 2,903 values in, 2,903 values out. Aggregations go the other way and boil many values down to one.

argmax deserves a second look. It does not return the largest value, it returns where the largest value is: position 5, which is Saturday. That position can then be used to look something up in a parallel array, as you will do in the project.

Two Dimensions: Which Way to Collapse?

With a table, "the sum" is ambiguous. The sum of everything? Of each column? Of each row? The axis argument decides. Here are the units sold on the first three days of 2024 (rows) at Asheville, Bend, Boise and Flagstaff (columns), the same table as in Lesson 1.1.

units3 = np.array([[110, 105, 148,  69],
                   [ 88,  84, 152,  82],
                   [103, 133,  90,  92]])

print(units3.sum())           # everything
print(units3.sum(axis=0))     # collapse the rows: one total per store
print(units3.sum(axis=1))     # collapse the columns: one total per day

Output

1256
[301 322 390 243]
[432 406 418]

💡 The Axis You Name Is the Axis That Disappears

The shape of units3 is (3, 4). Axis 0 is the first number (3 rows), axis 1 is the second (4 columns). sum(axis=0) squashes the 3 away and leaves shape (4,). sum(axis=1) squashes the 4 away and leaves shape (3,). If you cannot remember which is which, print the shape of the result: it tells you what survived.

Every aggregation accepts axis. Using the first week of revenue as a 7×4 table (days by stores), as in the Lesson 1.1 project:

week1 = revenue[:28].reshape(7, 4)       # 7 days x 4 stores

print(week1.mean(axis=0).round(2))       # average day at each store
print(week1.max(axis=1))                 # best store's revenue on each day
print(week1.argmax(axis=0))              # which day (0 = Monday) was best at each store
print(week1.argmax(axis=1))              # which store (0 = Asheville) won each day

Output

[5099.55 5446.93 7914.32 4681.29]
[ 5962.    6583.13  6275.05  7667.88  9570.46 12388.57  9361.59]
[4 5 5 5]
[2 2 1 2 2 2 2]

Read the third line as: Asheville's best day was day 4 (Friday), while Bend, Boise and Flagstaff all peaked on day 5 (Saturday). The fourth line says Boise (column 2) took the top spot on six of the seven days, and Bend (column 1) won Wednesday.

🔢 Sorting and Picking by Position

np.sort returns a sorted copy. Its more useful sibling is np.argsort, which returns the positions that would sort the array. Like argmax, positions are valuable because they work on parallel arrays.

days = np.array(["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"])

print(np.sort(week))
order = np.argsort(week)         # positions, from smallest value to largest
print(order)
print(days[order])               # the days, from worst to best
print(days[order][::-1][:3])     # the top three days

Output

[ 3866.59  5962.    6583.13  7667.88  9361.59  9570.46 12388.57]
[2 0 1 3 6 4 5]
['Wed' 'Mon' 'Tue' 'Thu' 'Sun' 'Fri' 'Sat']
['Sat' 'Fri' 'Sun']

days[order] is a new kind of indexing: an array of positions inside the brackets. NumPy returns the elements at those positions, in that order. (You will see it called "fancy indexing". Like mask indexing, it returns a copy.)

print(week[[0, 5, 6]])           # Monday, Saturday, Sunday
print(days[week.argmax()], week.max())

Output

[ 5962.   12388.57  9361.59]
Sat 12388.57

🔁 From Loop to Array Expression

Here is a realistic piece of loop code, the kind you might have written after the Python courses. A store earns a bonus of 2% of whatever it sells above $10,000 in a day. Days with no revenue recorded earn nothing.

def bonus_loop(values):
    out = []
    for r in values:
        if r != r:               # nan is the only value not equal to itself
            out.append(0.0)
        elif r > 10000:
            out.append((r - 10000) * 0.02)
        else:
            out.append(0.0)
    return out

def bonus_vectorized(values):
    over = np.maximum(values - 10000, 0)        # amount above 10,000, never negative
    return np.where(np.isnan(values), 0, over * 0.02)

loop_result = bonus_loop(revenue.tolist())
fast_result = bonus_vectorized(revenue)

print(np.allclose(loop_result, fast_result))
print(round(fast_result.sum(), 2))

Output

True
29708.28

np.allclose checks that two arrays are equal to within a tiny rounding tolerance. It is the right tool for comparing floating-point results, and "same answer as the slow version" is the best test a vectorized rewrite can have. Now time them.

import timeit

as_list = revenue.tolist()
t_loop = min(timeit.repeat(lambda: bonus_loop(as_list), number=20, repeat=5)) / 20
t_fast = min(timeit.repeat(lambda: bonus_vectorized(revenue), number=20, repeat=5)) / 20

print(f"loop      : {t_loop * 1e6:7.1f} microseconds")
print(f"vectorized: {t_fast * 1e6:7.1f} microseconds")
print(f"speedup   : {t_loop / t_fast:.0f}x")

Output (your numbers will differ)

loop      :    82.1 microseconds

speedup   : 15x

✅ Loops Are Not Forbidden

A loop over four store names, twelve months or five files is fine. What you want to avoid is a Python loop over the rows, because that is where the thousands or millions are. If a calculation truly depends on the previous result (a running balance with rules, a simulation step), a loop may be the honest answer. Write it, make it correct, and only then ask whether it is slow enough to matter.

⚠️ Common Mistakes

Most of these produce a clear error message, and the message names the problem once you know how to read it. The last two produce no message at all, which is why they are worth meeting here first.

1. Using and Instead of &

both = (revenue > 10000) and (promo == 1)

Error

ValueError: The truth value of an array with more than one element is ambiguous. Use a.any() or a.all()

What it means: and needs one true-or-false value on each side, and each side is an array of 2,903 answers. It is the same message you saw in Lesson 1.1 for if week > 6000. Fix: (revenue > 10000) & (promo == 1).

2. Forgetting the Parentheses

both = revenue > 10000 & promo == 1

Error

TypeError: ufunc 'bitwise_and' not supported for the input types, and the inputs could not be safely coerced to any supported types according to the casting rule ''safe''

What it means: & binds more tightly than >, so Python tried 10000 & promo first, and "bitwise and" between an integer and an array of floats is not defined. The message is cryptic, but whenever you see bitwise_and in an error, look for missing parentheses. Fix: wrap each comparison: (revenue > 10000) & (promo == 1).

3. Calling a math Function on an Array

import math
roots = math.sqrt(week)

Error

TypeError: only 0-dimensional arrays can be converted to Python scalars

What it means: the functions in Python's math module work on one number at a time. Fix: use the NumPy function of the same name: np.sqrt(week).

4. Arrays That Do Not Line Up

seven = np.arange(7)
four = np.arange(4)
total = seven + four

Error

ValueError: operands could not be broadcast together with shapes (7,) (4,)

What it means: element-by-element arithmetic needs a partner for every element, and 7 values cannot pair up with 4. Fix: print both shapes and find out why they differ. Often one array was filtered and the other was not. (Some different shapes can be combined, by rules called broadcasting. That is the whole of the next lesson.)

5. Forgetting That nan Fails Every Comparison

print(revenue.size)
print((revenue > 0).sum() + (revenue <= 0).sum())
print((revenue == np.nan).sum())

Output (six rows have gone missing, and nothing equals nan)

2903
2897
0

What happened: a missing value is neither greater than zero nor less than or equal to zero. Every comparison with nan is False, including nan == nan. So the six store-days with no revenue silently drop out of both groups, and "the rest" is not the same as "not the first group". Fix: test for missing values explicitly with np.isnan(revenue), and decide on purpose which group they belong to.

6. Summarizing Along the Wrong Axis

print(week1.mean(axis=1).shape)    # 7 values: one per DAY
print(week1.mean(axis=0).shape)    # 4 values: one per STORE

Output

(7,)
(4,)

What happens: no error, just numbers that answer a different question. "Average per store" needs the days collapsed, which is axis=0. Fix: check the shape of the result against what you expect. Four stores should give four numbers.

    for t in totals:

💡 Hint

✅ Solution 
import timeit

def shipping_loop(totals):
    out = []
    for t in totals:
        if t >= 75:
            out.append(0.0)
        elif t >= 25:
            out.append(6.95)
        else:
            out.append(14.95)
    return out

def shipping_vectorized(totals):
    return np.select([totals >= 75, totals >= 25], [0.0, 6.95], default=14.95)

totals = np.array([12.50, 25.00, 74.99, 75.00, 310.20, 48.00])
print(shipping_vectorized(totals))
print(np.allclose(shipping_loop(totals), shipping_vectorized(totals)))

many = np.linspace(5, 400, 1_000_000)
many_list = many.tolist()
print(np.allclose(shipping_loop(many_list), shipping_vectorized(many)))

Output

[14.95  6.95  6.95  0.    0.    6.95]
True
True
t_loop = min(timeit.repeat(lambda: shipping_loop(many_list), number=1, repeat=3))
t_fast = min(timeit.repeat(lambda: shipping_vectorized(many), number=1, repeat=3))
print(f"loop {t_loop * 1000:.1f} ms, vectorized {t_fast * 1000:.1f} ms, {t_loop / t_fast:.0f}x")

❓ Common Questions at This Stage

Is it ever right to loop over an array?

Yes. Loop over a small number of groups (stores, months, files) whenever it makes the code clearer. Loop when each step depends on the result of the previous one and no NumPy function expresses it. And loop when you are still working out what the calculation should be: a correct loop is a fine first draft, and it gives you something to check the vectorized version against.

What about np.vectorize? The name sounds like exactly what I need.

The name is misleading. np.vectorize(my_function) lets you call an ordinary Python function with an array, but underneath it still runs your function once per element in Python. It is a convenience, and it is no faster than the loop. Real speed comes from expressing the calculation with operators, ufuncs, np.where and aggregations.

Why do I sometimes see a RuntimeWarning but still get a result?

For floating-point arrays, NumPy does not stop on a division by zero or the mean of nothing. It stores inf or nan in that position, prints a warning, and carries on with the rest of the array, because one bad row should not throw away a million good ones. Treat the warning as a prompt to look: use np.isfinite(result).all() to check whether anything odd got in.

Does a long expression like (a - b) / a * 100 waste memory?

Each step creates a temporary array that is thrown away afterward. For arrays of thousands or a few million values this does not matter. For very large arrays you can update in place with a *= 100 or np.multiply(a, 100, out=a), which reuse the existing memory. Reach for that only when memory is a measured problem, since in-place code is harder to reason about.

📝 Lesson Summary

🎓 Key Takeaways

  • Vectorized means one operation on a whole array, with the loop inside NumPy's compiled code
  • Operators and ufuncs (np.sqrt, np.log10, np.abs, np.maximum, np.clip) work element by element on arrays of the same shape
  • A comparison produces a boolean mask; its sum counts, its mean is a fraction, and in brackets it filters
  • Combine masks with &, |, ~ and parentheses around every comparison, never and / or
  • Mask and position indexing return copies; assign through the mask to change the original
  • np.where is a vectorized if/else; np.select handles three or more outcomes, first match wins
  • Aggregations collapse an array; the axis you name is the axis that disappears
  • argmax and argsort return positions, which you can use on parallel arrays
  • nan fails every comparison, so handle missing values on purpose with np.isnan
