🌉 Loading Is Translation

Every analysis starts with the same step: getting someone else's data into your DataFrame. It sounds like a formality, and it is where a surprising share of wrong answers begin. A date that loads as text cannot be grouped by month. An id that loads as a decimal number will not match the same id in another table. A header that sits on row 4 turns the whole sheet into nonsense.

💡 Mental Model: The Interpreter at the Border

A file is a message written in another language. A CSV says "2024-01-01", and it is only characters: nothing in the file says "this is a date". pd.read_csv() is an interpreter who makes a reasonable guess about what each column means. Good interpreters can be briefed: "column three is a date, the missing-value marker is n/a, ignore the two lines of notes at the top". The options in this lesson are that briefing. And like any careful traveler, you check the translation before you rely on it.

graph TD A["A file: CSV, Excel, JSON, database"] --> B["A reader: pd.read_..."] B --> C["Options: columns, dtypes, dates"] C --> D["A DataFrame"] D --> E{"Check: shape, dtypes, head"} E -->|"something is off"| C E -->|"looks right"| F["Analyze"] F --> G["A writer: df.to_..."]

pandas has a family of matching readers and writers. You will use all of these today.

🏷️ Dtypes and Dates on Load

pandas infers each column's dtype by reading its values. The inference is sensible, and there are three situations where you should overrule it.

customers = pd.read_csv("data/customers.csv")
print(customers[["customer_id", "phone", "birth_year", "loyalty_tier"]].dtypes)
print(customers["birth_year"].head(3).tolist())

Output

customer_id       int64
phone               str
birth_year      float64
loyalty_tier        str
dtype: object
[nan, 1989.0, 1995.0]

birth_year is a year, a whole number, but it loaded as float64 and prints as 1989.0. The reason is the nan at the top: 442 customers gave no birth year, and NumPy's int64 has no way to say "missing", so pandas fell back to floats. And loyalty_tier holds only three distinct values repeated 4,850 times, stored as full text each time.

customers = pd.read_csv(
    "data/customers.csv",
    dtype={"birth_year": "Int64", "loyalty_tier": "category", "acquisition_channel": "category"},
    parse_dates=["signup_date"],
)
print(customers[["birth_year", "loyalty_tier", "signup_date"]].dtypes)
print(customers["birth_year"].head(3).tolist())
print(customers["birth_year"].isna().sum())

Output

birth_year               Int64
loyalty_tier          category
signup_date     datetime64[us]
dtype: object
[<NA>, 1989, 1995]
442
  • "Int64" with a capital I is pandas's nullable integer. It stores whole numbers and marks missing ones as <NA>. Use it for ids, years and counts that have gaps. The capital letter matters: lowercase "int64" is the NumPy type and cannot hold a missing value.
  • "category" stores each distinct value once and then a small integer code per row. For a column with few distinct values this saves a lot of memory, and you will see how much in Large Files.
  • parse_dates handles the date, as before.

⚠️ Ids That Look Like Numbers

Codes such as ZIP codes, phone numbers or account numbers with leading zeros (02134) are text that happens to be written with digits. Read as numbers, they lose their zeros and can never be recovered. Protect them on load with dtype={"zip": "str"}. A good test: would it make sense to add two of them together? If not, it is text.

If a file has already been loaded, the same conversions are available afterward: pd.to_datetime(df["col"]) for dates and df["col"].astype("Int64") for types. You will use both in a moment. Doing it in read_csv is tidier because the table is right from its first line.

🧩 Awkward Text Files

Pinecrest's own files are well behaved. Exports from other systems often are not. So that you can see several options at once, here is a small export typed straight into the notebook. io.StringIO wraps a string so that it can stand in for a file; read_csv accepts either.

import io

export = io.StringIO("""Pinecrest regional export
generated by the till system
store;week;revenue;returns
Boise;2024-W01;55.400,22;n/a
Bend;2024-W01;38.128,49;3
Flagstaff;2024-W01;32.769,02;--
Asheville;2024-W01;35.696,85;1
""")

regional = pd.read_csv(
    export,
    sep=";",                    # the separator is a semicolon, not a comma
    skiprows=2,                 # two lines of notes above the header
    decimal=",",                # 55.400,22 uses a decimal comma...
    thousands=".",              # ...and a dot for thousands
    na_values=["n/a", "--"],    # extra spellings of "missing"
)
print(regional)
print(regional.dtypes)

Output

       store      week   revenue  returns
0      Boise  2024-W01  55400.22      NaN
1       Bend  2024-W01  38128.49      3.0
2  Flagstaff  2024-W01  32769.02      NaN
3  Asheville  2024-W01  35696.85      1.0
store          str
week           str
revenue    float64
returns    float64
dtype: object

Five options, each fixing one thing you can see in the text: semicolons, two lines of notes, numbers written the continental European way (55.400,22), and two different ways of writing "nothing here". The result has a numeric revenue and proper NaNs. Without na_values, the returns column would have loaded as text because of n/a and --. pandas already recognizes common markers such as an empty cell, NA, N/A, NaN and null; na_values adds your file's local dialect.

Dates in Another Format

Is 03/04/2025 the 4th of March or the 3rd of April? It depends on who wrote the file. Do not let pandas guess. Tell it with date_format, using the same codes as Python's strftime (%m month, %d day, %Y four-digit year).

us_dates = io.StringIO("order_id,order_date\n1,03/04/2025\n2,12/25/2025\n")
parsed = pd.read_csv(us_dates, parse_dates=["order_date"], date_format="%m/%d/%Y")
print(parsed)
print(parsed["order_date"].dt.month.tolist())

Output

   order_id order_date
0         1 2025-03-04
1         2 2025-12-25
[3, 12]

💡 Encodings in One Paragraph

Text files store characters as bytes, and the mapping is called an encoding. pandas assumes UTF-8, today's standard. If a load fails with UnicodeDecodeError, or names come out as JosÃ© instead of José, the file was written in another encoding: try encoding="latin-1" or encoding="cp1252", the usual culprits for files exported by older Windows software. Files saved from Excel as "CSV UTF-8" start with an invisible marker, and encoding="utf-8-sig" removes it.

✅ Look Before You Load

If you have a spreadsheet program, open the workbook and look at it for ten seconds: which sheet, which row has the header, where does the data stop? If you do not, pd.read_excel(path, header=None, nrows=8) shows you the top of the sheet exactly as it is. Either way, you are deciding the options from evidence.

🌳 Nested JSON

CSV and Excel are tables: rows and columns. JSON is a tree: values inside objects inside lists inside objects. It is the language of web APIs (Module 6) and of document databases (Lesson 5.5), and it maps directly onto Python dictionaries and lists. The work is turning the tree into a table.

data/web_sessions.json holds a month of visits to Pinecrest's website. Load it first with the standard library's json module, so you can see its shape before pandas is involved.

import json

with open("data/web_sessions.json", encoding="utf-8") as f:
    data = json.load(f)

print(type(data), list(data))
print(data["site"], data["period"])
print(len(data["sessions"]))

Output

pinecrest-outfitters.example {'start': '2025-11-01', 'end': '2025-11-30'}

Lists Inside Records: record_path

Each session has a list of pages. To get a table with one row per page view, tell json_normalize which key holds the list (record_path) and which fields of the parent to copy onto every row (meta).

pages = pd.json_normalize(data["sessions"], record_path="pages", meta=["session_id", "converted"])
print(pages.shape)
print(pages.head(4))

Output

(9348, 5)
                 path  seconds                   at session_id converted
0                   /       45  2025-11-01T06:31:45     S00001     False
1  /category/sleeping       13  2025-11-01T06:32:30     S00001     False
2                   /       18  2025-11-01T06:48:03     S00002     False
3   /product/TNT-1003       38  2025-11-01T06:48:21     S00002     False

2,400 sessions became 9,348 page views, and each row carries its session_id so the two tables can be connected again. That is the general pattern for nested data: one table per level of nesting, linked by a key. Joining such tables back together is the subject of Lesson 2.5.

💡 When Is pd.read_json() Enough?

pd.read_json(path) reads JSON that is already table-shaped: a list of flat records. It cannot handle a file like this one, with a wrapper object around nested records (you will see its error in Common Mistakes). For anything nested, json.load and json_normalize are the reliable pair.

🗄️ A Preview: SQL Databases

Much business data lives in databases. pandas reads the result of a SQL query straight into a DataFrame with pd.read_sql(). Here it is with data/pinecrest.db, a SQLite database, which Python can open with no extra software.

🐘 Large Files

A DataFrame lives in memory. A CSV of 5 GB will not load on a laptop with 8 GB of RAM, and long before that point everything gets slow. The course files are small, so you will practice the techniques on order_items.csv (45,490 rows) and trust that they scale. They do: these are exactly the moves used on files a thousand times larger.

Step One: Measure

items = pd.read_csv("data/order_items.csv")
print(items.shape)
print(items.memory_usage(deep=True))
print(round(items.memory_usage(deep=True).sum() / 1024**2, 2), "MB")

Output

(45490, 5)

order_id         363920
sku              727840

memory_usage(deep=True) reports bytes per column (deep=True makes it count the text properly). Each number column costs 8 bytes a row. The sku text column costs twice that, though it holds only 240 distinct values.

Step Two: Load Less, and Smaller

lean = pd.read_csv(
    "data/order_items.csv",
    usecols=["order_id", "sku", "quantity", "unit_price"],
    dtype={"order_id": "int32", "quantity": "int16", "sku": "category", "unit_price": "float32"},
)
print(lean.dtypes)
print(round(lean.memory_usage(deep=True).sum() / 1024**2, 2), "MB")

Output

sku           category
quantity         int16
unit_price     float32
dtype: object
0.53 MB

A quarter of the memory, with the same information. Dropping a column you do not need is free. category shrinks repetitive text dramatically. The smaller number types (int32, int16, float32) halve or quarter a column, with the caution from Lesson 1.1: check that your values fit. One new caution: float32 keeps only about 7 significant digits (float64 keeps 15 to 17), which is fine for a price and wrong for a large total.

Step Three: Read in Chunks

When even the slimmed-down table will not fit, do not load it all. chunksize turns read_csv into something you loop over: each turn of the loop hands you the next piece as an ordinary DataFrame. Keep a running result, and let each chunk go.

total_units = 0
total_revenue = 0.0
n_chunks = 0

for chunk in pd.read_csv("data/order_items.csv", chunksize=10_000):
    total_units += chunk["quantity"].sum()
    total_revenue += (chunk["quantity"] * chunk["unit_price"]).sum()
    n_chunks += 1

print(n_chunks, "chunks")
print(total_units, round(total_revenue, 2))
print(items["quantity"].sum(), round((items["quantity"] * items["unit_price"]).sum(), 2))

Output

5 chunks
65104 3963530.35
65104 3963530.35

Five chunks of up to 10,000 rows, and the totals match the whole-file answer exactly: 65,104 units and $3,963,530.35 of merchandise. At no point did more than 10,000 rows have to be in memory. Sums and counts combine across chunks easily. A mean needs a little care (keep a sum and a count, divide at the end), and a median cannot be done this way at all.

💡 The Order to Try Things In

(1) nrows to peek. (2) usecols to load only what you need. (3) dtype to make it smaller. (4) chunksize when it still does not fit. (5) Convert the file to Parquet once and read that from then on. Beyond that, the data belongs in a database, which is where Module 5 picks up.

💾 Writing Data Out

Analysis produces tables that somebody else needs: a cleaned file, a summary for a colleague, a snapshot for tomorrow. Every reader has a matching writer. Keep outputs in their own folder so they never overwrite the original data.

CSV

from pathlib import Path

out = Path("output")
out.mkdir(exist_ok=True)

completed = orders[orders["status"] == "completed"]
completed.to_csv(out / "completed_orders.csv", index=False)

print(back.shape)

Output

(18762, 11)
str

The row and column counts survived. The date did not: it is str again, because a CSV file is only text and carries no types. Whoever reads this file will need parse_dates again. That is the price of CSV's universality.

Notice index=False. Leave it out and pandas writes the index as an extra, unnamed first column, which comes back as a column called Unnamed: 0:

print(pd.read_csv(out / "oops.csv").columns.tolist()[:3])

Output

['Unnamed: 0', 'order_id', 'customer_id']

✅ A Habit Worth Having

Write index=False every time you call to_csv or to_excel, unless the index holds real information (dates, or a key you set on purpose).

Parquet: A File That Remembers Its Types

Parquet is a file format designed for data tables. It stores the data column by column, compressed, together with each column's dtype. It needs the pyarrow package, installed in Lesson 0.1.

completed.to_parquet(out / "completed_orders.parquet")
back_pq = pd.read_parquet(out / "completed_orders.parquet")

print(back_pq["order_date"].dtype)
print(back_pq.equals(completed))
for name in ["completed_orders.csv", "completed_orders.parquet"]:
    print(f"{name:<28}{(out / name).stat().st_size / 1024:>8,.0f} KB")

Output

datetime64[us]
True
completed_orders.csv           1,280 KB
completed_orders.parquet         354 KB

The date came back as a date. .equals() confirms the table read from Parquet is identical to the one written, values and dtypes alike. And the file is under a third of the size of the CSV. Because the data is stored by column, you can also read just the columns you want without scanning the rest:

only = pd.read_parquet(out / "completed_orders.parquet", columns=["order_id", "order_total"])
print(only.shape)

Output

(18762, 2)

The trade-off: a Parquet file is binary. You cannot open it in a text editor or a spreadsheet program. Use CSV to hand data to people and other tools; use Parquet to hand data to your future self and to other data tools.

⚠️ Common Mistakes

Loading errors are some of the friendliest in pandas: the message nearly always names the file, the column or the row. Here are the ones you are most likely to meet.

1. The File Is Not Where Python Is Looking

pd.read_csv("orders.csv")

Error

FileNotFoundError: [Errno 2] No such file or directory: 'orders.csv'

What it means: the path is relative to the folder Python is working in, and there is no orders.csv there. Fix: the file is in the data folder: "data/orders.csv". If that fails too, print Path.cwd(), as in Lesson 0.1.

2. Treating Text as a Date

plain = pd.read_csv("data/orders.csv")
plain["order_date"].dt.year

Error

AttributeError: Can only use .dt accessor with datetimelike values

What it means: the column is str, and .dt exists only for real datetimes. Fix: parse_dates when loading, or convert afterward.

plain["order_date"] = pd.to_datetime(plain["order_date"])
print(plain["order_date"].dt.year.value_counts())

Output

order_date
2025    10783
2024     9519
Name: count, dtype: int64

3. Asking for Plain Integers in a Column with Gaps

pd.read_csv("data/customers.csv", dtype={"birth_year": "int64"})

Error

ValueError: Integer column has NA values in column 8

What it means: "column 8" (counting from 0) is birth_year, it has missing values, and NumPy's int64 cannot represent them. Fix: the nullable "Int64", capital I.

4. A Column Name That Is Not in the File

pd.read_csv("data/orders.csv", usecols=["order_id", "total"])

Error

ValueError: Usecols do not match columns, columns expected but not found: ['total']

What it means: exactly what it says: the file has order_total, not total. Fix: peek at the header with nrows=0 or nrows=5 and copy the names.

5. read_json on a Nested File

pd.read_json("data/web_sessions.json")

Error

ValueError: Mixing dicts with non-Series may lead to ambiguous ordering.

What it means: the file's top level mixes single values (site) with a dictionary and a long list, and pandas cannot make one table out of that. Fix: json.load() the file, find the list of records, and pass it to pd.json_normalize().

6. The Header Is Not on the First Row

wrong = pd.read_excel("data/sales_2025.xlsx", sheet_name="Monthly Sales")
print(wrong.columns.tolist())
print(wrong.shape)

Output

['Pinecrest Outfitters - 2025 revenue by month (USD)', 'Unnamed: 1', 'Unnamed: 2', 'Unnamed: 3', 'Unnamed: 4', 'Unnamed: 5']
(15, 6)

What happened: no error at all. You got 15 rows instead of 12 and columns called Unnamed. This is the dangerous kind of mistake, because the code runs. Fix: skiprows=3, and the habit of printing .shape and .head() after every load.

❓ Common Questions at This Stage

Can read_csv load a file straight from a web address?

Yes: pass a URL instead of a path and pandas downloads it, and it reads compressed files (.csv.gz, .zip with one file inside) without unpacking. For anything beyond a public file at a plain URL, such as an API that needs a key or returns JSON in pages, you will want the requests library and the techniques of Module 6.

Should I use category for every text column?

No. It pays off when a column has few distinct values relative to its length: status, store, tier. For a column where nearly every value is different (names, email addresses, ids) it saves nothing and can use more memory. A category column also behaves a little differently when you group by it, which Lesson 2.4 explains. A reasonable rule: load as plain text first, and convert the columns that nunique() shows are repetitive.

My CSV loads, but one number column is str. How do I find out why?

One or more values are not numbers: a currency symbol, a thousands separator, a word such as free. pd.to_numeric(df["col"], errors="coerce") converts what it can and turns the rest into NaN, so df[pd.to_numeric(df["col"], errors="coerce").isna()] shows you the offending rows. Fixing them is cleaning, and that is exactly what Lesson 2.3 is about.

Is Parquet always better than CSV?

For your own working files, usually: smaller, faster, and types survive. CSV wins when a person needs to open the file, when another program expects it, or when you want to see changes line by line in version control. Many analysts keep the original CSV exactly as received and work from a Parquet copy.

🎓 Key Takeaways

  • Loading is translation: a text file carries no types, so you brief the reader and check the result (shape, dtypes, head()) every time
  • The read_csv options that earn their keep: parse_dates, usecols, dtype, index_col, nrows, na_values, sep, skiprows, encoding
  • Dates stay text unless you parse them; "Int64" keeps whole numbers whole when some are missing; "category" shrinks repetitive text
  • Unnamed columns mean the header is not where pandas looked: use skiprows or header
  • Nested JSON: json.load, find the list of records, pd.json_normalize; use record_path and meta for lists inside records; absent keys become NaN
  • For big files: peek, load fewer columns, use smaller dtypes, then chunksize
  • Write with index=False; CSV forgets types, Parquet remembers them
