🪪 Who Is Asking?

The practice shop's product pages are for everyone. Its orders are not: they are business records, and an API that serves them needs to know who is asking before it answers. Nearly every API worth using works this way, including the free ones, because the owner wants to know who its users are, how much each one uses, and whom to contact or cut off when something goes wrong.

Two words get mixed up constantly, and the difference will matter in ten minutes:

  • Authentication answers "who are you?" You present a credential, and the server recognizes you or does not.
  • Authorization answers "are you allowed to do this?" The server knows who you are and decides whether you may.

💡 Mental Model: The Library Card and the Wristband

An API key is a library card. It was issued to you once, it is good until it is cancelled, and you show it every time you borrow something. Anyone holding your card is you as far as the library can tell, so you do not leave it lying around.

A token is the wristband you get at a festival gate. You show your ticket and ID once (you log in), and for the rest of the day you just hold up your wrist. The wristband is quick to check and it expires on its own, so a lost one is a small problem for a short time.

MethodWhat you sendWhere you will meet it
NoneNothingOpen data: the practice API's /products
API keyA long fixed string in a headerMost data APIs: the practice API's /orders
Bearer tokenA temporary string in the Authorization header, obtained by logging inAPIs with user accounts: the practice API's /me
OAuth 2.0Also a bearer token; the difference is the ceremony for getting one ("Sign in with ...", approve access)Acting on behalf of a user on a large platform

This lesson covers the two you will use most as an analyst: a key and a token. OAuth 2.0 ends with the same header you will write today, and each platform's documentation walks you through its sign-in steps.

🤫 Secrets Stay Out of Code

Before you send a single credential, decide where it will live. The tempting place is a line in your notebook: API_KEY = "...". That is how keys leak. Notebooks get emailed, pasted into chat, shared on screen and pushed to GitHub, and a key in a file goes wherever the file goes. Programs scan public repositories for keys around the clock; a leaked cloud key can be running up someone's bill within minutes.

🛑 The Rule

A secret never appears in your code, your notebook, your version control or your screenshots. Code says where to find the secret. The secret itself lives somewhere that does not travel with the code.

The simplest such place is an environment variable: a named value that belongs to your terminal session, which every program started from that terminal can read. Set three of them for this lesson. If Jupyter is running, stop it first, set the variables in that same terminal, then start it again, because a program only sees the variables that existed when it started.

Windows (PowerShell)

$env:PINECREST_API_KEY = "pinecrest-demo-key"
$env:PINECREST_USER = "analyst"
$env:PINECREST_PASSWORD = "trailmix"

macOS and Linux

export PINECREST_API_KEY="pinecrest-demo-key"
export PINECREST_USER="analyst"
export PINECREST_PASSWORD="trailmix"

These last until you close that terminal. Now read them from Python. A small helper turns a missing variable into an error message that says exactly what to do.

import os
import time

import pandas as pd
import requests

pd.set_option("display.width", 150)
pd.set_option("display.max_columns", 20)

API = "http://127.0.0.1:8000"
USER_AGENT = "pinecrest-course-bot/1.0 (learning project; contact: you@example.com)"
HEADERS = {"User-Agent": USER_AGENT}


def require_env(name):
    """Read a required setting from the environment, or stop with a clear message."""
    value = os.environ.get(name)
    if not value:
        raise RuntimeError(f"Set the environment variable {name} before running this code.")
    return value


API_KEY = require_env("PINECREST_API_KEY")
USERNAME = require_env("PINECREST_USER")
PASSWORD = require_env("PINECREST_PASSWORD")

print("key loaded:", API_KEY[:4] + "...", f"({len(API_KEY)} characters)")

Output

key loaded: pine... (18 characters)

The notebook now contains the name PINECREST_API_KEY and nothing more. You could publish it. Notice the last line, too: when you need to confirm that a secret loaded, print a hint of it, never the whole value. Output cells are saved with the notebook.

require_env("PINECREST_ADMIN_KEY")

Error

RuntimeError: Set the environment variable PINECREST_ADMIN_KEY before running this code.

💡 Two Other Places for Secrets

  • Typed in when needed. In a notebook, API_KEY = getpass.getpass("API key: ") (from the standard library's getpass module) asks for the value in a box that hides what you type and does not save it in the notebook.
  • A .env file. Many projects keep NAME=value lines in a file named .env and load it at startup, often with the python-dotenv package. This is convenient, and safe only if .env is listed in .gitignore before your first commit, so that it is never pushed.

Whichever you use, the test is the same: could you hand your code to a stranger without handing over the secret?

🗝️ An API Key in a Header

Ask the orders endpoint for data the way you asked for products in Lesson 6.1, with no credential at all.

r = requests.get(f"{API}/orders", headers=HEADERS, timeout=10)

print(r.status_code, r.reason)
print(r.json())

Output

401 Unauthorized
{'error': {'code': 'missing_api_key', 'message': 'Send your key in the X-API-Key header.'}}

401 Unauthorized: the server does not know who you are. The message even says how to fix it. API documentation always states where the key goes; here it is a header named X-API-Key. Try a made-up key first.

r = requests.get(f"{API}/orders", headers={**HEADERS, "X-API-Key": "not-the-key"}, timeout=10)

print(r.status_code, r.reason)
print(r.json()["error"]["code"])

Output

403 Forbidden
invalid_api_key

403 Forbidden, a different answer. You presented a credential and it was rejected. The two codes point at different repairs:

  • 401 means "I cannot tell who you are": the credential is missing, malformed or expired. Check that you are sending it, and how.
  • 403 means "I understood, and the answer is no": the key is wrong or revoked, or it is valid but not allowed to do this. Sending the same request again will never help.

Now the real key, from the environment. {**HEADERS, ...} builds a new dictionary with everything in HEADERS plus one more entry.

KEY_HEADERS = {**HEADERS, "X-API-Key": API_KEY}

r = requests.get(f"{API}/orders", headers=KEY_HEADERS, params={"per_page": 2}, timeout=10)
data = r.json()

print(r.status_code)
print({k: v for k, v in data.items() if k != "items"})
print(data["items"][0])

Output

200
{'page': 1, 'per_page': 2, 'total': 20302, 'total_pages': 10151, 'next': '/orders?page=2&per_page=2'}
{'order_id': 100001, 'customer_id': 12673, 'order_date': '2024-01-01', 'channel': 'store', 'store': 'Flagstaff', 'status': 'completed', 'payment_method': 'cash', 'promo_code': None, 'discount_pct': 0, 'shipping_cost': 0.0, 'order_total': 434.9}

The door opens: 20,302 orders, two per page as requested. An order looks exactly like a row of data/orders.csv, with None where the CSV has an empty cell.

⚠️ Headers, Not URLs

Some APIs also accept the key as a query parameter, as in ?api_key=.... Prefer the header whenever both are offered. URLs are written to server logs, saved in browser history, shown in error messages and pasted into bug reports. Headers mostly are not. For the same reason, never send a credential over plain http:// to anything but your own computer: on the open internet, only https:// keeps it private.

🚦 Errors by Status Code

You have now seen 401 and 403, and in Lesson 6.1 you met 404 and the family of 5xx codes. With authentication in the picture, the status code becomes a decision: each one tells your program what kind of move comes next.

StatusIt meansYour program should
400 Bad RequestThe request itself is malformed (a bad date, a missing field)Stop. Fix the code. Never retry unchanged.
401 UnauthorizedNo valid credentialIf a token expired, get a new one and retry once. Otherwise stop.
403 ForbiddenRecognized, not allowedStop. A person needs to fix the key or the permissions.
404 Not FoundNo such thing at this URLStop, or record "does not exist" if that is a valid answer.
429 Too Many RequestsYou are going too fastWait, then retry (Lesson 6.5).
5xxThe server failedWait, then retry a few times (Lesson 6.5).

raise_for_status() would turn all of these into the same HTTPError and throw away the API's own explanation. A slightly smarter check keeps it. The practice API, like most, describes every error in a JSON body with a short machine-readable code and a human-readable message.

class ApiError(Exception):
    """An error response from the API, with its status, code and message."""

    def __init__(self, status, code, message):
        super().__init__(f"{status} {code}: {message}")
        self.status = status
        self.code = code
        self.message = message


def check(resp):
    """Return the response if it succeeded. Otherwise raise ApiError."""
    if resp.ok:
        return resp
    try:
        error = resp.json()["error"]
        code, message = error["code"], error["message"]
    except (requests.exceptions.JSONDecodeError, KeyError, TypeError):
        code, message = "http_error", resp.reason
    raise ApiError(resp.status_code, code, message)

A custom exception is an ordinary class that inherits from Exception. This one carries three attributes, so the code that catches it can branch on err.status or err.code instead of picking a string apart. The try inside check() covers servers that answer an error with something other than the expected JSON.

check(requests.get(f"{API}/orders", headers=KEY_HEADERS, params={"since": "12/01/2025"}, timeout=10))

Error

ApiError: 400 bad_request: 'since' must look like 2025-01-31, got '12/01/2025'.

That is a message you can act on in five seconds. From here on, every request in this lesson goes through check().

for path in ["/orders", "/products/TNT-9999", "/products/TNT-1001"]:
    try:
        resp = check(requests.get(f"{API}{path}", headers=HEADERS, timeout=10))
        print(path, "OK:", resp.json()["name"])
    except ApiError as err:
        print(path, "failed:", err.status, err.code)

Output

/orders failed: 401 missing_api_key
/products/TNT-9999 failed: 404 not_found
/products/TNT-1001 OK: Granite Fork Drift 1-Person Tent

🎟️ Logging In for a Token

The second kind of authentication starts with a login. You send a username and password once, in the body of a POST request, and the server answers with a token. This is your first POST: where GET reads, POST sends data. Passing json= tells requests to encode a dictionary as JSON in the request body and label it correctly.

resp = check(requests.post(f"{API}/login",
                           json={"username": USERNAME, "password": PASSWORD},
                           headers=HEADERS, timeout=10))
body = resp.json()

print(list(body))
print(body["token_type"], "token, valid for", body["expires_in"], "seconds")
print(body["access_token"][:6] + "...")

Output (your token will differ)

['access_token', 'token_type', 'expires_in']
Bearer token, valid for 5 seconds
XPCh49...

Three things came back: the token itself (a long random string), its type, and how many seconds it will last. To use it, send it in the Authorization header after the word Bearer and a space. The name is literal: whoever bears this token gets in, no other questions asked.

token = body["access_token"]
auth_headers = {**HEADERS, "Authorization": f"Bearer {token}"}

me = check(requests.get(f"{API}/me", headers=auth_headers, timeout=10)).json()
print(me["username"], "|", me["name"], "|", me["role"])

Output

analyst | Demo Analyst | analyst

The server looked up the token, found whose it was, and answered for that user. Your password crossed the network exactly once, and the thing you carry around afterward is worth far less to a thief: it stops working on its own.

A wrong password is rejected at the gate, with a 401:

try:
    check(requests.post(f"{API}/login", json={"username": USERNAME, "password": "guess"},
                        headers=HEADERS, timeout=10))
except ApiError as err:
    print(err)

Output

401 invalid_credentials: Wrong username or password.

⌛ When the Token Expires

You started the API with five-second tokens. Wait six, and use the same token again.

time.sleep(6)

try:
    check(requests.get(f"{API}/me", headers=auth_headers, timeout=10))
except ApiError as err:
    print(err.status, err.code)
    print(err.message)

Output

401 token_expired
The token has expired. Log in again with POST /login.

The request that worked a moment ago now fails with 401 and the code token_expired. Nothing is wrong with your account or your code. The wristband ran out. This is the normal life of a token, and every program that uses one must expect it in the middle of its work.

graph TD A["POST /login with credentials"] --> B["Receive token and lifetime"] B --> C["Send token with each request"] C --> D{"401 token_expired?"} D -->|no| E["Use the data"] D -->|yes| F["Log in again, retry once"] F --> C

There are two sensible ways to cope, and good clients use both:

  • Look ahead. You were told the lifetime at login. Remember when the token will expire, and get a new one shortly before that.
  • Recover. Clocks drift and tokens get revoked early, so also handle the 401: get a new token and repeat the request once. If it fails a second time, the problem is something else, and retrying forever would only hammer the server.
def login():
    """Log in and return (token, the time.monotonic() value at which it expires)."""
    resp = check(requests.post(f"{API}/login",
                               json={"username": USERNAME, "password": PASSWORD},
                               headers=HEADERS, timeout=10))
    body = resp.json()
    return body["access_token"], time.monotonic() + body["expires_in"]


token, expires_at = login()

for attempt in range(3):
    if time.monotonic() >= expires_at - 1:          # within a second of expiry: renew first
        token, expires_at = login()
        print("  (logged in again)")
    me = check(requests.get(f"{API}/me", timeout=10,
                            headers={**HEADERS, "Authorization": f"Bearer {token}"})).json()
    print("request", attempt + 1, "answered for", me["username"])
    time.sleep(3)

Output

request 1 answered for analyst
request 2 answered for analyst
  (logged in again)
request 3 answered for analyst

Three requests three seconds apart, with a token that lasts five: the loop renewed it when it was needed and never once saw a 401. (time.monotonic() is a clock that only moves forward, which makes it the right tool for measuring "how long since".)

💡 Refresh Tokens

Logging in again means keeping the password available to your program. Many real APIs avoid that with a second, longer-lived refresh token handed out at login: when the access token expires you trade the refresh token for a new one, and the password is never needed again. The practice API keeps things simple and has you log in again, but the shape of the code (notice the expiry, renew, retry once) is identical.

📚 Pagination to a DataFrame

An API will not hand you 20,302 orders in one response. Like the shop's catalog, it serves a page at a time, and like the catalog it tells you where the next page is. Look at the paging fields again:

params = {"status": "returned", "since": "2025-12-01", "per_page": 25}
data = check(requests.get(f"{API}/orders", headers=KEY_HEADERS, params=params, timeout=10)).json()

print({k: v for k, v in data.items() if k != "items"})

Output

{'page': 1, 'per_page': 25, 'total': 66, 'total_pages': 3, 'next': '/orders?page=2&per_page=25&since=2025-12-01&status=returned'}

Sixty-six returned orders since December 1, three pages of up to 25, and next holds the address of page 2 with all your filters already in it. On the last page next is None. That is the same "follow the next link until there is none" loop you wrote in Lesson 6.2, with JSON in place of HTML.

def get_all(path, params=None):
    """Collect every item from a paginated endpoint by following 'next'."""
    items = []
    url = f"{API}{path}"
    while url:
        data = check(requests.get(url, headers=KEY_HEADERS, params=params, timeout=10)).json()
        items.extend(data["items"])
        url = f"{API}{data['next']}" if data["next"] else None
        params = None              # 'next' already carries the filters
    return items


returned = pd.DataFrame(get_all("/orders", params))
returned["order_date"] = pd.to_datetime(returned["order_date"])

print(returned.shape)
print(returned[["order_id", "order_date", "channel", "store", "order_total"]].head(4))

Output

(66, 11)

One detail in that loop is easy to get wrong. The filters go in params for the first request only. The next address already includes them, so sending params again would attach every filter twice. Setting params = None after the first request avoids that.

⚠️ Ask for What You Need

This API allows 30 requests every 10 seconds for each client. All 20,302 orders at 100 per page would be 204 requests, and you would be told to slow down long before the end. Filter on the server (status, since) and use the largest page size the API allows. Handling the "slow down" answer properly is the whole of Lesson 6.5.

🧰 A Small Client Class

Look at what you are now carrying from cell to cell: a base URL, two sets of headers, a token, its expiry time, and four functions that all need them. That is the signal to make a class. A client is an object that holds the connection details and credentials for one API and offers a method for each thing you want from it. The rest of your analysis then reads like plain English.

class PinecrestClient:
    """A small client for the Pinecrest practice API."""

    def __init__(self, base_url, api_key, username, password, user_agent):
        self.base_url = base_url
        self.username = username
        self.password = password
        self.session = requests.Session()
        self.session.headers.update({"User-Agent": user_agent, "X-API-Key": api_key})
        self.token = None
        self.token_expires = 0.0
        self.logins = 0

    def login(self):
        """Get a fresh bearer token and remember when it expires."""
        resp = self.session.post(f"{self.base_url}/login", timeout=10,
                                 json={"username": self.username, "password": self.password})
        body = check(resp).json()
        self.token = body["access_token"]
        self.token_expires = time.monotonic() + body["expires_in"] - 1
        self.logins += 1

    def get(self, path, params=None, auth=False):
        """GET a path and return the parsed JSON. auth=True sends a bearer token."""
        headers = {}
        if auth:
            if self.token is None or time.monotonic() >= self.token_expires:
                self.login()
            headers["Authorization"] = f"Bearer {self.token}"
        resp = self.session.get(self.base_url + path, params=params, headers=headers, timeout=10)
        try:
            return check(resp).json()
        except ApiError as err:
            if not (auth and err.code == "token_expired"):
                raise
        self.login()                                   # expired early: renew and retry once
        headers["Authorization"] = f"Bearer {self.token}"
        resp = self.session.get(self.base_url + path, params=params, headers=headers, timeout=10)
        return check(resp).json()

    def get_all(self, path, params=None):
        """Collect every item from a paginated endpoint."""
        data = self.get(path, params)
        items = data["items"]
        while data["next"]:
            data = self.get(data["next"])
            items.extend(data["items"])
        return items

    def orders(self, **filters):
        """Orders as a DataFrame. Filters: status=..., since='YYYY-MM-DD'."""
        frame = pd.DataFrame(self.get_all("/orders", {"per_page": 100, **filters}))
        if not frame.empty:
            frame["order_date"] = pd.to_datetime(frame["order_date"])
        return frame

    def me(self):
        """The account the bearer token belongs to."""
        return self.get("/me", auth=True)

    def close(self):
        self.session.close()

Nothing in there is new. It is this lesson, arranged:

  • __init__ stores the credentials and creates a Session whose headers carry the User-Agent and the API key on every request.
  • login() is the function you wrote, storing the token on the object. It renews one second early.
  • get() is the one place that talks to the network: it adds a valid token when asked, sets the timeout, runs check(), and performs the "renew and retry once" recovery. A bare raise passes every other error on unchanged.
  • get_all(), orders() and me() are short because get() did the hard part.
client = PinecrestClient(API, API_KEY, USERNAME, PASSWORD, USER_AGENT)

print(client.me()["name"], "| logins so far:", client.logins)
time.sleep(6)
print(client.me()["name"], "| logins so far:", client.logins)

cancelled = client.orders(status="cancelled", since="2025-12-01")
print(cancelled.shape)
client.close()

Output

Demo Analyst | logins so far: 1
Demo Analyst | logins so far: 2
(30, 11)

The token expired between the two calls to me(), and the code that uses the client never noticed. That is what a good client buys you: the fiddly parts are written once, tested once, and then stay out of your way. Most API providers publish a client library like this for their own service. Now you know what is inside one.

⚠️ Common Mistakes

1. Leaving Out the Word "Bearer"

token, expires_at = login()
r = requests.get(f"{API}/me", headers={**HEADERS, "Authorization": token}, timeout=10)
print(r.status_code, r.json()["error"]["code"])

Output

401 missing_token

What it means: the header's value must be the scheme, a space, then the token: Bearer abc123. Without the scheme the server does not recognize a token at all, so it reports one as missing. Fix: f"Bearer {token}". Check the API's documentation for the exact header name and format; they vary.

2. Sending a Form When the API Wants JSON

r = requests.post(f"{API}/login", data={"username": USERNAME, "password": PASSWORD},
                  headers=HEADERS, timeout=10)
print(r.status_code, r.json()["error"]["message"])

Output

400 The request body must be JSON.

What it means: data= encodes the dictionary the way an HTML form does (username=...&password=...). This API expects a JSON body. Fix: json=. Some APIs do want form encoding for their login; the documentation says which.

3. Assuming the Login Worked

resp = requests.post(f"{API}/login", json={"username": USERNAME, "password": "guess"},
                     headers=HEADERS, timeout=10)
token = resp.json()["access_token"]

Error

KeyError: 'access_token'

What it means: the login failed with a 401, so the JSON that came back was an error object with no access_token in it. The KeyError is a symptom; the cause was one line earlier. Fix: check the response before using it, with check() or raise_for_status().

4. A Secret in the Code

There is no error message for API_KEY = "the-real-key" in a notebook. It works perfectly, right up to the day the file is shared. Fix: environment variables or a prompt, from the first line of the first draft. If a real key ever does end up in a file you shared or committed, treat it as stolen: revoke it and issue a new one at the provider. Deleting the line afterward does not un-leak it, because version history and other people's copies remember.

5. Retrying a 401 or 403 in a Loop

A loop that says "if it failed, log in and try again" with no limit will, on a wrong password or a revoked key, send login attempts as fast as your computer can. From the server's side that looks like an attack, and accounts get locked for it. Fix: renew and retry once, as PinecrestClient.get() does, then let the error surface.

Write try_login(username, password) that returns True if the credentials are accepted and False if they are rejected, printing the API's message in the second case. Any other kind of error (a 400, a 500) should not be hidden: let it raise. Test it with the right password and with a wrong one.

💡 Hint

Catch ApiError, test err.code == "invalid_credentials", and use a bare raise for everything else.

✅ Solution 
def try_login(username, password):
    try:
        check(requests.post(f"{API}/login", json={"username": username, "password": password},
                            headers=HEADERS, timeout=10))
        return True
    except ApiError as err:
        if err.code != "invalid_credentials":
            raise
        print("rejected:", err.message)
        return False

print(try_login(USERNAME, PASSWORD))
print(try_login(USERNAME, "campfire"))

rejected: Wrong username or password.
False

Catching only the error you understand, and letting the rest through, keeps real problems visible.

class CatalogClient(PinecrestClient):
    def products(self, category=None):
        """The product catalog as a DataFrame, optionally for one category."""
        params = {"per_page": 100}
        if category:
            params["category"] = category
        return pd.DataFrame(self.get_all("/products", params))

❓ Common Questions at This Stage

How do I get an API key for a real service?

Usually by creating an account on the provider's developer site and generating a key on a settings page. Read what the key is allowed to do (many providers let you create read-only keys: use the narrowest one that does the job), what the usage limits are, and what the terms say about storing and sharing the data. Copy the key straight into an environment variable or a password manager, never into a file in your project.

What about HTTP Basic authentication?

Basic authentication sends a username and password with every request, encoded (not encrypted) in the Authorization header. requests supports it with auth=("user", "password"). It is simple and still found on internal tools, and it is only acceptable over HTTPS. The same rule applies: both values come from the environment, not the code.

My environment variable is set, but Python says it is not. Why?

Almost always because the program was started before the variable was set, or from a different terminal. Variables set with export or $env: exist only in that terminal session and the programs launched from it afterward. Close Jupyter, set the variables, and start Jupyter from the same terminal. To make a variable permanent, add it to your shell's startup file or your operating system's environment settings.

What is a JWT? I see that term in API documentation.

A JSON Web Token is a common format for bearer tokens: three chunks of text separated by dots that contain a few facts (who, expiry time) and a signature the server can verify. You use one exactly like the token in this lesson, by sending it after Bearer. Treat it as opaque, and as secret as a password while it is valid.

📝 Lesson Summary

🎓 Key Takeaways

  • Authentication is who you are; authorization is what you may do. 401 signals the first failing, 403 the second
  • An API key is a long-lived credential sent in a header on every request
  • A bearer token comes from a login, goes in Authorization: Bearer ..., and expires
  • Secrets never go in code: read them from environment variables, and print at most a hint
  • Expect expiry: renew shortly before it, and on token_expired renew and retry once
  • Let the status code decide the next move: fix (400), re-authenticate once (401), stop (403), wait (429, 5xx)
  • Paginate by following next until it is None, and filter on the server
  • A small client class keeps credentials, session, error handling and pagination in one tested place
