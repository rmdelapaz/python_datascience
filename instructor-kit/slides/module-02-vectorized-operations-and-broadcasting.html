1.2

Vectorized Operations

One operation, a whole array, no loop.

1.2 · Why it matters

Speed, shorter code, and code that reads like the question

  • "Which days beat $15,000, and what was the average on sale weekends?"
  • By the end your first thought is an array expression, not a for statement
  • Every pandas filter and summary you will write is built on today's masks and axes
  • Loops are not forbidden: four stores, fine. 2,903 rows, no
1.2 · Mental model

The workbench and the assembly line

  • A loop is a craftsperson at a workbench: pick up one item, inspect it, work on it, put it down
  • A vectorized operation is an assembly line: set the machine once, the whole batch flows through
  • The machine is fast because every item is the same kind of thing: one dtype
  • Parallel arrays: position 0 of every column is the same store-day
1.2 · Code

Array with array: paired by position

conversion = transactions / visitors     # share of visitors who bought something

A mask from one column, used on another

is_boise = stores == "Boise"

print(is_boise.sum(), (is_boise & is_promo).sum())

WHY & and, | or, ~ not. An average sale day: $13,950 against $7,212.

1.2 · Code

An if/else for every element

print(np.where(week > 9000, "strong", "normal"))

conditions = [np.isnan(revenue), revenue >= 12000, revenue >= 6000]
tier = np.select(conditions, ["missing", "high", "medium"], default="low")
names, counts = np.unique(tier, return_counts=True)
print(names)
print(counts)
['normal' 'normal' 'normal' 'normal' 'strong' 'strong' 'strong']
['high' 'low' 'medium' 'missing']
[ 260 1120 1517    6]
WHY np.select: the first true condition wins, like if / elif. Catch the missing rows first.
1.2 · Code

The axis you name is the axis that disappears

units3 = np.array([[110, 105, 148,  69],
                   [ 88,  84, 152,  82],
                   [103, 133,  90,  92]])

print(units3.sum(axis=0))
print(units3.sum(axis=1))
[301 322 390 243]
[432 406 418]
  • Shape (3, 4): days by stores
  • axis=0 squashes the 3 days: one total per store
  • axis=1 squashes the 4 stores: one total per day
  • Not sure? Print the shape of the result

1.2 · Common mistakes

One loud, two quiet

  • and / or, or no parentheses → & and |, with parentheses around each comparison
  • The wrong axis → no error, just an answer to a different question. Check the shape
  • nan fails every comparison → missing rows are in neither group. Use np.isnan on purpose
FIX Before you run: how many answers do I expect? After: print .shape, or add up the pieces.

1.3

Broadcasting

Two short rules for combining different shapes.

1.3 · Why it matters

"Was this a good day for THIS store?"

  • Boise takes in almost twice what Asheville does: raw revenue only says Boise is bigger
  • Subtract each store's own average from its own column: a table combined with a row
  • week * 2 was already broadcasting: seven numbers and one
  • Standardizing, shares of a total, price grids: all one line each
1.3 · Mental model

The rubber stamp

  • A form with seven lines; a stamp that prints one line of four numbers
  • Press it on line 1, line 2, ... down the page. The stamp is reused, not made longer
  • Rule 1: line the shapes up from the right; a missing entry counts as 1
  • Rule 2: each pair is equal, or one of them is 1. The result takes the larger
1.3 · Code

A table and a row: it just works

store_mean = week1.mean(axis=0)
print(store_mean.round(2), store_mean.shape)

diff = week1 - store_mean          # (7, 4) with (4,)
print(diff.shape)
[5099.55 5446.93 7914.32 4681.29] (4,)
(7, 4)
WHY From the right: 4 meets 4, and 7 meets a missing axis. Each store's own average comes off its own column.
1.3 · Code

A table and a column: first the error

day_total = week1.sum(axis=1)
print(day_total.shape)
share = week1 / day_total
(7,)
ValueError: operands could not be broadcast together with shapes (7,4) (7,)
WATCH Read the shapes from the right: 4 meets 7. A flat array can only be a row.
1.3 · Code

keepdims=True keeps the axis

day_total = week1.sum(axis=1, keepdims=True)
print(day_total.shape)

share = week1 / day_total          # (7, 4) with (7, 1)
print(share.sum(axis=1))          # every row should add up to 1
(7, 1)
[1. 1. 1. 1. 1. 1. 1.]
WHY Per store: a table and a row. Per day: a table and a column, so keepdims=True.
1.3 · Code

Column meets row: a grid

prices = np.array([299.95, 217.95, 449.00, 129.50])
discounts = np.array([0.10, 0.15, 0.20])

sale = prices[:, np.newaxis] * (1 - discounts)
print(sale.shape)
print(sale.round(2))
(4, 3)
[[269.96 254.96 239.96]
 [196.16 185.26 174.36]
 [404.1  381.65 359.2 ]
 [116.55 110.08 103.6 ]]
  • (4, 1) with (3,) gives (4, 3)
  • Every product under every discount
  • No loop inside a loop
1.3 · Code

The accidental grid: no error, wrong answer

actual = np.array([100.0, 200.0, 300.0, 400.0])
predicted = np.array([[110.0], [190.0], [330.0], [380.0]])    # shape (4, 1)

errors = actual - predicted
print(errors.shape)
print(np.abs(errors).mean())      # the average size of an error
(4, 4)
126.25
FIX Four values in, four out. actual - predicted.ravel() gives (4,) and an average of 17.5.
1.3 · Predict, then run

Result shape, or error?

  1. (7, 4) with (4,)
  2. (7, 4) with (7,)
  3. (7, 4) with (7, 1)
  4. (3, 1) with (1, 5)
  5. (6,) with (6, 1)
WHY Write each pair right-aligned on paper first. Check with np.broadcast_shapes.
1.3 · Common mistakes

One announces itself. Two do not

  • A flat array where a column was needed → the "could not be broadcast together" error. Read it from the right
  • The accidental grid → a row meets a column; 16 numbers where 4 were wanted
  • The square table → 4 day-means happen to fit as a row; wrong answer, no complaint
FIX keepdims=True on every axis=1 aggregation you combine with its table. Then print .shape.
