1.1

Arrays vs Lists

One type, fixed size, and math on everything at once.

1.1 · Why it matters

Everything in this course sits on arrays

  • pandas stores each column in an array
  • Matplotlib plots arrays; SciPy and statsmodels compute on arrays
  • Two years of daily sales is 2,903 store-days. Real datasets run to millions of rows
  • Understand this one container and the rest stops looking like magic spells
1.1 · Mental model

The parking lot and the starting grid

  • A list is a parking lot: any vehicle, any space, and a clipboard saying what is where
  • An array is a starting grid: every car the same class, bumper to bumper, numbered positions
  • No clipboard needed, and the whole field can move as one
  • Three rules: one type · fixed size · whole-array operations
1.1 · Code

A first array and its four facts

week_list = [5962.00, 6583.13, 3866.59, 7667.88, 9570.46, 12388.57, 9361.59]
week = np.array(week_list)

print(week)
print(week.dtype, week.shape, week.ndim, week.size)
[ 5962.    6583.13  3866.59  7667.88  9570.46 12388.57  9361.59]
float64 (7,) 1 7
WHY No commas on screen: that is an array. When something surprises you, print .dtype and .shape.
1.1 · Code

The same operator, two meanings

print(len(week_list * 2))
print(week * 2)
14
[11924.   13166.26  7733.18 15335.76 19140.92 24777.14 18723.18]
WHY A list repeats. An array does arithmetic on every element, with no loop.
1.1 · Measure it

One million integers, stored both ways

n = 1_000_000
numbers_list = list(range(n))
numbers = np.arange(n)

list_bytes = sys.getsizeof(numbers_list) + sum(sys.getsizeof(x) for x in numbers_list)
print(f"list : {list_bytes:>12,} bytes")
print(f"array: {numbers.nbytes:>12,} bytes")
list :   36,000,056 bytes
array:    8,000,000 bytes
WHY The list keeps an address and a full Python object per number. The array keeps only values.

1.1 · Code

Rows, comma, columns

units = np.array([[110, 105, 148,  69],
                  [ 88,  84, 152,  82],
                  [103, 133,  90,  92]])

print(units[0, 2])
print(units[1])
print(units[:, 2])
148
[ 88  84 152  82]
[148 152  90]
  • Shape (3, 4): 3 days, 4 stores
  • units[0, 2]: row 0, column 2
  • units[1]: all of row 1
  • units[:, 2]: every row, column 2
1.1 · Code

A slice is a window, not a photocopy

a = np.array([10, 20, 30, 40, 50])
window = a[1:4]
window[0] = 999

print(a)
print(np.shares_memory(a, window))
[ 10 999  30  40  50]
True
FIX Will you change the piece and still need the original? a[1:4].copy()

1.1 · Common mistakes

Three that give no error message

  • Changing a slice and losing the original → .copy() first
  • Rows and columns swapped → say "rows, comma, columns" and print .shape
  • A silent type change: text sneaks in, or a decimal is chopped → print .dtype
  • And one that does: if week > 6000: → .any() or .all()
FIX Ask the array before you ask the instructor: .dtype, .shape, np.shares_memory.
