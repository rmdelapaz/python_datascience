Feature Engineering Basics

Derived values, date parts, bins, categories and per-customer summaries, with nothing leaking in from the future.

2.9 · Why it matters

"Which customers will order again?"

  • customers.csv says who people are
  • orders.csv says what they bought, one row per order
  • Neither has a column called "likely to come back"
  • A feature is a column you build so the pattern becomes visible
FROM 2.8 "Same weekday last week" beat every smoother. That was a feature.
2.9 · Mental model

Prep before cooking. First: what is one row?

Will this customer order again?One row is a customer: orders so far, days since last order, tenure
Will this order be returned?One row is an order: contains footwear, channel, value, weekday
How busy tomorrow?One row is a store-day: weekday, same weekday last week, promotion flag
RULE Every feature is one fact about the unit. An order's total is not a customer feature.

2.9 · Honest fills

What should each NaN become?

Counts, sumsFill with 0. "Zero orders" and "$0 spent" are true statements
Averages, shares, recencyLeave missing. There is no average of zero orders
And add a flaghas_ordered = n_orders > 0, so the fact stays visible
Ordinal categoryOrdered integer codes: Basic 0, Silver 1, Gold 2
Nominal categoryOne yes/no column each: pd.get_dummies
2.9 · Code

The cutoff rule

cutoff = pd.Timestamp("2025-01-01")
base = customers.loc[customers["signup_date"] < cutoff, ["customer_id"]].copy()
past = orders[orders["order_date"] < cutoff]
later = orders[(orders["order_date"] >= cutoff) & (orders["order_date"] < "2025-07-01")]
count = lambda rows: base["customer_id"].map(rows.groupby("customer_id").size()).fillna(0)
base["n_before"], base["n_all_time"] = count(past), count(orders)
base["again"] = base["customer_id"].isin(later["customer_id"]).astype(int)
print(base[["n_before", "n_all_time"]].corrwith(base["again"]).round(2).to_dict())
{'n_before': 0.38, 'n_all_time': 0.55}
ASK Could I have computed this value on the cutoff date, from what existed then?
2.9 · Leakage

Three kinds of leak, all silent

Rows from the futureCounting orders after the cutoff as "orders so far" → filter before aggregating
A column that knows the answerloyalty_tier is today's tier, earned through the end of 2025 → leave it out
Statistics of the whole datasetMeans or qcut edges computed over all rows → compute on the earlier data only
SIGN No error. Results that are too good. "Too good" should make you look twice.

2.9 · Common mistakes

Three ways this goes wrong

  • An inner merge deletes the 1,058 customers who never ordered. No error → how="left", count rows
  • fillna(0) on everything: an "average order of $0.00" that never happened
  • Bins that lose values: edges that do not cover the data → -np.inf, np.inf
  • qcut on a column of mostly zeros → ValueError: Bin edges must be unique

3.1

Line, Scatter and Bar Charts

How Matplotlib is put together, the four charts that answer most questions, and how to pick one.

3.1 · Mental model

Question first, chart second

How did it change over time?Line · ax.plot · dates in order
Do two numbers move together?Scatter · ax.scatter · one dot per row
Which group is bigger?Bar · ax.bar, ax.barh · one number per group, computed by you
What is typical? How spread out?Histogram · ax.hist · raw rows; it counts for you
TEST Can you finish the sentence "This chart shows whether..."?

3.1 · One rule

plt creates and shows. Everything else is on ax or fig

plt.title("...")ax.set_title("...")
plt.xlabel("...")ax.set_xlabel("...")
plt.ylim(a, b)ax.set_ylim(a, b)
plt.legend()ax.legend()

3.1 · Common mistakes

Three ways this goes wrong

  • Bars from raw rows: no error, the tallest of each pile → aggregate first
  • Two styles mixed: ax.title(...) → TypeError. On an Axes: set_title, set_xlabel
  • Dates still text: 727 tick labels, a black band → parse_dates
  • x and y from different filters → ValueError: x and y must have same first dimension
