1.4

Random Number Generation

Random numbers you can reproduce, and simulations you can check.

1.4 · Why it matters

Why would a data course make numbers up?

  • Sampling: pick 200 orders to audit in a way nobody can call biased
  • Shuffling: see what "no real difference" looks like
  • Simulation: act a tangled question out thousands of times and count
  • Test data: try your code before the real data arrives
WHY The statistics module leans on all four.
1.4 · Mental model

The book of random digits

  • An enormous book of digits that pass every test of randomness
  • You open it at a page and read off numbers as you need them
  • The seed is the page you open at: same page, same numbers
  • Each draw moves the bookmark forward
WHY That is not a weakness. It lets someone else rerun your analysis and get your result.
1.4 · Code

A generator, and numbers everyone can reproduce

rng = np.random.default_rng(42)

print(rng.random())        # one float, from 0 up to (not including) 1
print(rng.random(5))       # an array of five
print(rng.integers(1, 7, size=10))    # ten dice: the upper end is left out
0.7739560485559633
[0.43887844 0.85859792 0.69736803 0.09417735 0.97562235]
[5 5 5 5 4 1 6 3 4 3]
WHY Same seed, same order of draws: your screen shows exactly these digits.
1.4 · Code

The bookmark moves

a = np.random.default_rng(2024)
print(a.integers(0, 100, size=5))
print(a.integers(0, 100, size=5))

a = np.random.default_rng(2024)

[24 67  9 21 31]
[30 90 79 91 99]
[24 67  9 21 31]
  • A second draw gives the NEXT five
  • Re-create the generator to start over
  • Rerunning a cell moves the bookmark
  • Reproducible: same code, run from the top
1.4 · Code

Draw from your own values

print(rng.choice(store_names, size=6))                    # with replacement: repeats allowed
print(rng.choice(store_names, size=3, replace=False))     # without: three different stores

deck = np.arange(10)
print(rng.shuffle(deck))         # shuffles IN PLACE and returns None
['Bend' 'Asheville' 'Asheville' 'Boise' 'Flagstaff' 'Asheville']
['Flagstaff' 'Bend' 'Boise']

WATCH deck = rng.shuffle(deck) replaces your deck with None. Use rng.permutation(deck) for a copy.

1.4 · Simulation

Model, repeat, count

buyers = rng.binomial(n=485, p=0.236, size=100_000)     # MODEL one day; REPEAT 100,000 times

ran_out = buyers > 130                                  # COUNT: 130 gift bags
print(ran_out.sum(), "of", buyers.size, "simulated days")
print(f"estimated chance of running out: {ran_out.mean():.1%}")
4430 of 100000 simulated days
estimated chance of running out: 4.4%
WHY A "what is the chance that..." question is the mean of a mask.
1.4 · Simulation

The part no amount of simulation fixes

boise_visitors = visitors[stores == "Boise"].astype(int)
print(boise_visitors.min(), boise_visitors.max(), boise_visitors.mean().round(1))

sim_visitors = rng.choice(boise_visitors, size=100_000)  # a real day's visitors
sim_buyers = rng.binomial(n=sim_visitors, p=0.236)  # buyers among them
print(f"estimated chance of running out: {(sim_buyers > 130).mean():.1%}")
177 1164 485.2
estimated chance of running out: 27.8%
WATCH Same question, same 100,000 runs. More simulations: more precise. A better model: more true.

1.4 · Common mistakes

Wrong random output looks just as random

  • "My numbers changed" → a cell that draws was run twice. Run from the top
  • The generator created inside a loop → the same "random" day, every time
  • integers(1, 6) is a five-faced die → the upper end is left out
  • A stable estimate from a weak model → precise is not the same as right
FIX One generator, created once, with a seed. Check .min(), .max(), and the model against real data.

1.5

Linear Algebra Essentials

Multiply each thing by a weight, and add up the results.

1.5 · Why it matters

So much of data work is one pattern

  • An order total is quantities weighted by prices
  • A course grade is scores weighted by percentages
  • A prediction is measurements weighted by coefficients
  • Today: do it to whole tables at once, and run it backward to FIND the weights
WHY A vector is a 1-D array. A matrix is a 2-D array. Only the names are new.
1.5 · Mental model

The receipt, seen from four sides

  • One receipt: a dot product
  • A stack of receipts priced from one list: a matrix times a vector
  • Quantities and totals known, prices unknown: solving a system
  • The same with noisy totals, so nothing fits perfectly: least squares
1.5 · Code

One receipt: the dot product

quantities = np.array([2, 1, 3])
prices = np.array([299.95, 82.95, 24.50])

print(quantities * prices)             # the three line totals
print((quantities * prices).sum())     # the order total
print(quantities @ prices)             # the same thing: a dot product
[599.9   82.95  73.5 ]
756.35
756.35
WHY Multiply matching positions and add everything up. Two vectors in, one number out.
1.5 · Code

A stack of receipts: matrix @ vector

orders = np.array([[2, 1, 3],
                   [1, 0, 2],
                   [0, 4, 1]])

print(orders @ prices)
print((orders * prices).shape)
[756.35 348.95 356.3 ]
(3, 3)
  • (3, 3) @ (3,) gives (3,)
  • Each row dotted with the prices
  • * keeps the shape: a table of line totals
  • @ multiplies and adds
1.5 · The shape rule

(n, k) @ (k, m) gives (n, m)

both = orders @ price_lists          # (3, 3) @ (3, 2)
print(both.shape)

wrong_order = price_lists @ orders   # (3, 2) @ (3, 3)
ValueError: matmul: Input operand 1 has a mismatch in its core dimension 0,
    ... (size 3 is different from 2)
FIX Read the END of the message. The inner numbers must match: swap the operands, or use .T.
1.5 · Code

Run the receipt backward

slip_totals = np.array([756.35, 348.95, 356.30])

recovered = np.linalg.solve(orders, slip_totals)
print(recovered)
print(np.allclose(orders @ recovered, slip_totals))
[299.95  82.95  24.5 ]
True
WHY Three equations, three unknowns. Always put the answer back into the original equation.
1.5 · Code

Least squares: the best line through 726 days

A = np.column_stack([np.ones(x.size), x])     # a column of ones, a column of visitors
coef, *_ = np.linalg.lstsq(A, y)
intercept, slope = coef
print(f"revenue = {intercept:.2f} + {slope:.2f} * visitors")

residuals = y - A @ coef                      # actual minus predicted
print(f"typical miss (RMSE): ${np.sqrt((residuals ** 2).mean()):,.2f}")
revenue = -238.85 + 21.39 * visitors
typical miss (RMSE): $1,344.33
WHY "Each additional visitor goes with about $21 more revenue." It describes; it does not prove.
1.5 · Code

More features are more columns; a prediction is one more @

A2 = np.column_stack([np.ones(x.size), x, promo[keep]])
coef2, *_ = np.linalg.lstsq(A2, y)
print(coef2.round(2))

scenarios = np.array([[1, 400, 0],      # an ordinary day, 400 visitors
                      [1, 700, 1]])     # a sale Saturday, 700 visitors
print((scenarios @ coef2).round(2))
[ 189.11   20.34 2502.17]
[8325.58 16930.1]
WHY Quote a forecast with its typical miss: about $8,300, give or take $1,300.

1.5 · Common mistakes

Mostly shapes, and one about meaning

  • * where @ was meant → no error, wrong shape. Print it
  • Shapes that do not chain → read the end of the message; swap, or .T
  • One nan in the data → every coefficient is nan. One mask, every array
  • No column of ones → the line is forced through zero, silently
  • "One more staff member adds $1,154" → what else is true of those days?
FIX Write the shapes first. Put the answer back in. Read a coefficient as "goes with".

What carries over to pandas? All of it

  • Arrays, dtypes and nan: every pandas column is an array underneath
  • Whole-array arithmetic and masks: a filter will apply to every column at once
  • axis, shapes and broadcasting: the same rules, with labels to protect you
  • Random sampling and @: the engines under statistics and models
  • What changes: columns get names, rows get labels, and the bookkeeping is done for you
