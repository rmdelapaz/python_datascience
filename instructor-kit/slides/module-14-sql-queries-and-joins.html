5.1 · Mental model

The binder and the librarian

  • A CSV is a photocopied binder: carry it all to your desk
  • A database is a library with a librarian at the desk
  • You hand over a request slip. Only those pages come back.
  • The slip is written in SQL. The librarian is the engine.

5.1 · Code

GROUP BY and HAVING

show("""
    SELECT store, COUNT(*) AS orders, ROUND(AVG(order_total), 2) AS avg_order
    FROM orders
    WHERE status = 'completed'
    GROUP BY store
    HAVING AVG(order_total) > 180
    ORDER BY avg_order DESC
""")
    store  orders  avg_order
   Online   11604     203.20
Flagstaff    1648     182.39
RULE WHERE filters rows before grouping. HAVING filters groups after it.
5.1 · The order it runs

You write SELECT first. The engine starts at FROM.

  1. FROM: pick the table
  2. WHERE: keep matching rows
  3. GROUP BY: form groups
  4. HAVING: keep matching groups
  5. SELECT: compute the columns
  6. ORDER BY, then LIMIT
SO An aggregate in WHERE fails: the groups do not exist yet.

Complex Queries

Combine tables without losing or inventing rows.

5.2 · Why it matters

Real data has cards with no partner

  • 739 orders belong to closed accounts not in customers
  • 1,058 customers have never ordered
  • 609 order lines use 6 SKUs no longer in products
  • 8 products have never sold
HABIT Say the row count you expect. Then count.
5.2 · Mental model

Two stacks of index cards

  • Take an order card. Find the customer card with the same id.
  • Staple them into one wider card.
  • Every join is the same stapling.
  • They differ in one thing: what happens to a card with no partner.

INNER JOIN: only the matches

show("""

5.2 · Code

A CTE names the step

show("""
    WITH spend AS (SELECT customer_id, SUM(order_total) AS total_spent
                   FROM orders WHERE status = 'completed' GROUP BY customer_id)
    SELECT c.loyalty_tier, COUNT(*) AS customers,
           ROUND(MIN(s.total_spent), 2) AS lowest_spend
    FROM spend AS s JOIN customers AS c ON c.customer_id = s.customer_id
    GROUP BY c.loyalty_tier ORDER BY lowest_spend
""")
loyalty_tier  customers  lowest_spend
       Basic       1710          7.50
      Silver       1294        600.43
        Gold        734       1502.00
WHY spend has one row per customer BEFORE the join: no fan-out.
5.2 · Code

A recursive CTE walks the tree

WITH RECURSIVE org (employee_id, level) AS (
    SELECT employee_id, 1
    FROM employees
    WHERE manager_id IS NULL
    UNION ALL
    SELECT e.employee_id, org.level + 1
    FROM employees AS e
    JOIN org ON e.manager_id = org.employee_id
)
SELECT level, COUNT(*) FROM org GROUP BY level
  • Anchor: the top of the tree
  • Recursive part: who reports to the rows found last round?
  • Stops when a round finds nobody
  • Six levels: 1, 4, 7, 14, 8, 21 people

5.2 · Common mistakes

Three wrong answers, no error message

  • An inner join that silently drops unmatched rows
  • A total summed after a fan-out: $10.3M instead of $3.7M
  • A filter on the right table in WHERE undoes the LEFT JOIN (put it in ON)
  • = NULL never matches · NOT IN with a NULL returns nothing
FIX count rows · aggregate first, then join · IS NULL, NOT EXISTS
