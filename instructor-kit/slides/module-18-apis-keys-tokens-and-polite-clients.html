6.4 · Code

Follow next to the end

def get_all(path, params=None):
    """Collect every item from a paginated endpoint by following 'next'."""
    items, url = [], f"{API}{path}"
    while url:
        data = check(requests.get(url, headers=KEY_HEADERS, params=params,
                                  timeout=10)).json()
        items.extend(data["items"])
        url = f"{API}{data['next']}" if data["next"] else None
        params = None              # 'next' already carries the filters
    return items
WHY Filters with the first request only: next carries them

6.5

Rate Limiting and Retries

Fast enough to finish, slow enough to be welcome.

6.5 · Mental model

The on-ramp light

  • Politeness: pace yourself, obey Retry-After, never ask twice
  • Resilience: retry what is temporary, give up clearly
  • Save work as you go, so an interruption loses nothing
  • Retry: a reason, a wait, a limit
RULE Retries are a safety net, not a pace

6.5 · Code

Plan A: pace yourself

interval = PER / LIMIT * 1.1
fresh_window()
throttle, statuses, started = Throttle(interval), [], time.monotonic()
for i in range(13):
    throttle.wait()
    statuses.append(requests.get(f"{API}/products", params={"per_page": 1},
                                 headers=HEADERS, timeout=10).status_code)
print(f"every {interval:.2f} s:", statuses.count(200), "of 13 succeeded,",
      f"about {time.monotonic() - started:.0f} s")
every 0.55 s: 13 of 13 succeeded, about 7 s
WHY window ÷ allowance × 1.1; the Throttle sleeps only for what is left

6.5 · Code

Backoff, and why it needs jitter

def backoff_delay(attempt, base=0.5, cap=8.0):
    """Seconds to wait after failed attempt number `attempt` (from 0)."""
    return min(cap, base * 2 ** attempt)


print([backoff_delay(n) for n in range(6)])
rng = random.Random(7)
print([round(rng.uniform(0, backoff_delay(n)), 2) for n in range(6)])
[0.5, 1.0, 2.0, 4.0, 8.0, 8.0]
[0.16, 0.15, 1.3, 0.29, 4.29, 2.93]
WHY Waves of retries keep a server down: spread them

6.5 · Code

The same policy, built in
