3.4

Saving Figures

The last step is part of the work.

3.4 · Why it matters

A chart in a notebook has an audience of one

  • Charts that matter end up on a slide, a web page, a printed report
  • Each place has its own demands: pixels, format, background
  • The usual failures: blurry, cut off at the edge, text too small to read
  • Almost always the same handful of settings
3.4 · Mental model

A sheet of paper and a scanner

  • figsize is the sheet of paper, in inches
  • dpi is the scanner: dots for every inch
  • pixels = inches x dpi
  • A finer scan makes everything sharper
  • A bigger sheet makes the text smaller relative to the page
WHY Two knobs. Keep them apart and most export problems solve themselves.
3.4 · Code

Save it, then read it back

fig.savefig(out / "boise.png")           # figsize=(8, 4), default dpi 100

saved = out / "boise.png"

True

WHY fig.savefig(), not plt.savefig(): say which figure you mean.

Same sheet, three scanners

3.4 · The rule

Why the text came out tiny

  • Both files: 1,200 x 600 pixels
  • Font sizes are in points: 1 point = 1/72 inch on the sheet
  • On the 6-inch sheet the same title is twice as prominent
  • Text too small? Smaller figsize, higher dpi
  • Raising the dpi alone never makes text bigger
WHY figsize sets how big the text looks. dpi sets how many pixels you get.
3.4 · Formats

Raster or vector

  • PNG (raster): a grid of pixels. Web, slides, email. Works everywhere
  • SVG (vector): sharp at any zoom on a web page
  • PDF (vector): print, reports, many pages in one file
  • JPEG: for photographs. Never for charts
  • Heavy scatter in a PDF? rasterized=True on that layer
WHY The format comes from the file extension you give.
3.4 · Code

The tight box changes the size

fig.savefig(out / "boise_default.png", dpi=100)
fig.savefig(out / "boise_tight.png", dpi=100, bbox_inches="tight")

for name in ("boise_default.png", "boise_tight.png"):
    rows, cols = plt.imread(out / name).shape[:2]
    print(f"{name:<20} {cols} x {rows}")
boise_default.png    800 x 400
boise_tight.png      811 x 411
WHY With layout="constrained" you rarely need it. For an exact size, leave it off.

3.4 · Code

Put the decisions in one place

PRESETS = {
    "web":   {"figsize": (9, 4.5),   "dpi": 110, "extension": "png"},   #  990 x 495
    "slide": {"figsize": (9.6, 5.4), "dpi": 200, "extension": "png"},   # 1920 x 1080
    "print": {"figsize": (6.5, 3.5), "dpi": 300, "extension": "pdf"},   # vector
}

def new_figure(kind="web"):
    return plt.subplots(figsize=PRESETS[kind]["figsize"], layout="constrained")
WHY Create the figure at the right size before drawing. save_chart() reads the same table.

3.4 · Common mistakes

Three that raise no error

  • Raising dpi to fix small text: bigger file, same tiny text
  • plt.savefig() after another figure was made: a blank file
  • bbox_inches="tight" when the slide needs exactly 1,920 x 1,080
  • The check for all three: plt.imread(path).shape, then open the file
WATCH Judge the saved file at the size it will be shown, not the notebook preview.

4.1

Descriptive Statistics I: Center and Spread

Two honest numbers for 20,302 orders.

4.1 · Why it matters

"Our average order is $195"

  • A sentence like that ends up on a slide, then in a budget
  • For Pinecrest it is true
  • And most orders are nowhere near $195
  • Knowing which summary to trust stops a correct calculation from becoming a wrong decision
4.1 · Mental model

The restaurant review

  • Nobody reads 1,000 reviews. You look at the average rating
  • Then, if you are careful, at how much the reviews disagree
  • A 4.2 where everyone gave a 4 is not a 4.2 made of fives and ones
  • Center: what is typical? mean, median, mode
  • Spread: how much does it vary? range, variance, SD, IQR
WHY Two numbers are the least you need to describe a column honestly.
4.1 · Predict, then run

One bulk order joins five ordinary ones

five = np.array([42.50, 88.00, 150.00,
                 163.25, 271.00])
six = np.append(five, 4893.00)

print(five.mean(), np.median(five))
print(six.mean(), np.median(six))
  • The first line prints 142.95 and 150.0
  • Predict the second line
  • Which number still describes an order?
PREDICT The mean is a balance point: a far-away weight has leverage.
4.1 · Code

Mean and median of the real column

print("mean  :", round(totals.mean(), 2))
print("median:", totals.median())

4.1 · Code

Is it just the twelve bulk orders?

is_bulk = totals > 2000
print("bulk orders:", is_bulk.sum())
print("mean without them  :", round(totals[~is_bulk].mean(), 2))
print("median without them:", totals[~is_bulk].median())
print("orders above $500  :", (totals > 500).sum())
bulk orders: 12
mean without them  : 192.63
median without them: 146.85
orders above $500  : 1131
WHY The whole tail does it. Mean for totals, median for a typical order: report both.
4.1 · Code

The mode: the only center for categories

print(orders["payment_method"].mode()[0])
print(pd.Series([1, 1, 2, 2, 3]).mode().tolist())
print(totals.mode()[0], "appears", (totals == totals.mode()[0]).sum(), "times")
card

WHY .mode() returns a Series: ties happen. For a measured quantity the mode is an accident.
4.1 · Code

A variance by hand

tents = np.array([4, 7, 5, 10, 4])
deviations = tents - tents.mean()

print("deviations     :", deviations, " sum:", deviations.sum())
print("squared        :", deviations ** 2, " sum:", (deviations ** 2).sum())
print("divide by n    :", (deviations ** 2).sum() / 5)
print("divide by n - 1:", (deviations ** 2).sum() / 4)
deviations     : [-2.  1. -1.  4. -2.]  sum: 0.0
squared        : [ 4.  1.  1. 16.  4.]  sum: 26.0
divide by n    : 5.2
divide by n - 1: 6.5
WHY SD = square root of the variance, back in tents: 6 a day, give or take about 2.5.
4.1 · Code

Two libraries, two standard deviations

print("np.std(tents)            :", round(np.std(tents), 4))
print("pd.Series(tents).std()   :", round(pd.Series(tents).std(), 4))
print("np.std(tents, ddof=1)    :", round(np.std(tents, ddof=1), 4))
np.std(tents)            : 2.2804
pd.Series(tents).std()   : 2.5495
np.std(tents, ddof=1)    : 2.5495
WHY NumPy: divide by n (ddof=0). pandas: n - 1 (ddof=1). If unsure, use ddof=1.
4.1 · Code

The IQR shrugs off a $1,000,000 typo

q1, q3 = totals.quantile(0.25), totals.quantile(0.75)
with_typo = pd.concat([totals, pd.Series([1_000_000.0])], ignore_index=True)
typo_iqr = with_typo.quantile(0.75) - with_typo.quantile(0.25)

print("Q1:", q1, " Q3:", q3)
print("SD :", round(totals.std(), 2), "->", round(with_typo.std(), 2))
print("IQR:", round(q3 - q1, 2), "->", round(typo_iqr, 2))
Q1: 78.85  Q3: 264.95
SD : 178.76 -> 7019.02
IQR: 186.1 -> 186.13
WHY The middle half of orders are between $78.85 and $264.95.
4.1 · Choosing

Pair center with spread

  • Roughly symmetric, no extremes: mean and SD
  • Skewed, or a few extreme values: median and IQR
  • May contain errors you have not cleaned: median
  • Needed for a total or a forecast: mean
  • Categories: mode and counts
WHY A histogram tells you which kind of column you have.

revenue = pd.read_csv("data/daily_sales.csv")["revenue"]

4.1 · Common mistakes

Three that raise no error

  • np.std and .std() disagree: check ddof first
  • Averaging group averages: $182.66 instead of $194.60
  • Mean and SD for skewed data, out of habit
  • The fix for the third: every mean gets a median next to it
WATCH "Orders average $195 plus or minus $179" paints a hump that does not exist.
