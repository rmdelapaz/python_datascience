NoSQL with MongoDB

Not all data is rows and columns.

5.5 · Why it matters

One website visit is not a row

  • A device, a list of pages, a cart with a list of items
  • In SQL: three tables and two joins to see one visit
  • Web APIs, logs and events already arrive as nested JSON
  • After today: five kinds of source, one destination (a DataFrame)
5.5 · Mental model

The ledger and the folder

  • Ledgers: fixed columns, facts spread over tables that point at each other
  • Folders: everything about one thing, in whatever shape it has
  • Two folders need not hold the same sheets
  • Neither is better. Orders live in pinecrest.db; sessions suit documents
MAP table → collection · row → document · column → field · primary key → _id

5.5 · Code

Missing is not the same as null

n = coll.count_documents
print("customer_id is null :", n({"customer_id": None}))
print("customer_id missing :", n({"customer_id": {"$exists": False}}))
print("utm missing         :", n({"utm": {"$exists": False}}))
print("utm equals None     :", n({"utm": None}))
customer_id is null : 1547
customer_id missing : 0
utm missing         : 916
utm equals None     : 916
WATCH None matches null and missing. $exists is the precise tool.
5.5 · Predict, then run

Which one is "90 seconds on the cart page"?

any_page = {"pages.path": "/cart", "pages.seconds": {"$gte": 90}}
same_page = {"pages": {"$elemMatch": {"path": "/cart",
                                      "seconds": {"$gte": 90}}}}
print("without $elemMatch:", coll.count_documents(any_page))
print("with $elemMatch   :", coll.count_documents(same_page))
PREDICT Vote first: which count is bigger, and why?
5.5 · Code

The first pipeline: group and count

pipeline = [
    {"$group": {"_id": "$device.os",
                "sessions": {"$sum": 1},
                "avg_cart": {"$avg": "$cart.value"}}},
    {"$sort": {"sessions": -1}},
]
by_os = pd.DataFrame(list(coll.aggregate(pipeline)))
print(by_os[["_id", "sessions", "avg_cart"]].round(2).to_string(index=False))
SQL SELECT os, COUNT(*), AVG(cart_value) ... GROUP BY os ORDER BY 2 DESC
5.5 · Code

Match, unwind, group, match again

pipeline = [
    {"$match": {"device.type": "desktop"}},
    {"$unwind": "$pages"},
    {"$match": {"pages.path": {"$regex": "^/product/"}}},
    {"$group": {"_id": "$pages.path", "views": {"$sum": 1},
                "avg_seconds": {"$avg": "$pages.seconds"}}},
    {"$match": {"views": {"$gte": 9}}},
    {"$sort": {"views": -1, "_id": 1}},
    {"$limit": 4},
]
WHY Before $group, $match is WHERE. After it, HAVING. $unwind is pandas explode.
5.5 · Common mistakes

Two typos, no error message

print(coll.count_documents({"device.typ": "mobile"}))
wrong = coll.aggregate([{"$group": {"_id": "device.type",
                                    "sessions": {"$sum": 1}}}])
print(list(wrong))
0
[{'sessions': 2400, '_id': 'device.type'}]
WATCH Be suspicious of zero. Look at one real document first.
5.5 · Common mistakes

Three to watch for

  • A misspelled field or wrong-case value returns 0, not an error
  • Field value in a pipeline needs the dollar: "$device.type"
  • Two conditions on one list element need $elemMatch
  • A cursor reads once: docs = list(cursor), then reuse docs
HABIT find_one() and distinct() before you trust a count

6.1

HTTP with Requests

One request, one response, and good manners.

Module 6 · Ground rules

Six rules, every session

  1. Read robots.txt and obey it
  2. Read the terms of use
  3. Prefer an API or a download when one exists. It is the front door.
  4. Go slowly and say who you are
  5. Never go around a login, a paywall or a block
  6. Do not collect personal data
6.1 · Why it matters

Everything in Module 6 sits on this

  • Beautiful Soup parses what requests downloads
  • An API client is requests plus a key
  • Rate limiting is deciding when to send the next request
  • When something breaks, the answer is in a status code or a header
6.1 · Mental model

The order counter

  • You hand over a slip: what you want, and a few notes about yourself
  • A tray comes back: a ticket with a number, then the food
  • The server never calls you. It only answers
  • It does not remember your last order unless you remind it
STATUS 2xx use it · 3xx nothing to do · 4xx fix your request · 5xx wait and retry

6.1 · Code

An API: parameters in, JSON out

API = "http://127.0.0.1:8000"

r = requests.get(f"{API}/products",
                 params={"category": "Camp Kitchen", "per_page": 3},
                 headers=HEADERS, timeout=10)
r.raise_for_status()
print(r.url)
print(r.headers["Content-Type"])
data = r.json()
print(list(data))
print(data["total"], "in the category;", len(data["items"]), "on this page")
WHY It built ...?category=Camp+Kitchen&per_page=3. Pass a dictionary; never glue the string yourself.

6.1 · Common mistakes

Three to watch for

  • Parsing an error page as data: check the status after every get
  • No timeout=, or the practice API is not running
  • Hand-built query strings; .json() on an HTML page
  • Stars that print as â˜…: set r.encoding = "utf-8"
DEBUG Print r.status_code, r.url and r.text[:200]
