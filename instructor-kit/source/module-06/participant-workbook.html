2.5

Merging and Joining

95 min lesson
By the end you can
  • Combine two tables on a key with merge() and choose between inner, left, right and outer joins
  • Find the keys that have no match on either side with indicator=True, and decide what to do about them
  • State the relationship between two tables (one-to-one, many-to-one, many-to-many) and enforce it with validate=
  • Predict and check the row count of a merge, and avoid double counting after a one-to-many merge
  • Merge on differently named or multiple keys, stack tables with concat(), and recognize when merge_asof() is the right tool
Key ideas
  • The claim ticket. A key is a column that appears in both tables. left.merge(right, on="key") finds, for each left row, the right rows with the same key. Two questions: what if a key has no match? What if it matches more than once?
  • Four joins. how="inner" (the default) keeps only keys in both tables · "left" keeps every row of the left table · "right" every row of the right · "outer" every row of both. Missing partners become NaN.
  • Count before, count after. Say what the row count should be, then check. Fewer rows: keys failed to match. More rows: keys matched more than once.
  • The working default. Adding columns to a main table? how="left". Select only the columns you need from the right table (key included) before merging.
  • indicator=True adds _merge: both, left_only, right_only. Unmatched rows are findings with causes (closed accounts, discontinued products). Decide what to do with them; do not let the default decide.
  • Relationships. one-to-one, many-to-one (safe: the row count cannot grow), one-to-many (rows multiply: one per match), many-to-many (usually a mistake). validate="many_to_one" makes pandas check that the key is unique where you believe it is.
  • Know what one row means. After a one-to-many merge, columns from the 'one' side are repeated. Never sum or average them there. Aggregate first, then merge.
  • Awkward keys. Different names: left_on=, right_on=. Several columns: lists. Clashing column names: suffixes=. Keys must have the same dtype. Missing keys match each other.
  • Other tools. pd.concat([a, b], ignore_index=True) stacks tables with the same columns. pd.merge_asof matches the nearest earlier key (both tables sorted).

2.6

Pivot Tables and Reshaping

85 min lesson
By the end you can
  • Build a summary grid with pivot_table() by choosing its rows, columns, values and aggregation, and add totals with margins=True
  • Count and compare categories with pd.crosstab(), including row and column percentages
  • Choose between pivot() and pivot_table(), and explain the "duplicate entries" error
  • Recognize wide and tidy (long) layouts and convert between them with melt(), stack() and unstack()
  • Check a pivot before you trust it: its aggregation, its cell counts, its empty cells and its totals
Key ideas
  • Logbook and scoreboard. Long (tidy) data has one row per observation: it is for analysis. Wide data spreads one variable across the header: it is for reading. Tidy means each variable is a column, each observation a row, each cell one value.
  • Four questions. df.pivot_table(index=..., columns=..., values=..., aggfunc=...): what is each row, what is each column, which number goes in the cells, how are many rows combined? A pivot table is a groupby spread into a grid.
  • Always write aggfunc=. The default is the mean, not the sum.
  • Totals and empty cells. margins=True adds totals computed from all the underlying rows. A combination that never occurs is NaN: fill_value=0 is right for counts and sums, wrong for averages. The corner of a count pivot should equal the number of source rows.
  • pd.crosstab(a, b) counts combinations. normalize="index": each row sums to 1 ('of online orders, what share were returned?'). normalize="columns": each column sums to 1 ('of returned orders, what share were online?'). Different questions.
  • pivot() versus pivot_table(). pivot() only rearranges and fails with 'duplicate entries' when a cell would get several rows. That error is information about your data.
  • melt(id_vars=..., value_vars=..., var_name=..., value_name=...) turns header labels back into a column. stack() and unstack() do the same moves on index levels.
  • Labels are sorted. Month and weekday names come out alphabetical. Pivot on numbers, or reindex in the order you want.
  • Before you trust a pivot. What is one row of the source? What is the aggregation? How many rows are behind each cell? What do empty cells mean? Do the totals reconcile? Does a total hide a difference inside it?

Glossary for Session 6

  • Key: a column (or set of columns) that appears in two tables and connects their rows.
  • Merge / join: combining two tables side by side by matching rows on a key.
  • Inner join: keeps only keys found in both tables. The default of merge.
  • Left join: keeps every row of the left table; unmatched rows get NaN in the borrowed columns.
  • Outer join: keeps every row of both tables.
  • Indicator: the _merge column added by indicator=True: both, left_only or right_only.
  • Many-to-one: a relationship in which the key is unique in the right table: each left row finds at most one partner.
  • One-to-many: the key is unique in the left table: each left row can match several right rows, so rows multiply.
  • Many-to-many: the key repeats on both sides: every pairing appears. Usually a mistake.
  • validate=: a merge argument that states the expected relationship and raises MergeError if the keys say otherwise.
  • Concatenate: stacking tables on top of each other with pd.concat.
  • Long (tidy) data: one row per observation, one column per variable: the logbook.
  • Wide data: one variable's values spread across the column headers: the scoreboard.
  • Pivot table: a groupby on row and column keys whose result is spread into a grid.
  • Margins: the totals row and column added by margins=True, computed from all the underlying rows.
  • Crosstab: a table of counts of two categorical columns (pd.crosstab); normalize turns counts into shares.
  • Melt: turning column headers back into the values of one column (df.melt): wide to tidy.
