1.2 · Vectorized Operations: self-check

Q1
What does this print?
v = np.array([4, 9, 2, 7])
print((v > 3).sum(), (v > 3).mean())
A) 3 0.75
B) 20 0.75
C) [4 9 7] 3
D) 3 6.67
Why: The comparison gives a mask, [ True True False True]. True counts as 1, so the sum is how many are true (3) and the mean is the fraction that are true (3 of 4).
B is wrong: 20 is the sum of the VALUES that pass. The sum of a mask counts; v[v > 3].sum() would add the values.
C is wrong: That is the filter v[v > 3], not the sum of the mask.
D is wrong: 6.67 is the mean of the values that pass, v[v > 3].mean(). The mean of the mask is a fraction between 0 and 1.
Q2
stores (text) and visitors (numbers) are parallel arrays. Which line counts the Bend store-days with more than 500 visitors?
A) (stores == "Bend" and visitors > 500).sum()
B) (stores == "Bend" & visitors > 500).sum()
C) ((stores == "Bend") & (visitors > 500)).sum()
D) (stores == "Bend").sum() & (visitors > 500).sum()
Why: Combine masks with & and put parentheses around each comparison. The sum of the combined mask is the count.
A is wrong: and wants one true-or-false value on each side and gets an array: ValueError: The truth value of an array ... is ambiguous.
B is wrong: Without parentheses Python evaluates "Bend" & visitors first and raises a TypeError that mentions bitwise_and.
D is wrong: That counts each group separately and then does a bitwise "and" of two whole numbers. It answers no question at all.
Q3
What does this print?
t = np.array([[1, 2, 3],
              [4, 5, 6]])
print(t.max(axis=1), t.sum(axis=0).shape)
[3 6] (3,)
Why: The axis you name is the axis that disappears. axis=1 collapses the 3 columns and leaves one value per row: the row maximums 3 and 6. axis=0 collapses the 2 rows and leaves one value per column, so the shape is (3,).
Q4
What does this print?
x = np.array([5.0, np.nan, 12.0])
print((x > 8).sum() + (x <= 8).sum())
A) 3
B) 2
C) nan
D) 1
Why: Every comparison with nan is False. The missing value is counted in neither group, so one value is above 8, one is not, and one has silently dropped out.
A is wrong: That assumes every value is in one group or the other. A missing value is in neither.
C is wrong: The masks hold only True and False, so their sums are ordinary whole numbers.
D is wrong: 1 is the count of one group alone.
Q5
What does this print?
p = np.array([40, 95, 60])
print(np.where(p >= 60, "pass", "retry"))
['retry' 'pass' 'pass']
Why: np.where(condition, value_if_true, value_if_false) is an if/else for every element, and the result keeps the array's shape. 60 passes because the test is >=.
Q6
What does this print?
names = np.array(["Asheville", "Bend", "Boise", "Flagstaff"])
totals = np.array([2935, 3312, 4347, 2661])
print(names[totals.argmax()], totals.argmin())
A) 4347 2661
B) Boise Flagstaff
C) 2 3
D) Boise 3
Why: argmax and argmin return positions, not values. Position 2 looked up in the parallel array names is Boise; the smallest total is at position 3.
A is wrong: Those are totals.max() and totals.min(): the values, not their positions.
B is wrong: The second part is printed as a bare position; nothing looked it up in names.
C is wrong: The first part IS looked up in names, so it prints a store name.

1.2 · Vectorized Operations: predict, then run

P1
What does this print?
s = np.array([3, 8, 5, 10])
m = s > 4
print(m, s[m], s[~m])
[False  True  True  True] [ 8  5 10] [3]
Why: The mask marks the values above 4. In brackets it keeps them; ~m flips every True and False, so it keeps the rest.
P2
What does this print?
g = np.array([[1, 2],
              [3, 4],
              [5, 6]])
print(g.sum(axis=0), g.sum(axis=1), g.sum())
[ 9 12] [ 3  7 11] 21
Why: Shape (3, 2). axis=0 collapses the three rows and leaves one total per column (two numbers). axis=1 collapses the two columns and leaves one total per row (three numbers). With no axis, everything is added.
P3
What does this print?
r = np.array([200.0, np.nan, 50.0])
print((r > 100).sum(), (r == np.nan).sum(), np.isnan(r).sum())
1 0 1
Why: One value is above 100. Nothing is ever equal to nan, not even nan itself, so the middle count is 0. np.isnan is the test that finds the missing value.

1.3 · Broadcasting: self-check

Q7
An array of shape (6, 3) is added to an array of shape (3,). What is the result?
A) A ValueError, because the shapes are different
B) An array of shape (6, 3)
C) An array of shape (6,)
D) An array of shape (3, 3)
Why: Line the shapes up from the right: 3 meets 3 (equal), and 6 meets a missing axis, which counts as 1. The row of three is reused on each of the six rows.
A is wrong: Different shapes are allowed when every pair of lengths is equal or one of them is 1.
C is wrong: The result takes the larger length from each pair; nothing is collapsed.
D is wrong: The 6 does not shrink to match anything; the smaller array is the one that is reused.
Q8
t has shape (30, 4): 30 days as rows, 4 stores as columns. Which expression subtracts each day's mean from that day's row?
A) t - t.mean(axis=1)
B) t - t.mean(axis=0)
C) t - t.mean(axis=1, keepdims=True)
D) t - t.mean()
Why: Per-day means are one value per row, and to line up with the rows they must stand as a column of shape (30, 1). keepdims=True keeps the collapsed axis with length 1.
A is wrong: The 30 day-means come back flat, shape (30,). From the right, 4 meets 30: ValueError.
B is wrong: That runs, but it subtracts each STORE's mean from its column: a different question.
D is wrong: That subtracts one number, the mean of everything, from every cell.
Q9
What does this print?
a = np.array([1, 2, 3])
b = np.array([[10], [20]])
print((a * b).shape, (a * b)[1, 2])
(2, 3) 60
Why: A row of three meets a column of two, so both are stretched into a 2 by 3 grid of every combination. Row 1, column 2 is 20 times 3.
Q10
Which pair of shapes can NOT be broadcast together?
A) (8, 1) and (1, 5)
B) (8, 5) and (5,)
C) (8, 5) and (1,)
D) (8, 5) and (8,)
Why: Shapes are matched from the right, so the 8 of the flat array is compared with the 5 columns. They are not equal and neither is 1.
A is wrong: Each pair has a 1 in it: a column meets a row and the result is (8, 5).
B is wrong: 5 meets 5, and 8 meets a missing axis: a table and a row.
C is wrong: A length of 1 fits anything; this is the same as combining with a single number.
Q11
What does this print?
print(np.broadcast_shapes((4, 1), (3,)))
(4, 3)
Why: From the right: 1 meets 3 (compatible, result 3), then 4 meets a missing axis (compatible, result 4). A column of four against a row of three is a 4 by 3 grid.
Q12
sales has shape (12,) and plan has shape (12, 1). What does sales - plan give?
A) An array of shape (12, 12): every sales value minus every plan value, with no error
B) An array of shape (12,) holding the twelve differences
C) A ValueError, because the shapes are different
D) An array of shape (12, 1) holding the twelve differences
Why: A flat array is treated as a row. A row meeting a column builds the grid of every combination: the accidental grid. Twelve values in should mean twelve out; plan.ravel() fixes it.
B is wrong: That is what you wanted, and what you get only after flattening plan.
C is wrong: The shapes are compatible by the rules (12 meets 1, then 12 meets a missing axis), which is exactly why this mistake is silent.
D is wrong: The result takes the larger length from each pair, so both axes come out as 12.

1.3 · Broadcasting: predict, then run

P1
What does this print?
t = np.ones((3, 4))
print((t + np.array([1, 2, 3, 4])).shape, (t + np.array([[1], [2], [3]]))[2])
(3, 4) [4. 4. 4. 4.]
Why: A table and a row of four, then a table and a column of three: both give a (3, 4) result. In the second, 3 is added to everything in row 2, so that row is four 4s.
P2
What does this print?
col = np.array([1, 2, 3])[:, np.newaxis]
row = np.array([10, 20])
print(col + row)
[[11 21]
 [12 22]
 [13 23]]
Why: (3, 1) with (2,): a column meets a row and both are stretched into a 3 by 2 grid holding every sum.
P3
This line fails. Predict the two shapes in the error message, then say which pair of lengths is the problem.
np.ones((3, 4)) + np.array([1, 2, 3])
ValueError: operands could not be broadcast together with shapes (3,4) (3,)
Why: From the right, 4 meets 3: not equal, and neither is 1. The three values would need to stand as a column, shape (3, 1), to be added to the three rows.

Lab Reference Solutions

Every lab has a runnable _solution.py next to its starter in labs/module-02/. The notes give what a correct run prints, the lines that matter and why, and the wrong results you are most likely to see. Check all eight files with python3 labs/check_labs.py module-02.

Lab 1.2-A: labs/module-02/l1_2-vectorized-operations/staffing_load_starter.py → staffing_load_solution.py

Reference output: visitors per staff member: mean 55.3 | min 28.2 | max 116.5; 814 stretched store-days, 28.0% of all store-days; stretched AND sale day: 26; stretched OR sale day: 884; quiet 361, steady 1728, stretched 814; most stretched: 2025-02-26 Bend | 233 visitors, 2 staff; then a per-store block: staff 5.35 / 5.87 / 8.62 / 6.11 and visitors per staff 52.2 / 57.8 / 56.5 / 54.5 for Asheville, Bend, Boise, Flagstaff.

The solution's key lines:

per_staff = visitors / staff
stretched = per_staff >= 60
is_promo = promo == 1
print((stretched & is_promo).sum(), (stretched | is_promo).sum())
labels = np.select([per_staff >= 60, per_staff >= 45], ["stretched", "steady"], default="quiet")
i = per_staff.argmax()
print(dates[i], stores[i], visitors[i], staff[i])

Why: every step is one expression on parallel arrays. The "or" count can be checked by hand: 814 stretched + 96 sale store-days - 26 that are both = 884. The three label counts add up to 2,903 because neither visitors nor staff has missing values. argmax gives one position, and the same position reads the date, the store and both counts.

Common wrong results: stretched count 0 and steady 2,542 (the >= 45 condition listed first: first match wins); 910 for the "or" (added the two counts instead of combining the masks); 116.5 reported as "the most stretched day" (the value, not the row); the bitwise_and TypeError (no parentheses).

Lab 1.2-B: labs/module-02/l1_2-vectorized-operations/eight_weeks_axis_starter.py → eight_weeks_axis_solution.py

Reference output: (56, 4) 2024-01-01 to 2024-02-25; total 13255.0; per store [2935. 3312. 4347. 2661.]; per day, first five [204. 196. 196. 234. 287.]; shapes (4,) (56,); each store's busiest day ['2024-02-24' '2024-02-24' '2024-01-13' '2024-01-27'] with [ 95. 105. 151. 85.] transactions; three busiest days 2024-02-24, 2024-01-13, 2024-01-20 with totals [392. 374. 360.]; Asheville won 1, Bend 8, Boise 45, Flagstaff 2 of 56 days.

The solution's key lines:

store_total = table.sum(axis=0)        # the 56 days disappear: 4 values
day_total = table.sum(axis=1)          # the 4 stores disappear: 56 values
best_row = table.argmax(axis=0)        # for each store, the ROW of its busiest day
print(day[best_row])
top3 = np.argsort(day_total)[::-1][:3]
winner = table.argmax(axis=1)          # for each day, the COLUMN of the busiest store

Why: argmax(axis=0) answers "for each column, which row?", so its four results are row numbers and index the day array. argmax(axis=1) answers "for each row, which column?", so its 56 results are 0 to 3 and index store_names. All three top days are Saturdays.

Common wrong results: dates in early January for every store (day[table.argmax(axis=1)]: column numbers 0 to 3 used as row numbers); the three smallest totals (no [::-1]); a per-store total of 56 numbers (axis swapped). In each case the shape of the result gives it away.

Block 1: and raises ValueError: The truth value of an array with more than one element is ambiguous; use &. Answer 15. Block 2: no parentheses raises TypeError: ufunc 'bitwise_and' not supported...; write (revenue > 20000) & (stores == "Boise"). Answer 15. Block 3: runs and prints 6, and the learner's job is to explain it: the six missing revenues fail both comparisons. np.isnan(revenue).sum() counts them directly. Block 4: capped = revenue is a second name for the same array, so the cap is written into the real data and the last line prints 15000.0 as the largest real revenue. With capped = revenue.copy() the largest real revenue is 27677.1 and 101 values in capped equal 15000.

Lab 1.3-A: labs/module-02/l1_3-broadcasting/fair_visitors_starter.py → fair_visitors_solution.py

Reference output: (224, 4) 2024-01-01 to 2024-08-11; store averages [281.4 323.4 440.9 281.6]; ratio shape (224, 4) with first rows [0.71 0.62 0.76 0.51] and [0.74 0.68 0.7 0.65]; busiest day, times normal [2.51 2.45 2.3 2.4], all on 2024-05-25; without keepdims: operands could not be broadcast together with shapes (224,4) (224,); rows add up to [1. 1. 1.]; average share per store [0.213 0.244 0.332 0.211]; Boise's largest share 0.406 on 2024-04-20, smallest 0.243 on 2024-02-10.

The solution's key lines:

store_mean = table.mean(axis=0)                  # shape (4,)
ratio = table / store_mean                       # (224, 4) with (4,) -> (224, 4)
print(ratio.max(axis=0), day[ratio.argmax(axis=0)])
day_total = table.sum(axis=1, keepdims=True)     # shape (224, 1): a column
share = table / day_total                        # (224, 4) with (224, 1) -> (224, 4)

Why: per-store values are a row and line up with the last axis as they are; per-day values must be a column, which keepdims=True provides. ratio.argmax(axis=0) gives one row position per store, and day[...] turns positions into dates (Session 2's first lesson, reused). Visitors have no missing values in this stretch, so plain mean and sum are safe; the lesson's project uses revenue and needs the nan-aware versions.

Common wrong results: 224 "store averages" (axis=1); the ValueError in Step 2 (they divided by the day totals there); a share table whose rows do not add up to 1 (divided by table.sum(axis=0): each column then adds up to 1 instead, which is "share of the store's 224 days", a different question).

Lab 1.3-B: labs/module-02/l1_3-broadcasting/target_grid_starter.py → target_grid_solution.py

Reference output: current means [ 5703.83 6997.87 10144.21 6889.75], shapes (4,) (3,); (4,) with (3,) fails ("shape mismatch: objects cannot be broadcast to a single shape"); (4, 1) with (3,) gives (4, 3); (224, 4) with (4,) gives (224, 4); (4,) with (4, 1) gives (4, 4); targets (rounded) [[5875 5989 6274] [7208 7348 7698] [10449 10651 11159] [7096 7234 7579]]; targets above $7,500: 5 of 12; per store [0 1 3 1]; wrong shape (4, 4) with average size 1753.02; fixed errors [-196.17 197.87 -255.79 189.75] with average size 209.9.

The solution's key lines:

targets = current[:, np.newaxis] * (1 + growth)      # (4, 1) with (3,) -> (4, 3)
above = targets > 7500
print(above.sum(), above.sum(axis=1))                # all twelve; then one count per store
errors = actual - forecast.ravel()                   # (4,) with (4,) -> (4,)

Why: stores must run down the rows, so the four store means become a column; the three growth rates stay a row. In Step 4 the forecast arrives as a column, and a row minus a column is every actual minus every forecast: sixteen numbers whose average size is meaningless. Flattening the forecast gives four errors.

Common wrong results: per store [1 1 3] (that is axis=0: one count per scenario); a (3, 4) grid (the new axis was put on growth: legal, but rows are now scenarios, so axis=1 no longer means "per store"); 1753.02 left standing because the shape line was not read.

The Lesson Pages' Own Quick Quizzes

Each lesson page ends with a five-question Quick Quiz (three options each). Learners do them at home; these are the answers with the page's own explanation.

Lesson 1.2 · Vectorized Operations
  1. Question 1. What does this print? 
    q1 = np.array([3, 8, 5, 10])
print((q1 > 4).sum())
    Answer: A) 3. The comparison gives [False True True True]. In arithmetic True counts as 1, so the sum of a mask is the number of elements that passed the test.
  2. Question 2. revenue and promo are float arrays of the same length. Which line correctly counts sale days with revenue above 10,000?
    Answer: C) ((revenue > 10000) & (promo == 1)).sum(). Each comparison is wrapped in parentheses so it is evaluated first, the ampersand combines the two masks element by element, and the sum counts the True values.
  3. Question 3. What does this print? 
    q3 = np.array([[1, 2, 3],
               [4, 5, 6]])
print(q3.sum(axis=0))
    Answer: B) [5 7 9]. axis=0 collapses the rows, leaving one total per column: 1+4, 2+5, 3+6. The shape goes from (2, 3) to (3,).
  4. Question 4. What does this print? 
    q4 = np.array([-2, 5, -1, 3])
print(np.where(q4 > 0, q4, 0))
    Answer: C) [0 5 0 3]. np.where keeps the shape. Where the condition is true it takes the value from q4, and everywhere else it takes 0.
  5. Question 5. You run high = revenue[revenue > 15000] and then high[0] = 0. What happens to revenue?
    Answer: B) Nothing: selecting with a mask builds a new array, so high is a copy. Mask indexing gathers the chosen elements into a new array, unlike a slice. To change the original through a mask, assign in one step, with the mask in brackets on the left of the equals sign.
Lesson 1.3 · Broadcasting
  1. Question 1. An array of shape (5, 3) is added to an array of shape (3,). What is the result?
    Answer: B) An array of shape (5, 3). Lined up from the right, 3 meets 3, and the missing axis is treated as 1 and reused along the 5 rows. The three values are added to every row.
  2. Question 2. What does this print? 
    q2a = np.array([1, 2, 3])
q2b = np.array([[10], [20]])
print((q2a + q2b).shape)
    Answer: C) (2, 3). Shapes (3,) and (2, 1): from the right, 3 meets 1 and gives 3, then the missing axis meets 2 and gives 2. A row meeting a column makes a grid.
  3. Question 3. t has shape (7, 4). Which expression divides every row by that row's total?
    Answer: A) t / t.sum(axis=1, keepdims=True). axis=1 gives one total per row, and keepdims=True keeps them as a column of shape (7, 1), which is reused across the 4 columns.
  4. Question 4. actual has shape (100,) and predicted has shape (100, 1). What does actual - predicted give?
    Answer: A) An array of shape (100, 100), with no error. From the right, 100 meets 1, then a missing axis meets 100. Both are legal, so NumPy builds every actual minus every prediction: 10,000 numbers. Flatten one side first.
  5. Question 5. Which pair of shapes can not be broadcast together?
    Answer: C) (3, 4) and (3,). Lined up from the right, 4 meets 3. They are not equal and neither is 1, so it fails. The 3 would have to be a column of shape (3, 1).

Warm-up Answers

W1
Name the three rules that are true of every NumPy array and not of a Python list.
One type for the whole array (the dtype), a fixed size, and operations that act on every element at once.
W2
What does [1, 2, 3] * 2 give? What does np.array([1, 2, 3]) * 2 give?
[1, 2, 3, 1, 2, 3] (a list repeats) and [2 4 6] (an array does arithmetic).
W3
b = a[1:4], then b[0] = 0. What happened to a, and how do you prevent it?
a[1] is now 0, because a slice is a view. b = a[1:4].copy() makes an independent array.
W4
The mean of the revenue array printed nan. Why, and what did you use instead?
Six values are missing and arithmetic with a missing value gives nan. np.nanmean(revenue) skips them.
W5
t has shape (7, 4): days by stores. What does t[:, 2] select, and what is its shape?
Every row of column 2: one store's value on each of the seven days. Shape (7,).

Exit Ticket

E1
revenue and promo are parallel arrays. Write one line that counts the sale days (promo equal to 1) with revenue above 10,000.
((revenue > 10000) & (promo == 1)).sum(): &, parentheses around each comparison, and the sum of the mask counts.
E2
A table has shape (224, 4): days by stores. What is the shape of table.mean(axis=0), and what does each value mean?
(4,): one mean per store. The axis you name (the 224 days) is the one that disappears.
E3
You want every row of that table divided by its own row total. Write the expression, and say what goes wrong if you leave out the keyword.
table / table.sum(axis=1, keepdims=True). Without keepdims=True the totals have shape (224,); from the right, 4 meets 224 and NumPy raises "could not be broadcast together".
