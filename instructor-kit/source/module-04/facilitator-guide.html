Session 4: DataFrames and Loading Data

How to teach the session where the course moves from NumPy arrays to pandas tables. First learners meet the labeled column and the labeled table, learn to inspect, select, filter, change, sort and count, and see for themselves why chained assignment never works under copy-on-write. Then they learn to get data in properly from CSV, Excel and nested JSON with the right types, and to save results in a format that remembers them.

The #1 risk of Session 4: mistakes that raise no error

Most of today's damage is silent. Chained assignment prints a warning and changes nothing. == np.nan counts zero missing values. A spreadsheet loaded without skiprows gives 15 rows of nonsense and no complaint. A date left as text sorts and filters wrongly weeks later. Train one habit all session and say it every time: "Run it, then look: shape, dtypes, head()." The second risk is pace: 2.1 has more new vocabulary than any lesson so far. Protect .loc versus .iloc and the copy-on-write demonstration; everything else can be looked up.

Warm-up: Retrieval from Session 3

10 min
Five retrieval questions (no notes, 5 minutes)

Slide 3. Learners write answers on paper with notebooks closed, then compare with a neighbor for one minute before you take answers. Wrong answers are welcome: the point is the effort of recalling.

  1. You write rng = np.random.default_rng(42). What is rng, and what does the 42 do? Answer: A random number generator. The seed fixes where its sequence starts, so the same code run from the top gives the same numbers.
  2. Can rng.integers(1, 7, size=5) ever return a 7? Answer: No. The upper end is left out, so the values are 1 to 6 (a die).
  3. What does replace=False guarantee in rng.choice(skus, size=10, replace=False)? Answer: Ten distinct items: nothing is picked twice.
  4. For two 1-D arrays of length 3, what is the difference between a * b and a @ b? Answer: a * b is position by position and gives three numbers; a @ b is the dot product, one number: a weighted sum.
  5. A matrix of shape (726, 3) is multiplied with @ by a vector of shape (3,). What shape is the result, and what must match? Answer: (726,). The inner numbers must match (3 and 3): one dot product per row.

Three mistakes to expect
  • and / or between masks, or & without parentheses. Symptoms: ValueError: The truth value of a Series is ambiguous (for and) or the cryptic TypeError: Cannot perform 'rand_' with a dtyped [float64] array and scalar of type [bool] (for missing parentheses). Coach: "Read me the last line. How many True/False values is on each side of your and?" Then: "Put a pair of parentheses around each condition and tell me what changed." Do not type the fix for them.
  • Chained assignment: df[mask]["col"] = value. Symptom: a ChainedAssignmentError warning that is easy to miss, and a table that did not change. Coach: "Count the pairs of brackets before the equals sign. Which table did the first pair create? Where did it go?" The repair is always the same sentence: one .loc[rows, "col"] on the table you mean to change. Learners who read older tutorials will reach for .copy() after every filter; tell them it is no longer needed.
  • A position where a label was expected (and the reverse). Symptom: KeyError: 0 from by_sku.loc[0], or one row too many from .loc[0:3]. Coach: "Is 0 a label in this table or a position? Print df.index[:3] and decide." Point at the board drawing: .loc reads the label on the bin, .iloc counts bins from the left. Also expect KeyError: 'Price': names are case-sensitive, so have them print df.columns.tolist() and copy the name.

Mental model to say

A CSV says 2024-01-01, and it is only characters: nothing in the file says 'this is a date'. read_csv is an interpreter who makes a reasonable guess about each column. Three mistakes to expect
  • The file is not where Python is looking. Symptom: FileNotFoundError: [Errno 2] No such file or directory: 'orders.csv'. Coach: "Which folder is Python working in? Print Path.cwd(). Is there a data folder inside it?" This is almost always a notebook opened from the wrong folder, not a typo. In the labs the question does not arise (DATA finds the folder), so expect it in the lesson project instead.
  • Trusting a load that ran without error. Symptoms: Unnamed: 1 column names and 15 rows instead of 12 from the Excel sheet; .dt raising AttributeError: Can only use .dt accessor with datetimelike values because the date is still text; a numeric column that is str because of one n/a. Coach: "What did shape and dtypes say right after the load?" If they did not look, that is the fix. Make 'load, then look' a spoken rule today.
  • pd.read_json on a nested file, or flattening the wrong level. Symptom: ValueError: Mixing dicts with non-Series may lead to ambiguous ordering. or a DataFrame with whole dictionaries in its cells. Coach: "Print list(data). Which key holds the list of records? Is it the file itself or one level down?" Then json.load plus pd.json_normalize(data["sessions"]), and record_path only when they want one row per item of an inner list.

Checks for understanding
  1. Why does pandas not turn order_date into a date on its own? Answer: It does not guess dates, because guessing wrong is worse than not guessing. You say so with parse_dates.
  2. What is the difference between "Int64" and "int64"? Answer: Capital I is pandas's nullable integer and can hold <NA>; lowercase is NumPy's and cannot hold a missing value.

Wrap-up

10 min
Exit ticket (3 questions, on paper or sticky notes, 5 minutes)
  1. You run df[df["price"] > 100]["price"] = 0. What happens to df, and what should you write instead? Answer: Nothing happens to df (pandas warns with ChainedAssignmentError): the first brackets made a temporary copy. Write df.loc[df["price"] > 100, "price"] = 0.
  2. On a table with the default index, how many rows do df.loc[0:3] and df.iloc[0:3] return, and why are they different? Answer: 4 and 3. .loc slices by label and includes the end; .iloc slices by position and leaves out the stop.
  3. You save a table that has a date column to out.csv and to out.parquet. Read back with no options, which file gives the date back as a date, and why? Answer: The Parquet file. It stores each column's dtype with the data; a CSV is only text, so the date comes back as str unless you pass parse_dates again.
