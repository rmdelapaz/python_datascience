2.1 · DataFrames and Series: self-check

Q1
What does this print?
s = pd.Series([5, 6, 7], index=["x", "y", "z"])
t = pd.Series([1, 1], index=["z", "x"])
print((s + t).tolist())
A) [6, 7, 7]
B) [6.0, 7.0, nan]
C) [6.0, nan, 8.0]
D) A ValueError, because the lengths differ
Why: Series arithmetic aligns on labels: x gets 5 + 1, z gets 7 + 1, and y has no partner, so it is NaN. The NaN makes the whole result float.
A is wrong: That adds by position and treats the missing partner as nothing; pandas matches labels.
B is wrong: That adds by position (5 + 1, 6 + 1) and puts the gap last. The gap belongs to the label y, in the middle.
D is wrong: Two NumPy arrays of lengths 3 and 2 would raise an error. Two Series align and fill with NaN.
Q2
What does this print?
df = pd.DataFrame({"n": [10, 20, 30, 40]}, index=["a", "b", "c", "d"])
print(len(df.loc["a":"c"]), len(df.iloc[0:2]), df.iloc[-1, 0])
3 2 40
Why: A .loc slice includes its end label, so a, b, c are three rows. An .iloc slice leaves out the stop, so positions 0 and 1 are two rows. .iloc[-1, 0] is the last row, first column: 40.
Q3
In a table of 242 products, products.info() shows the line rating 234 non-null float64. What does that line tell you?
A) 8 products have no rating
B) There are 234 different ratings
C) The ratings are stored as text
D) 8 products have a rating of 0
Why: Non-Null Count is the number of values that are present. 242 rows minus 234 present leaves 8 missing ratings.
B is wrong: The number of distinct values comes from .nunique(), not from info().
C is wrong: The dtype on that line is float64: numbers. Text would say str.
D is wrong: A rating of 0 is a value and would be counted as non-null. Missing is not zero.
Q4
Which line correctly counts the products that are in the Tents category or cost less than $20?
A) (products["category"] == "Tents" | products["price"] < 20).sum()
B) (products["category"] == "Tents" or products["price"] < 20).sum()
C) products[("category" == "Tents") | ("price" < 20)].sum()
D) ((products["category"] == "Tents") | (products["price"] < 20)).sum()
Why: Each condition sits in its own parentheses, | combines them element by element, and .sum() of the mask counts the True rows.
A is wrong: Without parentheses | is evaluated before == and <, so Python tries "Tents" | products["price"] first and raises an error.
B is wrong: or wants a single True or False on each side; a Series is 242 of them (ValueError: ambiguous truth value).
C is wrong: It compares the text "category" with "Tents", not the column. The column must be written products["category"].
Q5
What does the last line print? (The second line also produces a warning.)
df = pd.DataFrame({"price": [10, 50, 90]})
df[df["price"] > 40]["price"] = 0
print(df["price"].tolist())
[10, 50, 90]
Why: Chained assignment. df[df["price"] > 40] creates a temporary table that behaves as a copy; the 0 is written into that and thrown away. df is unchanged and pandas warns with ChainedAssignmentError. The working form is df.loc[df["price"] > 40, "price"] = 0.
Q6
After top = products.sort_values("price", ascending=False), what is top.index[0]?
A) 0, because sorting renumbers the rows
B) The original row label of the most expensive product
C) The highest price
D) 241, the last position
Why: sort_values reorders the rows and their labels travel with them. The first row of top still carries the label it had in products (19 in the course data).
A is wrong: Rows are renumbered only if you add .reset_index(drop=True).
C is wrong: The index holds labels, not values. The highest price is top["price"].iloc[0].
D is wrong: 241 is the label of the last row of products; it has nothing to do with the sort.

2.1 · Predict, then run

P1
Labels travel with their values.
s = pd.Series([3, 1, 2], index=["c", "a", "b"])
print(s.sort_values().index.tolist(), s.iloc[0], s.loc["a"])
['a', 'b', 'c'] 3 1
Why: Sorting by value puts 1, 2, 3 in order, and their labels a, b, c come along. s itself is unchanged (sort_values returned a new Series), so .iloc[0] is still the first value typed, 3, and .loc["a"] is the value labeled a, 1.
P2
A piece of a table, changed.
df = pd.DataFrame({"x": [1, 2, 3, 4]})
part = df[df["x"] > 2]
part["x"] = 0
print(df["x"].sum(), part["x"].sum(), part.index.tolist())
10 0 [2, 3]
Why: part is an independent table from the moment it is created (copy-on-write), so setting its column to 0 leaves df at 1 + 2 + 3 + 4 = 10. part kept the row labels of the rows it came from: 2 and 3.
P3
Looking for missing values.
r = pd.Series([4.5, np.nan, 3.0])
print((r == np.nan).sum(), r.isna().sum(), r.mean())
0 1 3.75
Why: == np.nan is False everywhere because NaN is not equal to anything, so it counts 0. .isna() finds the one missing value. .mean() skips missing values: (4.5 + 3.0) / 2 = 3.75.

Question: Which were the five biggest store-days by revenue, were they promo days, and how often does a store pass $15,000 in a day?

How the solution works: sort_values("revenue", ascending=False) with a list of four column names gives the top-five table (nlargest(5, "revenue") is equally good). labs/module-04/l2_1-dataframes-series/recommend_groups_solution.py

Question: Split the 0-to-10 'would you recommend us?' answers into promoters, passives and detractors, and compare Asheville shoppers with everyone.

How the solution works: The column starts as "no answer" and three .loc lines overwrite it. A comparison with NaN is False, so the 54 blanks are never overwritten. The score is the difference of two mask means among the rows that answered. The solution wraps that in a small function so it can be reused for the Asheville piece; learners may simply repeat the three lines.

2.1 Q1
What does this print?
qa = pd.Series([10, 20, 30], index=["a", "b", "c"])
qb = pd.Series([1, 2, 3], index=["b", "c", "d"])
print((qa + qb).tolist())
A) [11, 22, 33]
B) [nan, 21.0, 32.0, nan]
C) [10.0, 21.0, 32.0, 3.0]
Why: Series arithmetic aligns on labels. Only b and c exist in both, giving 21 and 32. Labels a and d exist in one Series only, so the result there is NaN, and the NaNs make the whole result float.
2.1 Q2
Which expression returns a DataFrame rather than a Series?
A) products[["price"]]
B) products["price"]
C) products.iloc[0]
Why: A list of column names inside the brackets always returns a DataFrame, even when the list holds a single name.
2.1 Q3
What does this print?
qdf = pd.DataFrame({"n": [1, 2, 3, 4, 5]}, index=[10, 20, 30, 40, 50])
print(len(qdf.loc[10:30]), len(qdf.iloc[0:2]))
A) 2 2
B) 3 3
C) 3 2
Why: loc slices by label and includes both ends: labels 10, 20 and 30 make three rows. iloc slices by position and excludes the stop: positions 0 and 1 make two rows.
2.1 Q4
What does this print?
qorig = pd.DataFrame({"x": [1, 2, 3]})
qpart = qorig[qorig["x"] > 1]
qpart["x"] = 0
print(qorig["x"].tolist())
A) [1, 2, 3]
B) [1, 0, 0]
C) [0, 0, 0]
Why: Under copy-on-write qpart behaves as an independent copy from the moment it is created, so writing to it changes qpart only. qorig keeps 1, 2, 3.
2.1 Q5
You want the products that cost more than $100 and are out of stock. Which line is correct?
A) products[products["price"] > 100 and products["stock_status"] == "out_of_stock"]
B) products[products["price"] > 100 & products["stock_status"] == "out_of_stock"]
C) products[(products["price"] > 100) & (products["stock_status"] == "out_of_stock")]
Why: Each condition sits in its own parentheses and they are joined with the element-by-element and operator, so the result is one mask with a True or False per row.

2.2 · Loading Data: self-check

Q7
What does this print?
f = io.StringIO("id,qty\n1,4\n2,\n3,6\n")
print(pd.read_csv(f, dtype={"qty": "Int64"})["qty"].tolist())
A) [4.0, nan, 6.0]
B) [4, <NA>, 6]
C) [4, 0, 6]
D) A ValueError: Integer column has NA values
Why: "Int64" with a capital I is the nullable integer: the whole numbers stay whole and the gap is shown as <NA>.
A is wrong: That is what you get with no dtype: the gap forces the column to float64.
C is wrong: pandas never invents a 0 for a missing value.
D is wrong: That error comes from lowercase "int64", the NumPy type, which cannot hold a missing value.
Q8
A text export starts with two lines of notes, then the header store;week;revenue, then rows such as Boise;2024-W01;55.400,22. Which call loads revenue as a number?
A) pd.read_csv(f, sep=";", skiprows=2, decimal=",", thousands=".")
B) pd.read_csv(f, sep=";", header=None)
C) pd.read_csv(f, skiprows=2, decimal=",")
D) pd.read_csv(f, sep=";", skiprows=3, decimal=",", thousands=".")
Why: Four facts in the text, four options: semicolons, two note lines above the header, a decimal comma and a dot for thousands.
B is wrong: header=None says the file has no header at all, so the notes and the header row land in the data and every column is text.
C is wrong: Without sep=";" pandas splits on commas, so each line is cut at the decimal comma.
D is wrong: skiprows=3 skips the header line too, so the first data row becomes the column names.
Q9
What does this print?
recs = [{"id": 1, "tags": [{"t": "a"}, {"t": "b"}]},
        {"id": 2, "tags": [{"t": "c"}]}]
print(pd.json_normalize(recs, record_path="tags", meta=["id"]).shape)
(3, 2)
Why: record_path="tags" makes one row per item of each inner list: 2 + 1 = 3 rows. The columns are t (from the items) and id (copied from the parent by meta).
Q10
You load orders.csv with no options. orders["order_date"].dt.month raises AttributeError: Can only use .dt accessor with datetimelike values. What is the right fix?
A) Add index_col="order_date" to the load
B) Convert the column with .astype("int64")
C) Add encoding="latin-1" to the load
D) Load with parse_dates=["order_date"], or convert with pd.to_datetime()
Why: The column is str: pandas does not guess dates. parse_dates converts it while loading; pd.to_datetime converts it afterward. Then .dt works.
A is wrong: That moves the column into the index but leaves it as text.
B is wrong: A date such as 2024-01-01 is not a whole number; the conversion fails.
C is wrong: The encoding is about characters, not types. The file already reads correctly.
Q11
What does this print?
df = pd.DataFrame({"a": [1, 2]})
df.to_csv("q11.csv")
print(pd.read_csv("q11.csv").columns.tolist())
['Unnamed: 0', 'a']
Why: Without index=False, to_csv writes the index as an extra first column with no name. Read back, it becomes a column called Unnamed: 0.
Q12
A CSV file is larger than your computer's memory. You need the sum of one of its columns. Which approach is the right one?
A) Load the whole file, then delete the columns you do not need
B) Read the first 1,000 rows with nrows and multiply up
C) Read it with usecols and chunksize, keeping a running total
D) Open it in a spreadsheet program and save it as Excel first
Why: usecols loads only the column you need and chunksize hands you one piece at a time, so only one chunk is ever in memory. Sums add up across chunks exactly.
A is wrong: The load itself is what fails: the file does not fit.
B is wrong: That is an estimate from the first rows, not the sum, and the first rows are rarely typical.
D is wrong: A spreadsheet program holds the file in memory too, and has a row limit.

2.2 · Predict, then run

P1
A code that looks like a number.
text = "sku,zip\nA1,02134\nB2,97701\n"
a = pd.read_csv(io.StringIO(text))
b = pd.read_csv(io.StringIO(text), dtype={"zip": "str"})
print(a["zip"].tolist(), b["zip"].tolist())
[2134, 97701] ['02134', '97701']
Why: Read as a number, 02134 loses its leading zero for good. dtype={"zip": "str"} keeps it as text. The test from the lesson: would it make sense to add two of them? If not, it is text.
P2
A key that is not there.
recs = [{"id": 1, "geo": {"city": "Bend"}}, {"id": 2}]
flat = pd.json_normalize(recs)
print(flat.columns.tolist(), flat["geo.city"].isna().sum())
['id', 'geo.city'] 1
Why: The inner dictionary becomes a dotted column, geo.city. The second record has no geo key, so its cell is NaN: one missing value. Nothing fails and no record is dropped.
P3
A title above the header.
text = "Sales report,draft\nday,sales\nMon,10\nTue,12\n"
a = pd.read_csv(io.StringIO(text))
b = pd.read_csv(io.StringIO(text), skiprows=1)
print(a.columns.tolist(), a.shape, b.columns.tolist(), b["sales"].sum())
['Sales report', 'draft'] (3, 2) ['day', 'sales'] 22
Why: Without skiprows, pandas takes the first line as the header, so the columns are called Sales report and draft, the real header day,sales lands in the data as a row (three rows instead of two), and no error is raised. Skipping the one title line puts day,sales in the header position, and sales is a number column that adds up to 22.

labs/module-04/l2_2-loading-data/product_pages_solution.py

Question: In November 2025, which product pages were viewed most, and do visitors stay longer on product pages than on other pages?

How the solution works: record_path="pages" makes one row per page view (9,348) and meta copies session_id and converted onto each. Two types need repair: at is text, and converted arrives through meta as dtype object, so it is cast with .astype(bool). The second row of this small file has an empty amount. What does the code print?
qtext = io.StringIO("id,amount\n1,10\n2,\n3,30\n")

2.2 Q2
A worksheet has a title in row 1, a note in row 2, a blank row 3, and the column names in row 4. Which call reads it correctly?
A) pd.read_excel(path, nrows=4)
B) pd.read_excel(path, header=4)
C) pd.read_excel(path, skiprows=3)
Why: Skipping the first three rows makes row 4 the first row pandas sees, and it uses that row as the header. header=3 would do the same.
2.2 Q3
In a list of JSON records, some records have a utm dictionary and others have no utm key at all. What does pd.json_normalize(records) do with the records that lack it?
A) Keeps them, with NaN in the utm.* columns
B) Drops those records from the result
C) Raises a KeyError for the first record without the key
Why: json_normalize builds the columns from every key it finds in any record and fills NaN where a record does not have that key. In this lesson 916 sessions had NaN in the utm columns.
2.2 Q4
You save a table with df.to_csv("out.csv"). A colleague reads it and finds an extra first column named Unnamed: 0. What happened?
A) The file's header row was written twice
B) The index was written as a column; index=False prevents it
C) The file was saved in the wrong encoding
Why: to_csv writes the index as the first column unless told not to, and the default index has no name. Reading the file back turns it into a column called Unnamed: 0. Write with index=False.
2.2 Q5
A table with a datetime column and a category column is written to CSV and to Parquet. Read back with no options, only the Parquet version still has those dtypes. Why?
A) Parquet compresses the data, and CSV does not
B) read_parquet is better at guessing types from the values
C) A Parquet file stores each column's type with the data; a CSV is only text
Why: A Parquet file stores a schema, the type of every column, alongside the values, so nothing has to be guessed. A CSV file is plain text and every type must be inferred or supplied again on each load.

Warm-up Answers

  1. You write rng = np.random.default_rng(42). What is rng, and what does the 42 do? Answer: A random number generator. The seed fixes where its sequence starts, so the same code run from the top gives the same numbers.
  2. Can rng.integers(1, 7, size=5) ever return a 7? Answer: No. The upper end is left out, so the values are 1 to 6 (a die).
  3. What does replace=False guarantee in rng.choice(skus, size=10, replace=False)? Answer: Ten distinct items: nothing is picked twice.
  4. For two 1-D arrays of length 3, what is the difference between a * b and a @ b? Answer: a * b is position by position and gives three numbers; a @ b is the dot product, one number: a weighted sum.
  5. A matrix of shape (726, 3) is multiplied with @ by a vector of shape (3,). What shape is the result, and what must match? Answer: (726,). The inner numbers must match (3 and 3): one dot product per row.

Exit Ticket Answers

  1. You run df[df["price"] > 100]["price"] = 0. What happens to df, and what should you write instead? Answer: Nothing happens to df (pandas warns with ChainedAssignmentError): the first brackets made a temporary copy. Write df.loc[df["price"] > 100, "price"] = 0.
  2. On a table with the default index, how many rows do df.loc[0:3] and df.iloc[0:3] return, and why are they different? Answer: 4 and 3. .loc slices by label and includes the end; .iloc slices by position and leaves out the stop.
  3. You save a table that has a date column to out.csv and to out.parquet. Read back with no options, which file gives the date back as a date, and why? Answer: The Parquet file. It stores each column's dtype with the data; a CSV is only text, so the date comes back as str unless you pass parse_dates again.

Common Wrong Answers and What They Reveal

  • Q2 answered 2 2 40 or 3 3 40. The learner has one slicing rule, not two. Send them back to the one-line experiment: .loc includes the end label, .iloc leaves out the stop position.
  • Q5 answered [10, 0, 0]. They believe a filtered piece is a window onto the table (the NumPy view model from Lesson 1.1). Re-run the tents demonstration and have them say the copy-on-write rule in their own words.
  • Q4 answered A (no parentheses). They know to use | but not that it binds tighter than == and <. Have them add the parentheses and explain what Python tried to compute first.
  • Exit ticket 1 answered 'it sets them to 0'. The warning was not noticed. Show the cell again in a notebook and ask them to find the word ChainedAssignmentError.
  • Q7 answered A ([4.0, nan, 6.0]). They have learned 'gaps make floats' but not that Int64 is the cure. That is half right; point at the capital I.
  • Q9 answered (2, 2). They expect one row per record. Draw the tree: record_path makes one row per item of the inner list, so 2 + 1 = 3 rows.
  • Q11 answered ['a']. They do not yet see the index as something that gets written. Have them open the CSV in a text editor and look at the first column.
  • Lab till_export: 29 rows and a text revenue. The header was skipped or counted as a note. Ask which line holds the column names, then recount skiprows.
  • Lab recommend_groups: a different score for Asheville. Usually the denominator: all 202 responses instead of the 197 who answered. Ask what notna() is for.
