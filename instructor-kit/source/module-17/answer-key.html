6.2 · Parsing HTML with Beautiful Soup: Self-check

Q1
Which call gives you None (not an empty list, not an exception) when nothing on the page matches?
A) soup.select("p.sale-price")
B) soup.find_all("p", class_="sale-price")
C) soup.select_one("p.sale-price")
D) card["data-sale-price"] on a card without that attribute
Why: select_one() and find() return one element or None. Calling a method on that None is what produces AttributeError: 'NoneType' object has no attribute ....
A is wrong: select() always returns a list; with no match it is an empty list.
B is wrong: find_all() also returns a list, empty when nothing matches.
D is wrong: Square brackets on a missing attribute raise KeyError. Use .get() to receive None instead.
Q2
What does this print?
soup = BeautifulSoup('<ul><li class="card" data-sku="A1"><b>Tent</b></li>'
                     '<li class="card"><b>Stove</b></li></ul>', "html.parser")
print([li.get("data-sku") for li in soup.select("li.card")])
['A1', None]
Why: Both items match li.card. The first has a data-sku; the second has none, and .get() returns None instead of raising KeyError, the safe way to read an optional attribute.
Q3
Your loop follows nav.pagination a.next from page to page. How does it know it has reached the last page?
A) On the last page "Next" is a plain span, so select_one("nav.pagination a.next") returns None
B) The server answers the last page with a 404
C) The last page has no product cards
D) The loop counts to 13, the number of pages
Why: The site marks the end itself: the last page has span.next.disabled instead of a link. The loop needs no page count, and max_pages stays as a seat belt.
B is wrong: Every catalog page answers 200. Probing for a 404 sends one useless request and treats an error as normal.
C is wrong: The last page has 2 cards. Stopping on an empty page would need one extra request past the end.
D is wrong: A typed count is exactly what breaks when the shop adds products. Let the site say where the end is.
Q4
What does this print?
soup = BeautifulSoup('<p class="stock low-stock">Low stock</p>', "html.parser")
print(soup.p["class"], soup.p["class"][1].replace("-", "_"))
A) ['stock low-stock'] low-stock
B) stock low_stock
C) ['stock', 'low-stock'] low-stock
D) ['stock', 'low-stock'] low_stock
Why: Beautiful Soup splits class into a list because an element can carry several classes. Element 1 is low-stock, and .replace("-", "_") turns it into low_stock.
A is wrong: class is never one string with a space in it: it is a list of class names.
B is wrong: The first value printed is the whole list, not its first element.
C is wrong: The replace call changed the hyphen into an underscore.
Q5
Lesson 6.2 fetches price-list.html with requests and passes io.BytesIO(resp.content) to pd.read_html(), instead of giving read_html the URL. Why?
A) read_html cannot read a URL
B) So that your User-Agent, your timeout and raise_for_status() apply, and pandas reads the exact bytes you checked
C) Bytes make read_html return numbers instead of text
D) BytesIO removes the second table
Why: Fetching yourself keeps the polite habits of Session 16 (identify yourself, time out, check the status) and lets you save or reuse the bytes.
A is wrong: It can, but then you have no say over the User-Agent, the timeout or what happens on an error.
C is wrong: read_html reads what a person sees either way: Price still arrives as text such as $299.95.
D is wrong: Both tables come back; you choose one with attrs={"id": ...}.
Q6
What does this print?
html = ('<table id="t"><tr><th>City</th><th>Price</th></tr>'
        '<tr><td>Bend</td><td>$1,299.00</td></tr></table>')
t = pd.read_html(io.StringIO(html), attrs={"id": "t"})[0]
print(t["Price"].dtype, t["Price"].str.replace("[$,]", "", regex=True).astype(float)[0])
str 1299.0
Why: read_html reads the visible text, so $1,299.00 arrives as a string. Removing $ and , with a regular-expression replace and converting with astype(float) gives 1299.0.

6.3 · Dynamic Pages with Selenium: Self-check

Q7
requests gets the Search page and finds 0 results in #search-results, while the browser shows 24. What should you try first?
A) Drive a headless browser with time.sleep(5) after get()
B) Find the data file the page loads (Network tab, or read its script) and, if you may, request it directly
C) Send a browser's User-Agent so the server sends the full page
D) Use pd.read_html on the page instead
Why: The page's own script fills the list from a data file (products.json). One request for the file is faster, lighter for the server and sturdier than any browser automation.
A is wrong: A browser is the last resort, and a fixed sleep is always too short or too long.
C is wrong: The server sent the same HTML it sends everyone; the list is empty until JavaScript runs. Disguising your script also breaks the ground rules.
D is wrong: There is no table in the HTML that requests received, and the results are not a table anyway.
Q8
What does this print?
print(urlencode({"q": "", "category": "Snow", "max_price": "", "in_stock": 1}))
q=&category=Snow&max_price=&in_stock=1
Why: urlencode writes every pair, empty ones included, in dictionary order, joined by &. This is the exact query string the shop's search form sends when the text boxes are left empty.
Q9
Which line waits correctly for the deals status line to exist?
A) time.sleep(3)
B) WebDriverWait(driver, 10).until(EC.presence_of_element_located(By.ID, "deal-status"))
C) WebDriverWait(driver, 10).until(EC.presence_of_element_located((By.ID, "deal-status")))
D) driver.find_element(By.ID, "deal-status")
Why: An explicit wait with the locator as ONE tuple: (By.ID, "deal-status"). It continues the moment the element exists and raises TimeoutException after 10 seconds if it never does.
A is wrong: A fixed sleep is too short on a slow day and wasted time on a fast one.
B is wrong: The inner parentheses are missing: the condition receives two arguments instead of one locator tuple, and fails with a TypeError.
D is wrong: That looks once, immediately, and raises NoSuchElementException if the script has not finished.
Q10
After clicking Submit on the GET search form, the demo waits twice: first EC.url_contains("category=Packs"), then for #search-results[data-loaded="true"]. Why not only the second wait?
A) The second condition is slower
B) url_contains is the only wait that raises on failure
C) The form submits twice
D) The OLD page's results are already marked loaded, so the second wait alone could pass instantly, before the new page arrives
Why: Submitting loads a new page. Until it arrives, the old page still satisfies the results condition. Waiting for the address first guarantees you are looking at the new page.
A is wrong: Speed is not the issue; correctness is.
B is wrong: Every wait.until raises TimeoutException when its limit passes.
C is wrong: One click, one new page.
Q11
You stored status = driver.find_element(By.ID, "deal-status"), called driver.refresh(), and now status.text raises StaleElementReferenceException. What happened?
A) The handle pointed at an element in the page that was replaced; find the element again after anything changes the page
B) The browser crashed and must be restarted
C) The element's text was empty
D) The wait limit was too short
Why: A WebElement is a handle on one element in one loaded page. Store the data you read, not the element.
B is wrong: The browser is fine; only the old handle is dead.
C is wrong: An empty text is just "", not an exception.
D is wrong: No wait is involved: the element you hold no longer exists.
Q12
What is in driver.page_source after the deals have loaded and Load more was clicked twice?
A) The HTML exactly as the server sent it, with an empty deal list
B) Only the 24 deal elements, without the rest of the page
C) The JSON from deals.json
D) The page's HTML as it is now, after its scripts ran: all 24 deals are in it
Why: page_source is the current document, which is why Beautiful Soup finds the deals in it while the soup from requests found none.
A is wrong: That is what requests receives.
B is wrong: It is the whole document: head, banner, navigation and all.
C is wrong: The page fetched that file, but page_source is HTML, not the data file.

Warm-up and Exit Ticket Answers

Warm-up (retrieval from Session 16)
  1. In a pymongo query, what does {"utm": None} match? Answer: Documents where utm is null and documents where it is missing. $exists tells the two apart.
  2. Which aggregation stage does what pandas explode does? Answer: $unwind: one document per element of a list.
  3. requests.get() comes back with status 404. Has an exception been raised? Answer: No. You hold a normal response with .ok False; r.raise_for_status() makes it loud.
  4. Why does every request in this course carry timeout=? Answer: Without it requests waits forever for a server that has gone quiet.
  5. You see â˜… where a star should be. What happened, and what is one fix? Answer: UTF-8 bytes were decoded with the wrong table (no charset sent). Set r.encoding = "utf-8", or hand r.content to a parser that reads the page's <meta charset>.
Exit ticket
  1. Which Beautiful Soup method returns None when nothing matches, and which returns an empty list? Answer: select_one() (and find()) return None; select() (and find_all()) return a list, empty if nothing matches.
  2. Why is WebDriverWait(...).until(...) better than time.sleep(5)? Answer: It continues the moment the condition is true and raises a clear TimeoutException if it never is. A sleep is always too short or too long.
  3. Before you start a browser for a page that JavaScript fills in, what do you look for first? Answer: The data file or API the page loads (Network tab, or the page's script). If you may request it, do that instead.

What wrong answers reveal. "select returns None": mixing the two families; redo predict item 1. "Sleep is fine if it is long enough": the cost has not landed; ask what a thousand pages times five seconds is. "Use Selenium" for question 3: the order of the routes needs another pass at the start of Session 18.
