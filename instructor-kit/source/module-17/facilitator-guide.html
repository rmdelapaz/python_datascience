Session 17: Scraping Static and Dynamic Pages

How to teach the scraping session. The first half turns static HTML into a tidy, checked DataFrame with Beautiful Soup: labels over positions, one block one dictionary, missing values on purpose, pagination without counting. The second half meets pages that JavaScript fills in, teaches learners to look for the data file first, and drives headless Chrome with explicit waits when nothing else will do.

2 lessons 3 hrs session Lessons 6.2–6.3 Session 17 of 21

How to Use This Guide

  • Session 17 is the scraping session. Before the break learners turn static HTML into a checked DataFrame with Beautiful Soup (Lesson 6.2); after it they meet pages that JavaScript fills in, learn to look for the data file first, and drive headless Chrome with Selenium when they must (Lesson 6.3).
  • Same rhythm as every session: frame → live demo (you type, they follow) → guided lab → start the lesson project. Finishing the projects, the exercises, quizzes and journals is homework.
  • Every code block below was run for this guide: Beautiful Soup 4.15, pandas 3.0.6, requests 2.34.2 and Selenium 4.51 with headless Chromium, against a local copy of the practice shop that sends the course website's headers. The output is real; on the public site only the addresses you see are different, and they are shown as the public ones.
  • The single most useful moment in the first half is a crash: parse_card() works on the first cards and raises KeyError: 'data-rating' on the Packs page. Let it happen live. The most useful idea in the second half is the order of the routes: data file first, browser last.
  • Labs live in labs/module-17/. The Selenium labs fall back to saved finished pages when Chrome cannot start, so nobody is left without a lab.
The risk in Session 17: the browser as a hammer

Selenium is exciting, and learners who have just watched it click buttons will want to use it for everything, with time.sleep() sprinkled in until it works. Both habits are expensive. Keep two sentences on the board all afternoon: "Is the data in the HTML? Is it in a file the page loads? Only then a browser." and "Never sleep: wait for something by name."

Warm-up: Retrieval from Session 16

10 min

Five questions on the projector, answered on paper, notes closed (4 minutes), then aloud (3 minutes).

  1. In a pymongo query, what does {"utm": None} match? Answer: Documents where utm is null and documents where it is missing. $exists tells the two apart.
  2. Which aggregation stage does what pandas explode does? Answer: $unwind: one document per element of a list.
  3. requests.get() comes back with status 404. Has an exception been raised? Answer: No. You hold a normal response with .ok False; r.raise_for_status() makes it loud.
  4. Why does every request in this course carry timeout=? Answer: Without it requests waits forever for a server that has gone quiet.
  5. You see â˜… where a star should be. What happened, and what is one fix? Answer: UTF-8 bytes were decoded with the wrong table (no charset sent). Set r.encoding = "utf-8", or hand r.content to a parser that reads the page's <meta charset>.

Ground Rules Opener (2 minutes)

0:10

The Six Ground Rules for Module 6

2 min

Every Module 6 session opens here. Six learners read one rule each, aloud. Add one sentence for today: "A browser is a heavier guest than requests: it downloads every script, style and image. That is one more reason to reach for it last."

  1. Read robots.txt and obey it. It is the owner's published request to programs: where they may go and how fast.
  2. Read the terms of use. If they forbid automated collection, the answer is no, however easy the code would be.
  3. Prefer an API or a download when one exists. It is the front door.
  4. Go slowly and say who you are. Pause between requests; send a User-Agent with a way to contact you.
  5. Never go around a login, a paywall or a block. If you are asked to stop, stop.
  6. Do not collect personal data. Names, emails, profiles and photos of real people are protected by law in many places.

    def scrape(start_url, max_pages=50):
    """Follow 'next' links from start_url. Returns (rows, pages_fetched)."""
    rows, url, pages = [], start_url, 0
    while url and pages < max_pages:
        soup = get_soup(url)
        rows.extend(parse_card(c) for c in soup.select("li.product-card"))
        pages += 1
        nxt = soup.select_one("nav.pagination a.next")
        url = urljoin(url, nxt["href"]) if nxt else None
        time.sleep(DELAY)
    return rows, pages

Three mistakes to expect
  • AttributeError: 'NoneType' object has no attribute 'get_text'. The selector found nothing (usually a typo in a class name, or a class that the card does not have). Coach: "How many does len(soup.select(your_selector)) find? Now Inspect the page: what is the class really called?"
  • A list treated as one element, soup.select("p.price").get_text(). Beautiful Soup's own message says "You're probably treating a list of elements like a single element". Coach: "Do you want one, or all of them? One: select_one. All: a loop."
  • KeyError on an optional attribute, "fixed" with try/except: pass. That hides the product. Coach: "What should a missing rating MEAN in your table?" Then .get() and None. Keep square brackets for fields that must exist (SKU, price) so those crash loudly.

Also common: class= instead of class_= (a SyntaxError), and requesting a relative href (MissingSchema: use urljoin).

Mental model to say

"A static page arrives like a finished bookcase: what comes off the truck is what you see. A dynamic page arrives flat-packed: a nearly empty frame (the HTML), a bag of parts to be fetched (data files), and an instruction sheet (JavaScript). Your browser does the assembly after delivery. requests is a delivery driver, not a carpenter: it hands you the box exactly as shipped and never opens the instructions."

Three mistakes to expect
  • time.sleep() to make it work. It passes in class and fails at home on a slow connection. Coach: "What exactly are you waiting for? Name it, and wait for that."
  • Missing the inner parentheses in EC.presence_of_element_located((By.ID, "x")). The error is a TypeError about arguments. Coach: point at the board: the locator is ONE tuple.
  • Orphaned browsers. A crash before quit() leaves Chrome running; after a few runs the laptop is slow. Coach: "Where is your finally?" On Windows, Task Manager shows them; on macOS and Linux, Activity Monitor or ps.

Also common: NoSuchElementException right after get() (not yet: wait), a TimeoutException caused by a selector typo (give every wait a message=), StaleElementReferenceException after a reload, and old tutorials' find_element_by_id (removed in Selenium 4).

Exit ticket (3 questions, on a sticky note; answers)
  1. Which Beautiful Soup method returns None when nothing matches, and which returns an empty list? Answer: select_one() (and find()) return None; select() (and find_all()) return a list, empty if nothing matches.
  2. Why is WebDriverWait(...).until(...) better than time.sleep(5)? Answer: It continues the moment the condition is true and raises a clear TimeoutException if it never is. A sleep is always too short or too long.
  3. Before you start a browser for a page that JavaScript fills in, what do you look for first? Answer: The data file or API the page loads (Network tab, or the page's script). If you may request it, do that instead.
