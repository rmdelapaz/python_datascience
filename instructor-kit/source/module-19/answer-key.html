7.1 · Statistical Graphics with Seaborn: self-check

Q1
Which of these is a figure-level seaborn function?
A) sns.histplot
B) sns.boxplot
C) sns.displot
D) sns.heatmap
Why: displot creates its own figure, can facet with col= and row=, and returns a FacetGrid. The other two figure-level functions are relplot and catplot.
A is wrong: histplot is axes-level: it takes ax= and returns an Axes. It is what displot calls for you.
B is wrong: boxplot is axes-level; its figure-level front door is catplot(kind="box").
D is wrong: heatmap draws on one Axes and accepts ax=.
Q2
What does this print?
ax = sns.histplot(data=sales, x="revenue")
print(type(ax).__name__)
A) Axes
B) FacetGrid
C) Figure
D) Histogram
Why: An axes-level function returns the Matplotlib Axes it drew on, so every Module 3 method (set_title, set_xlabel, ...) works on the result.
B is wrong: A FacetGrid comes back from the figure-level functions (displot, relplot, catplot).
C is wrong: The Figure is one level up: ax.figure.
D is wrong: There is no such class; seaborn draws with ordinary Matplotlib artists.
Q3
What does this print?
g = sns.relplot(data=sales, x="visitors", y="revenue",
                col="store", col_wrap=2, height=2)
print(g.axes.shape)
(4,)
Why: Four stores make four panels. With col_wrap the FacetGrid keeps its Axes in a flat array, so the shape is (4,), not (2, 2). Loop over it with g.axes.flat.
Q4
sales has about 60 rows for each store and month. What does sns.lineplot(data=sales, x="month", y="revenue", hue="store", errorbar=None) draw?
A) A zigzag through every daily row, in file order
B) One line per store through the monthly means, with no band
C) One line per store through the monthly totals
D) Nothing: it raises an error because x has repeated values
Why: lineplot aggregates rows that share an x value. The default estimator is the mean, and errorbar=None only removes the shaded band.
A is wrong: That is what estimator=None would do.
C is wrong: The default estimator is the mean. For totals, pass estimator="sum", or better, sum with groupby first and plot that table.
D is wrong: Repeated x values are exactly the case lineplot is built for.
Q5
A chart shows the mean staff rating (1 to 5) for four stores, about 200 answers each. Every bar runs from roughly 3.2 to 5.0. What do the bars most likely show?
A) A 95% confidence interval for each mean
B) One standard error either side of each mean
C) The lowest and highest rating given
D) One standard deviation either side of each mean
Why: Individual ratings vary by about one point, so mean plus or minus one standard deviation spans almost two points. That is spread of the data.
A is wrong: With 200 answers the interval for a mean is only about 0.1 to 0.15 either side: far shorter.
B is wrong: A standard error here is about 0.06: the bar would be barely visible.
C is wrong: Ratings run from 1 to 5, so a min-to-max bar would start at 1.
Q6
What does this print? (Two lists.)
t = pd.DataFrame({"size": ["M", "S", "L", "S"], "n": [3, 1, 2, 5]})
fig, ax = plt.subplots()
sns.barplot(data=t, x="size", y="n", errorbar=None, ax=ax)
print([lab.get_text() for lab in ax.get_xticklabels()],
      [float(b.get_height()) for b in ax.patches])
['M', 'S', 'L'] [3.0, 3.0, 2.0]
Why: Two lessons in one line. Categories are drawn in the order they first appear (M, S, L), not sorted: pass order= when order matters. And barplot aggregates: the two S rows (1 and 5) become one bar at their mean, 3.0.

7.1 · Predict, then run

P1
Prints:
g = sns.catplot(data=sales, x="store", y="visitors", col="year", kind="bar", height=2.5)
print(type(g).__name__, g.axes.shape)
FacetGrid (1, 2)
Why: Two years make two panels in one row. A figure-level function returns a FacetGrid, and without col_wrap its Axes sit in a 2-D array: one row, two columns.
P2
Prints:
print(sales.groupby("store")["revenue"].agg(["std", "sem"]).round(0))
              std    sem
store                   
Asheville  2064.0   77.0
Bend       2546.0   95.0
Boise      3715.0  138.0
Flagstaff  2686.0  100.0
Why: The standard deviation (spread of single days) is about 27 times the standard error (uncertainty of the mean), because each store has about 725 days and the square root of 725 is about 27. That ratio is why errorbar="sd" bars are so much longer than errorbar="se" bars.

7.1 · The lesson page's own quiz

  1. B. scatterplot is axes-level: it accepts ax= and draws on the Axes you give it. relplot would ignore ax with a warning.
  2. C. lineplot aggregates rows that share an x: the line is the mean and the band a bootstrapped 95% confidence interval for it.
  3. A. A figure-level function returns a FacetGrid; row="year" gives 2 rows and col="store" 4 columns: (2, 4).
  4. B. sd bars show day-to-day spread; ci bars show uncertainty in the mean, which is tiny with 700 days.
  5. A. Text categories are drawn in first-seen order; order= (or an ordered categorical) sets the order you mean.

7.2 · Interactive Charts with Plotly: self-check

Q7
You run fig = px.line(monthly, x="month_start", y="revenue", color="store") in a script and nothing appears. Why?
A) The call only builds a Figure object; it is displayed when you call fig.show() (or write it to a file)
B) px.line needs kind="line" before it draws
C) Plotly needs an account before it can display a chart
D) monthly has more than one row per month, so Plotly refuses to draw
Why: Python builds a description (traces plus layout). Drawing happens in a browser, when you show the figure or open the HTML file you wrote.
B is wrong: kind= belongs to seaborn's figure-level functions.
C is wrong: The plotly library is open source and runs entirely on your machine.
D is wrong: Four stores with 24 months each is what color="store" handles: four traces.
Q8
sales has four stores and promo_day is 0 or 1. What does this print?
fig = px.scatter(sales, x="visitors", y="revenue",
                 color="store", facet_col="promo_day")
print(len(fig.data))
8
Why: Express makes one trace per combination of color and facet: 4 stores times 2 panels. Knowing how many traces to expect is the quickest check that a figure is what you meant.
Q9
Which hover_data entry shows revenue as $27,677 in the hover label?
A) "revenue": True
B) "revenue": "$%d"
C) "revenue": ":$,.0f"
D) "revenue": ":.2%"
Why: A string that starts with a colon is a d3 number format: $ adds the dollar sign, , the thousands separator, .0f no decimals.
A is wrong: True adds the column with its raw value: 27677.1.
B is wrong: That is Python's old percent formatting; Plotly uses d3-format after a colon.
D is wrong: .2% multiplies by 100 and adds a percent sign: right for a rate, wrong for dollars.
Q10
What does fig.update_layout(hovermode="x unified") change on a line chart with four stores?
A) Zooming one panel now zooms every panel
B) One hover box appears for the x position under the mouse, listing all four stores
C) The four lines are merged into one trace
D) The x axes of all facets are forced to the same range
Why: Unified hover reads a time series the way people compare it: one date, every series. It is a layout setting, so it applies to the whole figure.
A is wrong: Shared zoom comes from facets sharing axes, not from the hover mode.
C is wrong: The traces are untouched: the legend still switches each store on and off.
D is wrong: Axis ranges are set with update_xaxes; the hover mode only changes the label.
Q11
What does this print?
totals = sales.groupby("store", as_index=False)["revenue"].sum()
fig = px.bar(totals, x="store", y="revenue")
print(fig.data[0].type, len(fig.data[0].x))
bar 4
Why: Four rows in, four bars out: px.bar draws one bar segment per row and never aggregates. Hand it sales itself and the same print says bar 2903.
Q12
You will email one chart to a manager who is online. Your table has one row per customer, including an email column the chart does not use. What is the right way to prepare the file?
A) fig.write_html("chart.html") from the full table: unused columns are left out automatically
B) fig.write_image("chart.html"), so that no data is included
C) Put email in hover_data so the manager can check individual customers
D) Aggregate to what you mean to publish, pass only the columns the chart needs, then fig.write_html("chart.html", include_plotlyjs="cdn")
Why: The HTML file contains the data you passed to the figure as readable text. Decide what the reader may see before you build the figure; "cdn" keeps the file to a few kilobytes because the reader's browser fetches plotly.js.
A is wrong: Columns you did not map are indeed left out, but one point per customer still ships every customer's x, y and hover values; and the default embeds a multi-megabyte library.
B is wrong: write_image makes a PNG, SVG or PDF chosen by the extension; .html is not an image format.
C is wrong: That writes every email address into a file you are about to send.

7.2 · Predict, then run

P1
Prints:
fig = px.line(monthly, x="month_start", y="revenue", facet_col="store")
print(len(fig.data), len(fig.layout.annotations), fig.layout.annotations[0].text)
4 4 store=Asheville
Why: One trace per panel, and one annotation per panel: facet titles are layout annotations whose text is store=Asheville. That is why fig.for_each_annotation(lambda a: a.update(text=a.text.split("=")[-1])) cleans them up.
P2
Prints:
fig = px.histogram(sales, x="store", y="revenue", histfunc="avg")
print(fig.data[0].type, len(fig.data[0].x))
histogram 2903
Why: px.histogram lets Plotly do the averaging, but it does it in the browser: the figure still carries all 2,903 rows. The chart shows four bars; the file holds every store-day. Aggregating with pandas first sends four numbers.

7.2 · The lesson page's own quiz

  1. C. The default include_plotlyjs=True embeds the whole library, so the file works offline. "cdn" needs the internet; False will not display by itself.
  2. A. color="store" makes 4 traces, and px.bar draws one segment per row: 2,903 in total. It never aggregates.
  3. B. Every column named in hover_data is stored in the file as readable text: the emails travel with the chart.
  4. B. Two trace types on two y axes needs make_subplots with secondary_y and graph objects. Lines by color and facets are single Express calls.
  5. A. Small multiples put every month on screen at once; an animation makes the reader compare from memory.

Lab Reference Solutions

Lab 7.1-A · labs/module-19/l7_1-seaborn/tier_order_sizes_solution.py

Merge check: 18,762 completed orders, 18,079 with a customer row, 683 dropped (closed accounts). 3,738 customers. Median order total: Basic $110.66, Silver $146.98, Gold $162.28. Mean completed orders per customer: Basic 2.05, Silver 5.12, Gold 10.81. Gold against Basic: order size ×1.47, orders per customer ×5.26.

How the solution works. The merge uses validate="many_to_one", so pandas itself would complain if a customer id repeated in customers. The left panel is sns.ecdfplot(..., hue="loyalty_tier", hue_order=tiers, log_scale=True, ax=axes[0]): an ECDF, because three overlapping histograms of a skewed quantity are hard to read. The right panel needs one row per customer first (groupby(["customer_id", "loyalty_tier"]).agg(orders=("order_id", "count"))), then sns.pointplot(..., errorbar=("ci", 95), seed=42). Finishing is Matplotlib: set_title(..., loc="left"), axis labels that name the unit and the bars, sns.move_legend.

What to accept. Any pair of titles that states the finding (order size differs modestly, order count differs a lot). A box plot or bar plot on the right is fine if the label says what is drawn. Common wrong turn: running pointplot on table with y="order_total": that answers the first question twice. A caution worth saying: tiers are defined by completed spend, so "Gold customers order more" is partly true by construction; the chart describes how they got there, it does not explain why.

Lab 7.1-B · labs/module-19/l7_1-seaborn/website_by_age_solution.py

1,800 responses, 472 with no website rating. Means by age group: 3.69, 3.67, 3.67, 3.66, 3.72 and 65+ 3.04 (n = 291, 95% CI 2.94 to 3.15); everyone else 3.68, a gap of 0.64 points. The gap is the same for online shoppers (65+ 3.06) and store shoppers (65+ 3.02). catplot returns a FacetGrid with axes shape (1, 2). No website rating: 3% of online shoppers, 46% of store shoppers.

How the solution works. Step 1 draws the same pointplot twice with errorbar=("ci", 95) and errorbar="sd". Step 2 is the hand check: agg(n="count", mean="mean", sd="std", se="sem"), then mean ∓ 1.96 × se. The left panel's bars match ci_low to ci_high (to within bootstrap wiggle); the right panel's match mean ± sd. Step 3 is sns.catplot(kind="point", col="shopper", ...), which returns a FacetGrid: titles with g.set_titles("{col_name} shoppers"), saving with g.savefig(...).

What it reveals. A learner who writes g.set_title(...) or passes ax= to catplot has not yet separated the two kinds of function. A learner who reports the 65+ gap without Step 4's caveat has the chart and not the analysis: 46% of store shoppers gave no website rating, so the store panel is the store shoppers who use the website.

Lab 7.2-A · labs/module-19/l7_2-plotly/product_map_solution.py

242 products, 8 with no rating, 234 rows in the chart. Figure with 9 traces of type scatter. Spearman correlation of price and rating: −0.01. Lowest rated: Juniper Vane Trailhead Down Jacket, $372.95, rating 2.8, 4 reviews. product_map.html is about 31 KB with the CDN link; a product name is inside the file (True) and the cost column is not (False).

How the solution works. The table is cut to five columns before the figure exists. px.scatter(..., color="category", size="review_count", log_x=True, hover_name="name", hover_data={"category": True, "price": ":$,.2f", "rating": ":.1f", "review_count": ":,"}) gives nine traces (one per category) of type scatter (234 points is under the WebGL threshold of a thousand). The hover template that comes back is <b>%{hovertext}</b><br><br>Category=%{customdata[0]}<br>List price=%{x:$,.2f}<br>Rating=%{y:.1f}<br>Reviews=%{customdata[1]:,}<extra></extra>. On a log axis an annotation's x is math.log10(price).

What to accept. Any title that states the near-zero relationship. Common wrong answers: the correlation printed as Pearson (−0.03 is not the number asked for, though the conclusion is the same); "price": "$,.2f" without the leading colon (Plotly then shows the raw value); the full products table passed to px.scatter, after which the last check prints False only by luck, because unmapped columns are not written. The habit being taught is to decide the columns on purpose.

Lab 7.2-B · labs/module-19/l7_2-plotly/promo_share_trend_solution.py

20,302 orders, 2,148 with a promo code. Weekly table (210, 4); median weekly share 6.6% online, 7.9% in store. 2 traces, hover mode x unified. Six sale weekends shaded, each four days (Friday to Monday). Share of orders using a code: 51.0% on sale-weekend days, 8.0% on all other days. January 2024 is 25.3% with no sale on: the data starts there and WELCOME10 marks a customer's first order in the data.

How the solution works. orders["order_date"].dt.to_period("W-SUN").dt.start_time labels each order with the Monday of its week; groupby(["week", "channel"]).agg(orders=("order_id", "count"), share=("used_code", "mean")) gives 105 weeks times 2 channels = 210 rows. custom_data=["orders"] carries the count so the hover can say 11.4% of 153 orders. The sale weekends are found from daily_sales.promo_day, grouped into runs of consecutive dates with (promo_dates.diff().dt.days != 1).cumsum(), and shaded with add_vrect.

The stretch question. January 2024 shows a high share with no sale: WELCOME10 marks a customer's first order in the data, and the data starts on 2024-01-01, so long-standing customers look like new ones for the first weeks. It is a small preview of a trap in one capstone question; do not say which.

Warm-up and Exit Ticket Answers

Warm-up (retrieval from Session 18)
  1. A request comes back 401. Another comes back 403. What does each one tell you, and what should your client do next? Answer: 401: the server does not know who you are (no token, or token_expired): log in again and repeat the request once. 403: it knows who you are and refuses: stop and fix the credential or the permission. Neither is retried in a loop.
  2. Where does an API key live while you work on a notebook you will share, and where in the request does it travel? Answer: In an environment variable (or typed at a prompt), read at run time; never in the code. It travels in a header (X-API-Key), not in the URL, because URLs end up in logs and browser history.
  3. The server answers 429 with the header Retry-After: 4. What does a polite client do? What if the header is missing? Answer: Wait at least 4 seconds, then send the same request again. With no header, fall back to a default wait (exponential backoff with jitter), with a maximum number of tries.
  4. What does this print? 
    print([min(4.0, 1.0 * 2 ** n) for n in range(4)])
    Answer: [1.0, 2.0, 4.0, 4.0]: the delay doubles (1, 2, 4) and then the cap of 4.0 holds it. That is exponential backoff with a ceiling; real clients add random jitter on top.
  5. Name two failures a retry policy should retry and two it never should. Then: what made the Lesson 6.5 download resumable? Answer: Retry: 429, 5xx, timeouts (temporary). Never: 400, 401, 403, 404 (the same request will fail the same way). Resumable: each page is saved to its own file as soon as it arrives, written completely or not at all, and pages whose files exist are skipped.
Exit ticket
  1. You call sns.barplot(data=sales, x="store", y="revenue") and black lines appear on the bars. What are they, by default, and which argument changes them? Answer: A bootstrapped 95% confidence interval for the mean of each bar (uncertainty of the estimate, not spread of the days). errorbar= changes it: "sd", "se", ("pi", 50) or None. Say which one in the caption.
  2. Give one job for an axes-level function and one for a figure-level function. Answer: Axes-level (scatterplot, histplot, barplot): one panel inside your own plt.subplots() layout, with ax=. Figure-level (relplot, displot, catplot): seaborn builds a grid of panels from a column with col= / row= and returns a FacetGrid.
  3. You plot one point per customer with email in hover_data and send the HTML file to a colleague. What have you sent? Answer: The customer table: every x, y and hover column is stored as readable text inside the file. Aggregate first and pass Plotly only the columns the chart needs.

Common Wrong Answers and What They Reveal

  • Q3 answered `(2, 2)`: the learner pictures the layout, not the object. With col_wrap the Axes array is flat. Have them print g.axes.shape for a call with row= as well.
  • Q4 answered "monthly totals": the learner knows seaborn aggregates but not with what. Ask what estimator= defaults to.
  • Q5 answered "95% confidence interval": the most important miss of the session. The learner reads every bar as uncertainty. Go back to the four-panel figure and the summary table: sd about 0.9, se about 0.06.
  • Q6 answered `[1.0, 5.0]` for S, or four bars: the learner does not yet believe that barplot computes. Same root as Q4.
  • Q8 answered 4 or 2: counts colors or facets, not their combinations. Print [t.name for t in fig.data].
  • Q11 answered `bar 2903`: read the code as if sales had been passed. The groupby line is the whole point: this learner will stack slivers in the project.
  • Q12 answered A: believes "unused columns are left out" settles the privacy question. It does not: one point per customer is already the customer table.
