Your working pages for two of the most used skills in data work. Before the break: turning a damaged file into a table you can trust, and proving that you did. After the break: answering every question that starts with 'for each...'.

2.3

Cleaning Data

100 min lesson
By the end you can
  • Audit an unfamiliar table and list its problems before changing anything
  • Repair structure: untidy headers, summary rows and duplicate rows
  • Standardize inconsistent text and convert numbers and dates that were stored as text, including dates in several formats
  • Decide, and defend, what to do with each kind of missing or suspicious value: repair, fill, flag or leave
  • Verify a cleaning job with a before-and-after audit and assertions, and package it as a function you can rerun
Key ideas
  • The repair bench. Audit first and write the repair list. Fix one thing at a time, in code, on a copy. Check each repair. The raw file is read-only.
  • The order. Structure (headers, rows that are not data, duplicates) → text → numbers → dates → missing values. Fixing the shape first makes every later step simpler.
  • Audit by counting. df.dtypes, df.isna().sum(), df.nunique(), df.duplicated().sum(). Print df.columns.tolist() to see hidden spaces. A category column with more distinct values than the business has is damaged.
  • Text. .str.strip(), then .str.title() / .str.lower() / .str.upper(), then a mapping dictionary with .replace({...}), built from value_counts() after the mechanical steps. Placeholders such as none and - become real missing values with .where(...).
  • Numbers. pd.to_numeric(s, errors="coerce") is a detector: what became NaN but was not empty? Remove symbols with .str.replace("$", ""), then convert without errors= as a guarantee. Then .describe(): is the minimum and maximum plausible?
  • An outlier is a question. Never change a value for being extreme. Look for independent evidence (here: the order's item lines), then repair only the rows the evidence points to, with one .loc.
  • Dates. One pd.to_datetime(d, format=..., errors="coerce") per known format, combined with .fillna(). Impossible dates become NaT and stay missing.
  • Missing values are decisions. It is not missing (no promo code) · repair (a rule or another source) · leave and report · drop for one analysis with dropna(subset=[...]). Filling a number invents data. Write the decision down.
  • Prove it. Run the audit again and compare. State the rules as assert lines. Package the job as a function so it can be rerun.
Worked example: what is missing in the survey, and what should we do about it?

survey.csv is tidy: no bad headers, no duplicates. Its problem is the quiet one, missing answers. This example practices the part of cleaning that is judgment, not typing: look at what is missing, find out why, and decide.

Audit first. Seven columns have gaps, and two of them have hundreds.

survey = pd.read_csv("data/survey.csv")
print(len(survey), survey.duplicated(subset=["customer_id"]).sum())
missing = survey.isna().sum()
print(missing[missing > 0])

sat_overall       53

sat_price         47
sat_staff        605
sat_website      472
recommend         54
comment          977
dtype: int64

What would dropna() do? Print the row count before and after every drop.

print(len(survey), "->", len(survey.dropna()))
print(len(survey), "->", len(survey.dropna(subset=["sat_overall", "recommend"])))
1800 -> 295
1800 -> 1699

Why are 605 staff ratings missing? Compare the share of missing answers for online shoppers and store shoppers (the mean of a True/False column is a share).

online = survey["store"] == "Online"
for label, rows in [("online shoppers", online), ("store shoppers ", ~online)]:
    print(label, round(survey.loc[rows, "sat_staff"].isna().mean() * 100, 1), "% missing staff rating,",
          round(survey.loc[rows, "sat_website"].isna().mean() * 100, 1), "% missing website rating")
online shoppers 69.9 % missing staff rating, 2.9 % missing website rating
store shoppers  3.0 % missing staff rating, 45.9 % missing website rating

What would filling claim? Compare the mean as it is with the mean after filling every gap with a neutral 3.

print(survey["sat_staff"].mean().round(2), survey["sat_staff"].fillna(3).mean().round(2))
assert survey["sat_staff"].dropna().between(1, 5).all()
assert survey["recommend"].dropna().between(0, 10).all()
print("all checks passed")
4.02 3.68
all checks passed

Decision: leave the gaps and report them. Seven in ten online shoppers skipped the staff question because they never met staff: for them the honest value is 'does not apply', and filling it with 3 would pull the staff score from 4.02 down to 3.68 with invented answers. Dropping every row with any gap would keep 295 of 1,800 responses. What you write in the report: "Staff satisfaction is based on the 1,195 customers who answered, almost all of them store shoppers."

2.4

GroupBy Operations

90 min lesson
By the end you can
  • Explain split-apply-combine and read a groupby expression piece by piece
  • Summarize groups with built-in methods and with named aggregation, on one key or several
  • Choose correctly between agg (one row per group), transform (one row per original row) and filter (keep or drop whole groups)
  • Control what happens to missing keys and unused categories with dropna= and observed=
  • Recognize the common traps: lost rows, a key hidden in the index, and averages of averages
Key ideas
  • Split, apply, combine. df.groupby("key")["column"].function(): deal the rows into piles by key, compute on each pile, collect one answer per pile. Any question that starts 'for each...' is a groupby.
  • What comes back. A Series or DataFrame whose index is the group key, sorted. Get the key back as a column with .reset_index() or as_index=False.
  • Counting. .size() rows per group · .count() non-missing values of a column · .nunique() distinct values. They answer different questions.
  • Named aggregation. df.groupby("store").agg(orders=("order_id", "count"), revenue=("order_total", "sum")). New column name = (source column, function). Learn this form by heart.
  • Rates. Make a True/False helper column; its mean within each group is the rate.
  • Several keys. A list of keys gives one group per combination and a two-level index (MultiIndex). Flatten with .reset_index() or spread one level into columns with .unstack(). A key can be computed on the spot: orders["order_date"].dt.year.
  • What shape do I want back? One row per group: agg. The same rows with a group number on each: transform. Fewer of the same rows: filter (or a transform and a mask, which is faster).
  • Quiet traps. Rows whose key is missing vanish unless dropna=False: check that the groups add up to len(df). Never average group means of unequal groups. observed=False shows categories that have no rows.
Worked example: what do different age groups think of our prices?

survey.csv again, with a 'for each' question: for each age group, how satisfied are customers with prices and with the website (1 = very dissatisfied, 5 = very satisfied)? The example uses the four moves you will repeat in the lab: named aggregation, a check that the groups add up, transform, and filter.

One row per age group. count on response_id counts responses; count on sat_price counts answers, because count skips missing values.

by_age = survey.groupby("age_group").agg(
    responses=("response_id", "count"),
    answered_price=("sat_price", "count"),
    price=("sat_price", "mean"),
    website=("sat_website", "mean"),
)
print(by_age.round(2))

filter keeps whole groups: here, only the responses from stores with at least 250 responses.

busy = survey.groupby("store").filter(lambda g: len(g) >= 250)
print(len(busy), sorted(busy["store"].unique()))

Two groups stand out. Customers aged 18 to 24 rate prices at 2.80 when every other group is between 3.32 and 3.44, and customers aged 65 and over rate the website at 3.04 when every other group is near 3.7. Those are leads to investigate, not conclusions: Module 4 tests whether gaps like these could be chance. The average of the six group averages (3.276) is not the overall average (3.309), because the groups are different sizes.

Glossary for Session 5

  • Audit: a systematic count of what is in a table (dtypes, missing values, distinct values, duplicates) before changing anything.
  • Raw file: the data as received. Read-only: all fixes are code applied to a copy.
  • Duplicate: a row that is an exact copy of an earlier row (duplicated(), drop_duplicates()); subset= compares only some columns.
  • Placeholder: text that stands for 'nothing', such as none, - or pending. It must become a real missing value.
  • Coerce: errors="coerce": convert what can be converted and turn the rest into NaN or NaT instead of raising an error.
  • NaT: 'not a time': the missing value of a datetime column.
  • Mapping dictionary: a dictionary of wrong spelling to right spelling, applied with .replace(); it documents each judgment call.
  • Outlier: an extreme value. A question to investigate with independent evidence, not an error by itself.
  • Assertion: an assert line that states a rule and stops the program when the rule is broken.
  • Pipeline: cleaning steps packaged as functions and chained (.pipe()), so the whole job can be rerun.
  • Split-apply-combine: the groupby pattern: split rows into groups by a key, compute on each group, combine the answers.
  • Aggregation: reducing each group to one row (sum, mean, agg).
  • Named aggregation: agg(new_name=("column", "function")): one output column per argument.
  • Transform: a group calculation that returns one value per original row.
  • Filter (groupby): keeping or dropping whole groups according to a test on the group.
  • MultiIndex: an index with more than one level, as produced by grouping on several keys.
  • Average of averages: the mean of group means; it equals the overall mean only when the groups are the same size.
