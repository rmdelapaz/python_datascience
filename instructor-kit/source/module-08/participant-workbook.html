Feature Engineering Basics

95 min solo
Key ideas
  • A feature is a column you build so a pattern becomes visible. First decide the unit of analysis: what one row is. Every feature must be one fact about that unit.
  • Derived columns come from four patterns: a flag (.notna(), .isin(), a comparison), arithmetic between columns, a choice (np.where), a lookup (.map). Ratios remove size and leave behavior.
  • Dates become features as parts that repeat (.dt.month, a weekend flag) or as elapsed time from a fixed reference date. Never use today's date.
  • pd.cut: you choose the edges; each bin includes its right edge; values outside the edges become NaN. pd.qcut: equal-sized groups, edges chosen from the data.
  • An ordered categorical (pd.CategoricalDtype([...], ordered=True)) sorts, compares and takes max() in the real order, not the alphabet.
  • Per-customer features: group and aggregate to one row each, then left-merge onto the table that defines the unit. Fill counts and sums with 0. Leave averages missing and add a flag.
  • Encoding: ordinal categories → ordered integers (.cat.codes). Nominal categories → one yes/no column each (pd.get_dummies).
  • The cutoff rule: could I have computed this value on the cutoff date, using only what existed then? If not, it leaks. Leaks raise no error; they give results that are too good.

Worked example: product features: does time on sale explain review counts?

One row is a product. The question: which products have many reviews? Two candidate features: how long the product has been on sale, and how expensive it is. (The lesson builds customer features; this example uses data/products.csv.)

Elapsed time from a fixed reference date, then bands with edges that mean something (under a year, one to three years, longer).

products = pd.read_csv("data/products.csv", parse_dates=["launch_date"])
as_of = pd.Timestamp("2025-12-31")
products["years_on_sale"] = (as_of - products["launch_date"]).dt.days / 365.25
products["age_band"] = pd.cut(products["years_on_sale"], bins=[0, 1, 3, np.inf],
                              labels=["new", "established", "veteran"])
print(products["age_band"].value_counts(sort=False, dropna=False))
age_band
new             13
established     49
veteran        180
Name: count, dtype: int64

No NaN row in that count, so every product landed in a band. Now check the feature against the thing we care about, with the group size beside it.

print(products.groupby("age_band", observed=True)["review_count"]
      .agg(["mean", "median", "size"]).round(1))
             mean  median  size
age_band                       
new          37.5     0.0    13
established  56.8    34.0    49
veteran      76.6    40.5   180

The second feature: three equal-sized price bands, made by qcut.

products["price_band"] = pd.qcut(products["price"], q=3,
                                 labels=["low", "mid", "high"])
print(products.groupby("price_band", observed=True)["review_count"]
      .agg(["mean", "median", "size"]).round(1))
            mean  median  size
price_band                    
low         99.5    61.0    81
mid         56.8    26.0    81
high        54.8    26.5    80

Both features separate the products: review counts rise with time on sale, and the cheapest third of the catalog collects far more reviews than the rest. Notice observed=True: these are categoricals, and it keeps the output to the bands that exist. And notice the 13 new products with a median of 0 reviews: for a product launched last month, "no reviews" says nothing about quality.

3.1

Line, Scatter and Bar Charts

90 min solo
Key ideas
  • A chart is an answer to a question. Decide the question first; the chart type follows.
  • Figure = the whole canvas (it has a size, and it is what gets saved). Axes = one chart on it. Create both with fig, ax = plt.subplots(figsize=(7, 3.5), layout="constrained").
  • One rule: plt creates figures and shows them. Everything else is a method on ax or fig: ax.plot, ax.set_title, ax.set_xlabel, ax.legend, fig.savefig.
  • Most of a chart is made in pandas first. Aggregate to the level the question needs, then plot.
  • Line (ax.plot): change over time. One call per line; label= feeds ax.legend().
  • Scatter (ax.scatter): do two numbers move together? A small s and an alpha below 1 fix overplotting. It shows a pattern, not a cause.
  • Bar (ax.bar, ax.barh): which group is bigger? ax.bar never aggregates: one number per bar, and you compute it. Bars start at zero.
  • Histogram (ax.hist): what is typical, how spread out? It always counts: give it the raw rows. bins and range are your decisions; say what you left out.

Worked example: how did the number of orders per month change, online and in stores?

The question is about change over time, so the answer is a line chart, and most of the work happens in pandas before any plotting. (The lesson charts store revenue; this example counts orders by channel.)

Aggregate first: one row per month, one column per channel, each cell a count of orders.

orders = pd.read_csv("data/orders.csv", parse_dates=["order_date"])
orders["month"] = orders["order_date"].dt.to_period("M").dt.to_timestamp()
per_month = orders.pivot_table(index="month", columns="channel",
                               values="order_id", aggfunc="count")
print(per_month.iloc[[0, -1]])
channel     online  store
month                    
2024-01-01     409    204
2025-12-01     769    376

Then the five-line pattern, with one ax.plot call per column. A solid line and a dashed line, so the chart still works without color.

fig, ax = plt.subplots(figsize=(8, 3.6), layout="constrained")
ax.plot(per_month.index, per_month["online"], marker="o", markersize=3,
        color="#667eea", label="Online")
ax.plot(per_month.index, per_month["store"], marker="s", markersize=3,
        color="#d95f02", linestyle="--", label="Store (account holders)")
ax.set_title("Orders per month by channel")
ax.set_ylabel("Number of orders")
ax.set_ylim(bottom=0)
ax.legend()
plt.show()
print(len(fig.axes), len(ax.lines))
1 2

Both channels grow, and both spike in December. Online runs at about twice the store count throughout. The label on the store line matters: orders.csv holds store orders by signed-in account holders only, and a chart should say what it is counting.

Glossary

TermMeaning
FeatureA column you build so that a pattern becomes visible: orders so far, days since last order, share bought online.
Unit of analysisWhat one row of a table represents. The question decides it: a customer, an order, a store-day.
Derived columnA column computed from other columns in the same row: a flag, a difference, a ratio, a choice.
Reference dateA fixed date, written down, from which elapsed time is measured. Never today's date.
BinningTurning a number into a group. pd.cut: you choose the edges. pd.qcut: equal-sized groups from the data.
CategoricalA column that can hold only values from a fixed list. Ordered categoricals sort and compare correctly.
Ordinal / nominalA category with a meaningful order (tiers, age bands) / one without (store, channel).
One-hot encodingOne yes/no column per category, made with pd.get_dummies. For nominal categories.
ScalingPutting numeric columns on a common footing: min-max (0 to 1), z-score (mean 0, std 1), np.log1p for skew.
Cutoff dateThe date you pretend to stand on. Features come from before it; the target comes from after it.
LeakageA feature that uses information not available on the cutoff date. No error; results that are too good.
FigureThe whole picture: the sheet of paper. It has a size and it is what gets saved.
AxesOne chart on a Figure, with its own x axis, y axis, title and data. Not the plural of axis.
OverplottingSo many dots on top of each other that density is invisible. Fix with a small s and alpha.
Bin (histogram)One of the equal intervals a histogram cuts the range into; the bar shows how many rows fall in it.
Object-oriented interfaceDrawing with methods on ax and fig. plt is used only to create and show figures.
