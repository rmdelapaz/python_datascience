Known environment traps

Charts that do not appear. In a notebook a figure shows at the end of the cell. In a plain .py script, plt.show() opens a window and the script waits until it is closed. On a machine with no display (a remote server, some WSL setups) no window opens at all: save with fig.savefig("chart.png") and open the file. The kit labs always save to output/ and never call plt.show(), so they work everywhere.

A line of text above the chart, such as [<matplotlib.lines.Line2D object at 0x...>], is the return value of the cell's last line. It is harmless; ending the cell with plt.show() removes it.

Old habits from other tutorials. Learners who have seen Matplotlib before will type plt.title(...). It works with one chart, which is why it is tempting. Hold the line on the one rule (plt creates and shows; everything else is a method on ax or fig): Session 9 depends on it.

observed= warnings. Anyone on pandas 2.x sees a FutureWarning about observed when grouping by a categorical. The code still works; the lab solutions pass observed=True explicitly so they are quiet everywhere.

How to run it

Closed notebooks. Read each question aloud, 30 seconds of silent writing, one answer from the room, then yours. Five retrieval questions (with answers)
  1. You resample daily revenue to monthly totals. What do you print beside every total? Answer: The count of days with a value. Sums skip NaN silently, so a month with missing days looks like a weak month.
  2. What does wide.asfreq("D") do to a table with dates in the index? Answer: It gives every calendar day a row. Days that had no row appear, filled with NaN, and you then decide what each gap means.
  3. On a gap-free daily Series, how many NaN values does s.rolling(7).mean() have, and where? Answer: Six, at the start. A 7-row window is full for the first time on row 7.
  4. Write a 7-day average of rev that is safe for judging today. Answer: rev.shift(1).rolling(7).mean(). Shift first, so today is not inside its own baseline.
  5. A long table holds four stores stacked in one column. What three things do you do, in order, to get each store's own 7-day average? Answer: Sort (by store, then date), group (by store), window (inside transform). The first rows of each group should come out NaN.

Three mistakes learners will make, and how to coach each
  • An inner merge that deletes the most interesting rows. No error; the table shrinks from 4,850 to 3,792 and every average afterward describes buyers only. Coach: "How many rows before the merge? How many after?" Then how="left" from the table that defines the unit, plus validate=.
  • Filling every NaN with 0. table.fillna(0) turns "no average exists" into "average order of $0.00" and drags group means down. Coach: "Is that zero a fact about this customer?" Counts and sums: yes. Averages, shares, recency: no. Add a flag such as has_ordered.
  • Bins that silently lose values. pd.cut with edges that do not cover the data (a first edge of 18 instead of 17, a last edge that is too low) produces NaN with no warning. Coach: "Compare .isna().sum() before and after the cut." Fix with -np.inf and np.inf as the outer edges, or include_lowest=True. Related error, on qcut with many repeated values: ValueError: Bin edges must be unique.

The mental model to say

Say: "A table of 24 monthly totals is correct, and almost nobody can see the pattern in it. Draw the same 24 numbers as a line and the seasons, the growth and the odd month out are visible in a second. Your eyes are very good at shapes and very slow at columns of digits."

Say: "A chart is not a decoration. It is an answer to a question, and the kind of question picks the kind of chart. Four tools on a bench: you do not start by picking up the saw, you start by looking at what needs cutting." Write the four on the board under What question does this chart answer?: change over time → line; two numbers together → scatter; which group is bigger → bar; what is typical → histogram.

Two nouns: Figure, the sheet of paper; Axes, one chart drawn on it. Draw a rectangle with a smaller rectangle inside it and label both. "Next session the sheet holds four charts. That is why we hold ax in a variable from the very first chart."

Three mistakes learners will make, and how to coach each
  • Bars from rows that were never aggregated. ax.bar(df["store"], df["revenue"]) draws one bar per row, stacked at each x position; the visible height is each group's largest single value. No error. Coach: "How many bars did you draw? len(bars)." Then: groupby first, one number per bar. (The opposite slip is running a groupby before ax.hist: the histogram wants the raw rows.)
  • Mixing the two styles. ax.title("...") raises TypeError: 'Text' object is not callable; ax.xlabel(...) raises AttributeError. Coach: "On an Axes the verbs start with set_." Point at the translation table. A learner who writes plt.title(...) gets no error today; tell them it stops working next session with four panels.
  • Dates or numbers that are still text. The x axis becomes a solid black band (one tick per row: 727 of them) and the drawing is slow, or the points are in file order instead of date order. No error. Coach: "What is df["date"].dtype?" Fix at load time with parse_dates. A related error when x and y come from different filters: ValueError: x and y must have same first dimension.

Checks for understanding (ask out loud)
  1. What is the difference between a Figure and an Axes? Answer: The Figure is the whole canvas and is what gets saved. An Axes is one chart on it, with its own x and y axis, title and data.
  2. Which of ax.bar and ax.hist does the counting for you? Answer: ax.hist: give it the raw rows. ax.bar needs one number per bar that you computed.
  3. Orders per day of the week: sort the bars by value? Answer: No. Weekdays have a natural order that readers expect. Sort by value only when the categories have no order of their own.
  4. You see plt.xlabel("Visitors") in a tutorial. What do you write? Answer: ax.set_xlabel("Visitors").

Wrap-up

Exit ticket (3 questions, with answers)
  1. Before you build any feature, what is the first thing you decide? Answer: The unit of analysis: what one row of the table represents (a customer, an order, a store-day). Every feature must be one fact about that unit.
  2. State the cutoff rule in one sentence. Answer: For every feature: could I have computed this value on the cutoff date, using only what existed then? If not, it leaks.
  3. Name the chart for each question: (a) how did it change over time, (b) do two numbers move together, (c) which group is bigger, (d) what values are typical and how spread out are they? Answer: (a) line, ax.plot; (b) scatter, ax.scatter; (c) bar, ax.bar or ax.barh, after aggregating; (d) histogram, ax.hist, on the raw rows.

Reading the tickets: for question 1, "load the data" or "choose the features" means the unit of analysis has not landed; start Session 9 by asking what one row is in the nine-panel project.
