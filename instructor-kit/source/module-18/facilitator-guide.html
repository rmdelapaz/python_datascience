The risk in Session 18: secrets on screens, loops that hammer

Two habits to make automatic today. Secrets never appear in code, output or logs: the projector itself is a test (never print a key; print a hint). Every retry has a reason, a wait and a limit: retry 429, 5xx and timeouts; never 400, 403 or 404; renew an expired token once. A loop that retries a 401 forever looks like an attack.

Warm-up: Retrieval from Session 17

10 min

Five questions, notes closed, then answers aloud.

  1. Which Beautiful Soup method returns None when nothing matches? Answer: select_one() (and find()). select() and find_all() return a list, empty when nothing matches.
  2. Why does get_soup() pass resp.content, not resp.text? Answer: From bytes, Beautiful Soup reads the page's own <meta charset>, so the text decodes correctly whatever the server said.
  3. How does a pagination loop know it has reached the last page of the catalog? Answer: There is no a.next link on the last page, so select_one("nav.pagination a.next") returns None.
  4. requests sees an empty list where the browser shows deals. What do you try before Selenium? Answer: Find the data file the page loads (Network tab or the script) and request it directly, if allowed.
  5. Why WebDriverWait(...).until(...) instead of time.sleep(), and where does driver.quit() go? Answer: The wait continues as soon as the condition is true and raises clearly if it never is. quit() goes in a finally block.

Ground Rules Opener (2 minutes)

0:10

The Six Ground Rules for Module 6

2 min

Six learners, one rule each, aloud. Today's sentence: "An API is the front door rule 3 asked for. It comes with its own rules: a key that is yours alone, and a limit the owner sets. Keep both."

  1. Read robots.txt and obey it. It is the owner's published request to programs: where they may go and how fast.
  2. Read the terms of use. If they forbid automated collection, the answer is no, however easy the code would be.
  3. Prefer an API or a download when one exists. It is the front door.
  4. Go slowly and say who you are. Pause between requests; send a User-Agent with a way to contact you.
  5. Never go around a login, a paywall or a block. If you are asked to stop, stop.
  6. Do not collect personal data. Names, emails, profiles and photos of real people are protected by law in many places.

Mental model to say

"Think of a festival. At the gate you show your ticket once (your username and password). They give you a wristband (the token) and you wear it everywhere inside: no one asks for the ticket again.     class ApiError(Exception):
    """An error response from the API, with its status, code and message."""
    def __init__(self, status, code, message):
        super().__init__(f"{status} {code}: {message}")
        self.status, self.code, self.message = status, code, message


def check(resp):
    """Return the response if it succeeded. Otherwise raise ApiError."""
    if resp.ok:
        return resp
    try:
        error = resp.json()["error"]
        code, message = error["code"], error["message"]
    except (requests.exceptions.JSONDecodeError, KeyError, TypeError):
        code, message = "http_error", resp.reason
    raise ApiError(resp.status_code, code, message)

    def get_all(path, params=None):
    """Collect every item from a paginated endpoint by following 'next'."""
    items, url = [], f"{API}{path}"
    while url:
        data = check(requests.get(url, headers=KEY_HEADERS, params=params,
                                  timeout=10)).json()
        items.extend(data["items"])
        url = f"{API}{data['next']}" if data["next"] else None
        params = None              # 'next' already carries the filters
    return items

Three mistakes to expect
  • RuntimeError: Set the environment variable ... because Jupyter was started before the variables were set, or from another terminal. Coach: close it, set them, start it from that terminal. Do not let anyone "fix" it by typing the key into the notebook.
  • Leaving out the word Bearer, or using data= instead of json= for the login (401 missing_token; 400 The request body must be JSON.). Coach: "Print the headers you are sending. What does the documentation say the value looks like?"
  • KeyError: 'access_token' after a failed login. The KeyError is a symptom: the login answered 401 and the body is an error object. Coach: "What was the status of the line BEFORE?" Then check().

Also common: sending params again on every page (filters doubled), and a retry loop around a 401 with no limit.

Objectives (from the lesson)

Mental model to say

"Many freeway on-ramps have a light that lets one car go every few seconds. Nobody enjoys it, but without it everyone merges at once and the whole freeway crawls, including the cars from that ramp. A rate limit is that light. A good driver arrives at the pace the light allows, waits when it is red for exactly as long as it says, and does not honk."

Two halves on the board: politeness (pace yourself, obey Retry-After, never fetch the same thing twice) and resilience (retry what is temporary with backoff, give up clearly, save work so an interruption loses nothing).

  3. Plan A: pace yourself. Say: "The freeway on-ramp light. Ten per five seconds is one every half second; add ten percent for clock drift. The Throttle sleeps only for whatever is left of the interval." 
    class Throttle:
    """Keep calls at least `interval` seconds apart."""
    def __init__(self, interval):
        self.interval, self.last = interval, None

    def wait(self):
        if self.last is not None:

    def get_polite(url, max_tries=5, **kwargs):
    """GET that waits and retries when the server answers 429."""
    kwargs.setdefault("headers", HEADERS)
    kwargs.setdefault("timeout", 10)

        wait = float(resp.headers.get("Retry-After", 1))

    def backoff_delay(attempt, base=0.5, cap=8.0):
    """Seconds to wait after failed attempt number `attempt` (from 0)."""
    return min(cap, base * 2 ** attempt)

    RETRY_STATUSES = {429, 500, 502, 503, 504}


def get_with_backoff(url, max_tries=5, base=0.5, **kwargs):
    """GET with retries: obeys Retry-After, otherwise backs off with jitter."""
    kwargs.setdefault("headers", HEADERS)
    kwargs.setdefault("timeout", 10)
    for attempt in range(max_tries):
        try:
            resp = requests.get(url, **kwargs)
            if resp.status_code not in RETRY_STATUSES:
                return resp
            problem, asked = f"HTTP {resp.status_code}", resp.headers.get("Retry-After")
        except (requests.exceptions.Timeout, requests.exceptions.ConnectionError) as err:
            problem, asked = type(err).__name__, None
        if attempt == max_tries - 1:
            break
        delay = float(asked) if asked else random.uniform(0, backoff_delay(attempt, base))
        print(f"  try {attempt + 1}: {problem}; next try in {delay:.1f} s")
        time.sleep(delay)
    raise RuntimeError(f"gave up after {max_tries} tries (last problem: {problem})")

    from requests.adapters import HTTPAdapter
from urllib3.util.retry import Retry


def make_session(total=5, backoff_factor=0.5):
    """A Session that identifies itself and retries temporary failures."""
    retry = Retry(total=total, backoff_factor=backoff_factor,
                  status_forcelist=[429, 500, 502, 503, 504],
                  allowed_methods=["GET", "HEAD"], respect_retry_after_header=True)
    adapter = HTTPAdapter(max_retries=retry)
    session = requests.Session()
    session.mount("https://", adapter)
    session.mount("http://", adapter)
    session.headers.update(HEADERS)
    return session

    class ApiError(Exception):
    def __init__(self, status, code, message):
        super().__init__(f"{status} {code}: {message}")
        self.status, self.code, self.message = status, code, message


def check(resp):
    if resp.ok:
        return resp
    error = resp.json()["error"]
    raise ApiError(resp.status_code, error["code"], error["message"])


CACHE_DIR = Path("cache")


def cache_path(url, params=None):
    key = url + "?" + json.dumps(params or {}, sort_keys=True)
    return CACHE_DIR / (hashlib.sha256(key.encode("utf-8")).hexdigest()[:16] + ".json")


def cached_get_json(session, url, params=None):
    """Return (data, source): the cache when it can, the network when it must."""
    path = cache_path(url, params)
    if path.exists():
        return json.loads(path.read_text(encoding="utf-8")), "cache"
    resp = check(session.get(url, params=params, timeout=10))
    CACHE_DIR.mkdir(exist_ok=True)
    path.write_text(resp.text, encoding="utf-8")
    return resp.json(), "network"

    def download_pages(session, path, params, out_dir, throttle, max_new=None):
    """Save every page as JSON, skipping pages already saved."""
    out_dir = Path(out_dir)
    out_dir.mkdir(exist_ok=True)
    page, fetched, skipped = 1, 0, 0
    while True:
        file = out_dir / f"page_{page:04d}.json"
        if file.exists():
            data = json.loads(file.read_text(encoding="utf-8"))
            skipped += 1
        else:
            if max_new is not None and fetched >= max_new:
                return {"complete": False, "fetched": fetched, "skipped": skipped}
            throttle.wait()
            resp = check(session.get(f"{API}{path}", params={**params, "page": page},
                                     timeout=10))
            partial = file.with_suffix(".part")
            partial.write_text(resp.text, encoding="utf-8")
            partial.replace(file)
            data, fetched = resp.json(), fetched + 1
        if page >= data["total_pages"]:
            return {"complete": True, "fetched": fetched, "skipped": skipped}
        page += 1

Three mistakes to expect
  • int(resp.headers.get("Retry-After")) with no default: TypeError exactly when things are already going wrong. Coach: "What if the header is not there?" .get("Retry-After", 1).
  • Retrying everything, 404s and 403s included, or retrying with no wait and no limit. Coach: "Could this exact request succeed in two seconds? If not, why ask again?"
  • Caching before checking: one 429 saved and served forever. Coach: "Which line writes the file, and which line checks the status? Swap them."

Also common: thinking a retry policy replaces pacing (it catches the rare miss; the Throttle is plan A), and running several copies of a script to go faster (the limit is per client).

Exit ticket (3 questions, on a sticky note; answers)
  1. What is the difference between a 401 and a 403, and what does your program do with each? Answer: 401: no valid credential (missing, malformed, expired): fix how you send it, or renew an expired token and retry once. 403: understood and refused: stop; a person must fix the key or permission.
