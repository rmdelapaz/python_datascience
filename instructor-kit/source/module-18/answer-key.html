6.4 · API Authentication: Self-check

Q1
The orders endpoint wants a key in the X-API-Key header. What do you get with no key at all, and with a misspelled key?
A) 401 for no key, 403 for the misspelled one
B) 403 for both
C) 401 for both
D) 404 for no key, 401 for the misspelled one
Why: 401 means "I cannot tell who you are" (no credential). 403 means "I understood, and the answer is no" (a credential that is rejected). The practice API answers missing_api_key and invalid_api_key.
B is wrong: With no key there is nothing to refuse: the server cannot tell who you are, which is 401.
C is wrong: A wrong key was understood and rejected: 403. Sending it again will never help.
D is wrong: 404 is for an address that does not exist; /orders exists.
Q2
What does this print? (ApiError is the class from the demo.)
err = ApiError(401, "token_expired", "Log in again.")
print(err)
print(err.code == "token_expired", isinstance(err, Exception))
401 token_expired: Log in again. then True True
Why: super().__init__(f"{status} {code}: {message}") sets the text that print(err) shows. The code is stored as an attribute, so a program can branch on err.code, and ApiError inherits from Exception.
Q3
What does this print?
pages = {"/o?page=1": {"items": ["a", "b"], "next": "/o?page=2"},
         "/o?page=2": {"items": ["c"], "next": "/o?page=3"},
         "/o?page=3": {"items": [], "next": None}}
items, url, calls = [], "/o?page=1", 0
while url:
    page = pages[url]
    calls += 1
    items.extend(page["items"])
    url = page["next"]
print(items, calls)
A) ['a', 'b'] 1
B) ['a', 'b', 'c'] 2
C) ['a', 'b', 'c'] 3
D) ['a', 'b', 'c', None] 3
Why: The loop reads a page, then follows next until it is None. Page 3 exists and is empty, so three pages are fetched and the items are a, b, c.
A is wrong: The loop does not stop after the first page: page 1 has a next.
B is wrong: Page 2 also points onward, so a third request is made (it returns no items).
D is wrong: next is not an item; extend adds only the items list.
Q4
In get_all() the first request sends the filters in params, then the loop sets params = None. Why?
A) To save memory
B) The next address already carries the filters; sending them again would attach every filter twice
C) The server rejects a second page that has parameters
D) To force the server to start again at page 1
Why: next looks like /orders?page=2&per_page=10&since=2025-12-15&status=returned: the filters are already in it.
A is wrong: A small dictionary costs nothing.
C is wrong: The server accepts parameters on every page; the problem is duplicates you did not mean to send.
D is wrong: Page numbers come from next; dropping params does not reset anything.
Q5
Which header sends a bearer token correctly?
A) X-API-Key: <token>
B) Authorization: <token>
C) The token as ?token= in the URL
D) Authorization: Bearer <token>
Why: The value is the scheme, a space, then the token. Without the word Bearer the practice API reports missing_token.
A is wrong: That header is for the API key, a different credential.
B is wrong: This is mistake 1 in the lesson: the server does not recognize a token at all.
C is wrong: URLs are written to logs and histories: never put a credential there.
Q6
You will share this notebook. Which line may stay in it?
A) print(API_KEY)
B) print("key loaded:", API_KEY[:4] + "...")
C) API_KEY = "pinecrest-demo-key"
D) url = f"{API}/orders?api_key={API_KEY}"
Why: A hint confirms the secret loaded without revealing it. The key itself comes from os.environ at run time.
A is wrong: Output cells are saved with the notebook: the whole key would be shared.
C is wrong: A secret typed into code travels with every copy of the file.
D is wrong: The key would end up in logs, histories and error messages.

6.5 · Rate Limiting and Retries: Self-check

Q7
A response carries X-RateLimit-Remaining: 0 and X-RateLimit-Reset: 3. What should your next request do?
A) Go at once: the request itself is valid
B) Switch to a second API key
C) Wait about 3 seconds, until the window starts over
D) Stop the job: the limit is used up for the day
Why: You have used this window's allowance, and the window resets in 3 seconds. Waiting is the polite move and the fastest route to a 200.
A is wrong: It will be refused with 429 and count as wasted traffic.
B is wrong: Getting around a limit with extra keys breaks the ground rules.
D is wrong: Reset is in seconds for this API, not a daily quota.
Q8
What does this print? (CaseInsensitiveDict is the type of resp.headers.)
print(int(requests.utils.CaseInsensitiveDict({"retry-after": "3"}).get("Retry-After", 1)))
3
Why: Header names ignore case, so Retry-After finds retry-after. The default 1 is not needed here, but it protects you when a 429 arrives without the header.
Q9
What does this print?
print([min(2.0, 0.2 * 2 ** n) for n in range(5)])
[0.2, 0.4, 0.8, 1.6, 2.0]
Why: Each wait doubles (exponential backoff) and min caps it at 2.0 seconds.
Q10
The demo's Retry policy has allowed_methods=["GET", "HEAD"]. Why not retry POST too?
A) Repeating a POST can repeat its effect, such as placing an order twice
B) urllib3 cannot retry POST
C) POST requests never fail with 503
D) A POST is always faster
Why: GET and HEAD only read, so sending them twice is harmless. A POST changes something on the server.
B is wrong: It can when told to; the policy deliberately does not.
C is wrong: Any request can meet a busy server.
D is wrong: Speed has nothing to do with whether a repeat is safe.
Q11
A cache function writes resp.text to disk and only then calls check(resp). One request gets a 429. What happens on every later run?
A) Nothing: the cache refreshes itself
B) The next run raises FileNotFoundError
C) The 429 is retried automatically
D) The saved error body is served from the cache, as if it were data
Why: A cache that stores a failure serves it faithfully forever. Check first, write second.
A is wrong: This cache has no expiry: a file that exists is always used.
B is wrong: The file exists; that is the problem.
C is wrong: A cache hit never touches the network, so nothing is retried.
Q12
A job is slow because the API allows 10 requests per 5 seconds per client. A colleague suggests running three copies of the script at once. What happens?
A) It finishes three times faster
B) The limit applies to you, so the copies hit 429 three times as often and the job is no faster
C) Each copy gets its own 10 per 5 seconds
D) The server queues the extra requests politely
Why: The limit counts the client (the key, or the address). Parallel copies share it; on a public service this looks like abuse.
A is wrong: The allowance does not grow with the number of copies.
C is wrong: The copies send the same key from the same machine: one client.
D is wrong: Over the limit, the answer is 429, not a queue.

Warm-up and Exit Ticket Answers

Warm-up (retrieval from Session 17)
  1. Which Beautiful Soup method returns None when nothing matches? Answer: select_one() (and find()). select() and find_all() return a list, empty when nothing matches.
  2. Why does get_soup() pass resp.content, not resp.text? Answer: From bytes, Beautiful Soup reads the page's own <meta charset>, so the text decodes correctly whatever the server said.
  3. How does a pagination loop know it has reached the last page of the catalog? Answer: There is no a.next link on the last page, so select_one("nav.pagination a.next") returns None.
  4. requests sees an empty list where the browser shows deals. What do you try before Selenium? Answer: Find the data file the page loads (Network tab or the script) and request it directly, if allowed.
  5. Why WebDriverWait(...).until(...) instead of time.sleep(), and where does driver.quit() go? Answer: The wait continues as soon as the condition is true and raises clearly if it never is. quit() goes in a finally block.
Exit ticket
  1. What is the difference between a 401 and a 403, and what does your program do with each? Answer: 401: no valid credential (missing, malformed, expired): fix how you send it, or renew an expired token and retry once. 403: understood and refused: stop; a person must fix the key or permission.
  2. The server answers 429 with Retry-After: 5. What does your client do? Answer: Wait at least 5 seconds, then send the request again (with a maximum number of tries). Better still: pace requests so this rarely happens.
  3. Name one failure that must NOT be retried, and say why. Answer: Any of 400, 401 (except an expired token, once), 403, 404: they describe the request, so the same request gets the same answer.

What wrong answers reveal. 401 and 403 swapped: redo predict item 1 at the start of Session 19's warm-up. "Retry immediately" for a 429: the cost to the server has not landed. "Retry everything": the difference between the request and the server's mood needs one more example.
