Session Goals

  • keep keys and passwords out of code, output and logs

  • log in for a bearer token, use it, and renew it once when it expires
  • follow next to the end of a paginated API and check the result
  • read rate-limit headers, pace requests, and honor 429 and Retry-After

The six ground rules (every Module 6 session starts here)
  1. Read robots.txt and obey it. It is the owner's published request to programs: where they may go and how fast.
  2. Read the terms of use. If they forbid automated collection, the answer is no, however easy the code would be.
  3. Prefer an API or a download when one exists. It is the front door.
  4. Go slowly and say who you are. Pause between requests; send a User-Agent with a way to contact you.
  5. Never go around a login, a paywall or a block. If you are asked to stop, stop.
  6. Do not collect personal data. Names, emails, profiles and photos of real people are protected by law in many places.

Lessons

6.4

API Authentication

Key ideas
  • Secrets live in the environment, not in code: os.environ.get("PINECREST_API_KEY"). Print a hint (pine...), never the value.
  • The key goes in the header the documentation names (X-API-Key), never in the URL.
  • 401: "I cannot tell who you are" (missing, malformed or expired credential). 403: "I understood, and the answer is no." Never retry a 403.
  • Turn error bodies into an exception that keeps status, code and message (ApiError), so code can decide by status what to do next.
  • Log in with requests.post(url, json={...}). Send the token as Authorization: Bearer <token>.
  • Tokens expire. On token_expired, log in again and repeat the request once; anything else surfaces.
  • Ask for one record first to learn the size of the job. Then follow next until it is None, sending the filters only with the first request.
  • Check what you collected: the promised total, unique ids, the date range, and the source when you have it.

6.5

Rate Limiting and Retries

Key ideas
  • A rate limit is the owner's rule: so many requests per window per client. X-RateLimit-Limit, -Remaining, -Reset tell you where you stand.
  • Plan A: pace yourself. Interval = window ÷ allowance × 1.1. A Throttle sleeps only for what is left.
  • Plan B: obey 429. Wait Retry-After seconds (with a default), retry, with a maximum number of tries.
  • Retry only what is temporary: 429, 500, 502, 503, 504, timeouts, dropped connections. Never 400, 403, 404.
  • Exponential backoff (0.5, 1, 2, 4, 8 s, capped) plus jitter (a random wait below that ceiling).
  • urllib3's Retry on an HTTPAdapter mounted on a Session does this for you; retry only GET and HEAD.
  • Cache: same request, same file. Check the status before writing, so errors are never cached.
  • Resumable jobs: one file per page, skip files that exist, write to .part then rename.
  • Log milestones and problems; never log a key, a token or a password.
Worked example: plan the job before you run it

Question: how long will a download take at a polite pace? Three services, three limits:

for limit, per, pages in [(10, 5, 21), (30, 10, 204), (5000, 3600, 100_000)]:
    gap = per / limit * 1.1
    print(f"{limit:>5} per {per:>4} s -> one every {gap:.2f} s; "
          f"{pages:>7,} requests: {pages * gap:>7,.0f} s ({pages * gap / 3600:.1f} h)")
   10 per    5 s -> one every 0.55 s;      21 requests:      12 s (0.0 h)
   30 per   10 s -> one every 0.37 s;     204 requests:      75 s (0.0 h)
 5000 per 3600 s -> one every 0.79 s; 100,000 requests:  79,200 s (22.0 h)

Twenty-one requests take twelve seconds; 100,000 requests at 5,000 an hour take 22 hours. Know that before you press run.

Glossary

API key: a long secret string that identifies your program to an API; sent in a header such as X-API-Key.

Environment variable: a named setting of the terminal session (PINECREST_API_KEY), read with os.environ.

401 Unauthorized: no valid credential: missing, malformed or expired.

403 Forbidden: the credential was understood and refused.

POST: the method that sends data in the request body; json= encodes a dictionary as JSON.

Bearer token: a short-lived credential from a login, sent as Authorization: Bearer <token>.

ApiError: the lesson's exception carrying status, code and message from the API's error body.

Rate limit: the owner's rule for how many requests one client may send per window.

429 Too Many Requests: over the limit; Retry-After says how long to wait.

Throttle: an object that keeps requests at least a set interval apart.

Exponential backoff: waiting longer after each failure (0.5, 1, 2, 4 s...), up to a cap.

Jitter: randomness added to backoff so clients do not retry in waves.

Cache: a saved copy of a response, used instead of asking again.

Resumable job: a download that saves each piece as it arrives and skips finished pieces on restart.
