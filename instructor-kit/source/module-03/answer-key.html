1.4 · Random Number Generation: self-check

Q1
What does this print?
a = np.random.default_rng(5)
b = np.random.default_rng(5)
x = a.integers(0, 100, size=3)
y = a.integers(0, 100, size=3)
z = b.integers(0, 100, size=3)
print(np.array_equal(x, y), np.array_equal(x, z))
A) True True
B) False True
C) True False
D) False False
Why: A generator moves forward with every draw, so the second draw from a is the next three numbers, not the same three. b has the same seed and has not been used yet, so its first draw repeats a's first draw.
A is wrong: The seed fixes where the sequence starts, not what every later draw returns.
C is wrong: It is the other way round: the same generator gives new numbers, and a fresh generator with the same seed repeats them.
D is wrong: Two generators with the same seed always produce the same sequence.
Q2
Which line rolls ten ordinary six-sided dice (values 1 to 6)?
A) rng.integers(1, 6, size=10)
B) rng.random(6, size=10)
C) rng.choice(6, size=10)
D) rng.integers(1, 7, size=10)
Why: rng.integers(low, high) leaves out the upper end, like range and slicing, so 1 to 6 needs a high of 7 (or endpoint=True).
A is wrong: That draws 1 to 5: a die with five faces, and no error to warn you.
B is wrong: rng.random draws floats from 0 up to 1 and takes only a size; this call raises a TypeError.
C is wrong: rng.choice(6, ...) draws from 0 to 5.
Q3
What does this print?
d = np.arange(5)
r = np.random.default_rng(0).shuffle(d)
print(r, np.sort(d))
None [0 1 2 3 4]
Why: shuffle rearranges the array in place and returns None, so r is None. The array d still holds the same five values in a new order; sorted, they are 0 to 4 again.
Q4
orders has n rows. Which line chooses 50 different rows to audit?
A) rng.choice(n, size=50, replace=False)
B) rng.choice(n, size=50)
C) rng.integers(0, 50, size=n)
D) rng.permutation(50)
Why: With a whole number n, choice draws row positions from 0 to n - 1, and replace=False guarantees no position comes up twice.
B is wrong: The default is WITH replacement, so the same row can be drawn twice and you may audit fewer than 50 different orders.
C is wrong: That draws n numbers between 0 and 49: the wrong count and the wrong range.
D is wrong: That is the numbers 0 to 49 in random order: always the first fifty rows of the file.
Q5
A simulation of 1,000,000 days says a store runs out of gift bags on 4.5% of days, and the estimate barely moves from run to run. The model assumed exactly 485 visitors every day. What is the best reading?
A) The answer is correct, because a million simulations cannot be wrong
B) The answer is useless, because the numbers were random
C) The estimate is precise, but it is only as true as the model; a better model of visitors could change it a lot
D) Run ten million simulations to remove the effect of the assumption
Why: More simulations make an estimate more precise. Only a better model makes it more true. In the lesson, drawing each day's visitors from the real counts moved the answer from about 4.5% to about 28%.
A is wrong: Stability tells you about the luck of the draw, not about whether the model describes the store.
B is wrong: Random draws from a stated model give a perfectly usable estimate of that model's answer.
D is wrong: The assumption is in the model, not in the sample size. Ten million runs would give the same wrong 4.5%, to more decimal places.
Q6
What does this print?
s = np.random.default_rng(3).integers(1, 4, size=(1000, 2))
print(s.shape, s.min(), s.max())
(1000, 2) 1 3
Why: size can be a shape, so this is a table of 1,000 rows and 2 columns. The upper end is left out, so the values are 1, 2 and 3; with two thousand draws both ends are certain to appear.

1.4 · Random Number Generation: predict, then run

P1
What does this print?
r = np.random.default_rng(9)
first = r.random(3)
r = np.random.default_rng(9)
second = r.random(3)
third = r.random(3)
print(np.array_equal(first, second), np.array_equal(second, third))
True False
Why: Re-creating the generator with the same seed goes back to the first page, so second repeats first. Drawing again without re-creating it moves the bookmark on, so third is new.
P2
What does this print?
r = np.random.default_rng(1)
picks = r.choice(4, size=4, replace=False)
print(np.sort(picks), picks.sum())
[0 1 2 3] 6
Why: Four different values drawn from 0, 1, 2, 3 must be all four of them, in some order. Sorted they are [0 1 2 3] and they always add up to 6, whatever the seed.
P3
This line fails. Predict the kind of error and what the message says.
np.random.default_rng(2).choice(np.array(["A", "B", "C"]), size=5, replace=False)
ValueError: Cannot take a larger sample than population when replace is False
Why: There are only three values, and you cannot draw five different ones. Ask for at most three, or allow repeats by leaving replace at its default.

1.5 · Linear Algebra Essentials: self-check

Q7
What does this print?
u = np.array([2, 0, 1])
v = np.array([10, 5, 3])
print(u @ v, u * v)
A) 23 [20 0 3]
B) [20 0 3] 23
C) 23 23
D) A ValueError, because @ needs 2-D arrays
Why: @ multiplies matching positions and adds them up: 20 + 0 + 3. * multiplies position by position and keeps the shape.
B is wrong: The two results are the right ones in the wrong order: @ gives the single number.
C is wrong: * never adds anything up; you would need .sum().
D is wrong: Two 1-D arrays of the same length are exactly what a dot product takes.
Q8
X has shape (100, 3) (100 days, 3 features) and w has shape (3,). What is the shape of X @ w?
A) (100, 3)
B) (100,)
C) (3,)
D) It fails, because the shapes are different
Why: A matrix times a vector takes the dot product of every row with the vector: one number per row, so 100 predictions.
A is wrong: That is the shape of X * w, which broadcasts and keeps the table.
C is wrong: The 3 is the inner number that has to match; it is the one that disappears.
D is wrong: The row length (3) matches the vector's length (3), which is all @ needs.
Q9
What does this print?
A = np.array([[1, 2],
              [3, 4]])
print(A @ np.array([1, 1]), A.T[0])
[3 7] [1 3]
Why: Each row dotted with [1, 1] is that row's sum: 3 and 7. .T swaps rows and columns, so the first row of the transpose is the first column of A: 1, 3.
Q10
A least-squares fit with the columns (ones, visitors, sale day) returns the coefficients [189.11, 20.34, 2502.17]. What does the model predict for a sale day with 400 visitors?
print((np.array([1, 400, 1]) @ np.array([189.11, 20.34, 2502.17])).round(2))
A) 8325.11
B) 8136.0
C) 10827.28
D) 2711.62
Why: A prediction is the row of feature values dotted with the coefficients: 1 × 189.11 + 400 × 20.34 + 1 × 2502.17.
A is wrong: That leaves out the sale-day coefficient: it is the prediction for an ordinary day with 400 visitors.
B is wrong: That is 400 × 20.34 alone: no intercept and no sale-day term.
D is wrong: That adds the three coefficients without multiplying by the feature values.
Q11
What does this print?
print(np.linalg.norm(np.array([6.0, 8.0])),
      np.linalg.norm(np.array([1.0, 1.0]) - np.array([4.0, 5.0])))
10.0 5.0
Why: A norm is a length: the square root of 36 + 64 is 10. The distance between two vectors is the norm of their difference, [-3, -4], which is 5.
Q12
You look for the product most like a given one by distance over two columns: price (in the hundreds) and weight in kilograms (single digits). The "nearest" product has almost the same price and twice the weight. What is the fix?
A) Use * in place of @ when computing the distance
B) Add a column of ones to the table
C) Sort the table by price first
D) Standardize each column (subtract its mean, divide by its standard deviation) before measuring distance
Why: A distance adds up differences across columns, so the column with the biggest numbers dominates. Putting every column on one scale lets each feature pull equal weight.
A is wrong: The operator is not the problem; the scales of the columns are.
B is wrong: A column of ones gives a least-squares model its intercept. It does nothing for a distance.
C is wrong: Sorting changes the order of the rows, not the distances between them.

1.5 · Linear Algebra Essentials: predict, then run

P1
What does this print?
M = np.array([[1, 0, 2],
              [0, 3, 1]])
w = np.array([10, 1, 5])
print(M @ w, (M * w).shape)
[20  8] (2, 3)
Why: @ takes the dot product of each row with w: 10 + 0 + 10 and 0 + 3 + 5. * broadcasts the row of three across both rows and keeps the (2, 3) shape.
P2
What does this print?
a = np.array([[2.0, 0.0],
              [0.0, 4.0]])
print(np.linalg.solve(a, np.array([6.0, 8.0])))
[3. 2.]
Why: The two equations are 2 × first = 6 and 4 × second = 8, so the unknowns are 3 and 2. Check: a @ [3, 2] gives [6, 8].
P3
This line fails. Say why, using the shape rule, before you run it.
np.ones((2, 3)) @ np.ones((2, 3))
ValueError: matmul: Input operand 1 has a mismatch in its core dimension 0, with gufunc signature (n?,k),(k,m?)->(n?,m?) (size 2 is different from 3)
Why: (2, 3) @ (2, 3): the inner numbers are 3 and 2, and they must match. The end of the message says so. Transposing the second matrix, (2, 3) @ (3, 2), would work and give (2, 2).

Lab Reference Solutions

Every lab has a runnable _solution.py next to its starter in labs/module-03/. The notes give what a correct run prints, the lines that matter and why, and the wrong results you are most likely to see. Check all eight files with python3 labs/check_labs.py module-03.

Lab 1.4-A: labs/module-03/l1_4-random-generation/mystery_shopper_starter.py → mystery_shopper_solution.py

Reference output (seed 7): 361 Flagstaff rows in 2025; pilot stores: ['Boise' 'Flagstaff']; shopper dates 2025-01-02, 01-20, 03-23, 04-14, 04-19, 07-02, 07-24, 10-03, 10-24, 11-11, 11-13, 11-26; weekend days among them: 2 of 12; same schedule from the same seed: True; group sizes: 2032 871; mean visitors: 356.8 and 353.8 | all rows: 355.9.

The solution's key lines:

rng = np.random.default_rng(7)
pilot = rng.choice(store_names, size=2, replace=False)
picks = rng.choice(flagstaff_2025, size=12, replace=False)     # row positions, no repeats
print(np.sort(dates[picks]), (weekday[picks] >= 5).sum())
order = rng.permutation(visitors.size)
group_a, group_b = order[:cut], order[cut:]

Why: flagstaff_2025 holds row positions (the starter builds it with np.flatnonzero, which returns the positions where a mask is True), so one draw of positions can index dates, weekday and anything else. Reproducing the schedule needs a new generator with the same seed AND the same draws in the same order: the pilot draw has to be repeated before the dates, or the bookmark is in a different place.

Common wrong results: different dates from a neighbor's (an extra or repeated draw; a different seed); False in Step 4 (only the second draw was repeated); 3 or more weekend days "expected" (2 of 12 is well within what chance gives when 2 days in 7 are weekend days); group means reported as proof that the split "worked" or "failed" (similar and not identical is exactly what a random split looks like).

Lab 1.4-B: labs/module-03/l1_4-random-generation/returns_desk_starter.py → returns_desk_solution.py

Reference output (seed 14): 731 days | 1143 returned orders | first ten days: [1 1 1 2 3 1 0 1 0 4]; average returns per day: 1.564; 4 or more returns: simulated 7.4% | real 7.3%; no returns at all: simulated 21.1% | real 20.7%; mean and variance of the real counts: 1.56 1.52; 40 or more orders: simulated 1.7% | real 7.3%; mean and variance of real orders per day: 27.77 64.35.

The solution's key lines:

rate = returns_per_day.mean()
sim = rng.poisson(lam=rate, size=100_000)              # model + repeat, in one call
print((sim >= 4).mean(), (returns_per_day >= 4).mean())    # count, and check against reality
sim_orders = rng.poisson(lam=orders_per_day.mean(), size=100_000)
print((sim_orders >= 40).mean(), (orders_per_day >= 40).mean())

Why: a Poisson describes counts of events that happen at a steady average rate. Returned orders per day behave that way (the real mean and variance are nearly equal, as a Poisson's are), so the simulation agrees with the real days to within a few tenths of a point. Orders per day do not: weekends, seasons and sale days make busy days far more common than a single rate allows, and the real variance is more than twice the mean. The same code gives a trustworthy answer to one question and a wrong one to the other, and only the comparison with real data tells you which.

Notes for the debrief: "returns per day" here means how many of the orders PLACED on a day were later returned, because the data records an order's date and its final status. Small differences in the last digit are possible if a learner draws in a different order; the conclusions do not change. Common wrong results: a loop of 100,000 calls to rng.poisson(rate) (correct but slow: ask for size=); (sim > 4) instead of >= 4 (2.2% instead of 7.4%); concluding the model is "bad" from Step 6 alone, when it was a good model for the question it was built for.

Lab 1.5-A: labs/module-03/l1_5-linear-algebra/payroll_receipt_starter.py → payroll_receipt_solution.py

Reference output: the week-1 staff table (first row [4. 5. 6. 3.], Saturday [ 8. 7. 10. 5.]); 234 rated products | 17050 reviews; plain average rating 4.138, weighted 4.146; payroll per day: [3172. 2816. 2820. 2996. 4036. 5276. 4396.] (7,); shape (7, 2); week total, current and proposed: [25512. 27252.]; first column equals Part 2: True; payroll per store: [5880. 5984. 8832. 4816.] | total 25512.0; staff-days per store: [35. 34. 48. 28.]; hourly rates (lead, seller, trainee): [22. 19. 17.]; check True.

The solution's key lines:

weighted = rating @ reviews / reviews.sum()     # (234,) @ (234,) -> one number
payroll_per_day = week @ day_cost               # (7, 4) @ (4,)   -> (7,)
both = week @ pay_scales                        # (7, 4) @ (4, 2) -> (7, 2)
per_store = (week * day_cost).sum(axis=0)       # * keeps (7, 4); then collapse the days
rates = np.linalg.solve(hours, payroll)         # (3, 3) and (3,) -> (3,)

Why: each part is the receipt from a different side. Part 4 is deliberately a *: "per store" needs each store's column weighted by its own cost and then the days collapsed, which is a broadcast and an axis=0 sum, not a matrix product; day_cost @ week fails because the inner numbers are 4 and 7. The check in Part 5 puts the answer back into the original equation. The daily costs, pay scales and the pop-up stall's hours are made-up planning figures; the staff counts and ratings are the course data.

Common wrong results: a weighted "average" in the tens of thousands (not divided by reviews.sum()); a (7, 4) table for Part 2 (*); [25512. 27252.] reported as "per day" (that is the week total, the (7, 2) table summed over the days); rates that fail the check because payroll and hours were swapped in solve.

Lab 1.5-B: labs/module-03/l1_5-linear-algebra/basket_model_starter.py → basket_model_solution.py

Reference output: 724 days | mean transactions 77.8 | mean revenue 6889.75; A1 shape: (724, 2); revenue = 117.23 + 87.10 * transactions; transactions only: RMSE $631.35, R squared 0.945; average dollars per purchase (revenue / transactions): 88.77; intercept 89.82, per purchase 87.52, sale day -172.09; with sale days: RMSE $630.73, R squared 0.945; quiet day $5,341.19, busy ordinary day $8,842.11, sale day $13,046.16, each give or take about $631.

The solution's key lines:

A1 = np.column_stack([np.ones(x.size), x])
coef1, *_ = np.linalg.lstsq(A1, y)
print(np.mean(y / x).round(2))                      # a second route to the slope
A2 = np.column_stack([np.ones(x.size), x, is_promo])
coef2, *_ = np.linalg.lstsq(A2, y)
forecast = scenarios @ coef2

Why: the slope ($87.10 per additional purchase) and the directly computed basket value ($88.77) are two routes to nearly the same number; they differ a little because the fitted line also has an intercept. The fit is tight (R squared 0.945) because revenue is, almost by definition, purchases times what a purchase is worth. The sale-day coefficient is small and negative and the RMSE barely moves: once you know how many purchases there were, knowing it was a sale day adds nothing. That is an honest "this column did not earn its place", and it agrees with Session 2's finding that sale days bring more buyers, not bigger baskets.

Common wrong results: [nan nan] (the mask was dropped and the missing Flagstaff revenue got in); a single coefficient near 88 (no column of ones); the sale-day coefficient read as "sales lose $172" (it is within the noise: compare the two RMSE figures); forecasts computed one at a time by hand instead of with one @ (not wrong, but ask for the matrix).

The Lesson Pages' Own Quick Quizzes

Each lesson page ends with a five-question Quick Quiz (three options each). Learners do them at home; these are the answers with the page's own explanation.

Lesson 1.4 · Random Number Generation
  1. Question 1. What does this print? 
    r1 = np.random.default_rng(7)
r2 = np.random.default_rng(7)
print(np.array_equal(r1.integers(0, 100, size=3), r2.integers(0, 100, size=3)))
    Answer: C) True. Two generators created with the same seed start at the same point of the same sequence, so the same request returns the same numbers. That is what makes random results reproducible.
  2. Question 2. Which values can rng.integers(1, 7, size=5) produce?
    Answer: B) 1, 2, 3, 4, 5 or 6. The lower end is included and the upper end is left out, the same convention as range(1, 7). This is the correct way to roll a six-sided die.
  3. Question 3. skus is an array of 242 product codes. Which line picks 5 different products at random?
    Answer: A) rng.choice(skus, size=5, replace=False). replace=False means a drawn item is not put back, so the five results are guaranteed to be distinct.
  4. Question 4. You create rng = np.random.default_rng(42) in one notebook cell. In the next cell you run print(rng.random()) three times and see three different numbers. Why?
    Answer: B) The generator moves forward through its sequence with every draw; the seed only fixes where it starts. Each draw advances the generator, so the next request returns the next numbers. Re-creating the generator with the same seed starts the sequence again.
  5. Question 5. A simulation of 100 days estimates a probability as 0.07. The same simulation with 1,000,000 days gives 0.0449. What is the best reading?
    Answer: A) Trust 0.0449 more: estimates from more simulations vary less. This is the law of large numbers. With 100 days each single day moves the estimate by a whole percentage point, while a million days pin it down to about three decimal places.
Lesson 1.5 · Linear Algebra Essentials
  1. Question 1. What does this print? 
    q1u = np.array([1, 2, 3])
q1v = np.array([4, 5, 6])
print(q1u @ q1v)
    Answer: B) 32. The dot product multiplies matching positions and adds the results: 1 times 4, plus 2 times 5, plus 3 times 6. Two vectors in, one number out.
  2. Question 2. X has shape (5, 3) and W has shape (3, 2). What is the shape of X @ W?
    Answer: A) (5, 2). The inner numbers, 3 and 3, match, so the multiplication works, and the result keeps the outer numbers: the rows of the left matrix and the columns of the right one.
  3. Question 3. Why is np.linalg.solve(A, b) preferred to np.linalg.inv(A) @ b?
    Answer: C) Because it is faster and loses less accuracy, since it never builds the inverse. solve goes straight to the answer. Computing the full inverse first is extra work, and each extra step adds rounding error.
  4. Question 4. A least-squares fit uses the matrix np.column_stack([np.ones(n), x]). What is the column of ones for?
    Answer: A) It gives the model an intercept, so the line is not forced through zero. The coefficient that multiplies the ones is added to every prediction, which is exactly what an intercept does. Without it the line must pass through the origin.
  5. Question 5. What does this print? 
    q5 = np.array([3.0, 4.0])
print(np.linalg.norm(q5))
    Answer: B) 5.0. The norm is the square root of the sum of squares: 9 plus 16 is 25, and the square root of 25 is 5. It is the length of the vector, by the Pythagorean theorem.

Warm-up Answers

W1
big = revenue > 15000. What does big.sum() tell you? And big.mean()?
How many store-days are above $15,000, and what fraction of all store-days that is.
W2
Write a mask for "Boise and a sale day", given the parallel arrays stores and promo.
(stores == "Boise") & (promo == 1): &, with parentheses around each comparison.
W3
table has shape (224, 4): days by stores. What is the shape of table.sum(axis=1) and what does it hold?
(224,): one total per day. The axis you name (the 4 stores) disappears.
W4
State the two broadcasting rules.
Line the shapes up from the right, a missing entry counting as 1. Each pair of lengths must be equal, or one of them 1; the result takes the larger.
W5
How do you divide every row of that table by its own row total?
table / table.sum(axis=1, keepdims=True): the totals must stand as a column of shape (224, 1).

Exit Ticket

E1
You run a cell that draws from rng twice and get different numbers. Is the code broken? What makes a random result reproducible?
No. The generator moves forward with every draw. Reproducible means the same code, run from the top (from where the seeded generator is created), gives the same result.
E2
orders has shape (3, 3) (orders by products) and prices has shape (3,). What is the difference between orders * prices and orders @ prices?
* multiplies position by position and keeps the shape: a (3, 3) table of line totals. @ multiplies and adds: three order totals, shape (3,).
E3
A fit of revenue on visitors gives a slope of 21.39. Write the sentence a manager should hear, and one caution.
Each additional visitor goes with about $21 more revenue. It describes a pattern across days: it is not a promise about one more visitor, and a forecast should be quoted with its typical miss (the RMSE).
