Lessons

5.1

Database Connections

Key ideas
  • A database answers questions and returns only what you ask for. SQL is the language of the request. SQLite is a complete database engine in one file; Python includes it as sqlite3.
  • Work on a copy (shutil.copy) or open the file read-only, so the original stays as documented.
  • Connection, cursor, rows. sqlite3.connect() gives a connection. Running a statement gives a cursor that walks forward through the result. Rows come back as tuples; fetchone(), fetchmany(n), fetchall().
  • One statement does most of the work: SELECT ... FROM ... WHERE ... GROUP BY ... HAVING ... ORDER BY ... LIMIT, always written in that order. The engine runs it starting from FROM: FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, LIMIT.
  • WHERE filters rows before grouping; HAVING filters groups after it. Every selected column is either in the GROUP BY or inside an aggregate.
  • Three COUNTs: COUNT(*) rows, COUNT(col) rows where col is not NULL, COUNT(DISTINCT col) different values.
  • Values go in through placeholders (? with a tuple, or :name with a dictionary). Never with an f-string, .format(), % or +. A one-item tuple needs its comma: ("Boise",).
  • Changes are saved only on commit. with conn: commits if the block finishes and rolls back if it raises: all or nothing.
  • SQLAlchemy gives one way to talk to any database: create_engine(url), with engine.connect() as c:, text("...") with :name parameters.
  • pd.read_sql(query, connection, params=...) brings a result into a DataFrame; df.to_sql(name, engine, if_exists=..., index=False) saves one as a table. Let the database do the heavy filtering and grouping.
Worked example: a report function with parameters

Marketing asks, for any year: how many completed orders used each promo code, and what was the average order? The year changes, so it travels through params. (The f-strings build the two date VALUES from an integer; the SQL text itself is fixed. conn is the lesson's connection.)

def promo_report(conn, year):
    """Orders and average total for each promo code in one calendar year."""
    sql = """
        SELECT promo_code,
               MAX(discount_pct)          AS discount_pct,
               COUNT(*)                   AS orders,
               ROUND(AVG(order_total), 2) AS avg_total
        FROM orders
        WHERE status = 'completed'
          AND order_date >= :start AND order_date < :end
        GROUP BY promo_code
        HAVING COUNT(*) >= 100
        ORDER BY orders DESC
    """
    params = {"start": f"{year}-01-01", "end": f"{year + 1}-01-01"}
    return pd.read_sql(sql, conn, params=params)

print(promo_report(conn, 2025))

Reading it. The first row has no promo code: NULL is its own group, and pandas shows it as NaN. Most orders use no code. HAVING COUNT(*) >= 100 removed the smaller groups after grouping. The averages fall as the discount rises (SUMMIT20 orders average $141.76), partly because order_total is the amount AFTER the discount: compare like with like before you conclude anything about basket size. Call promo_report(conn, 2024) and the same function answers for another year, with no SQL rewritten.

5.2

Complex Queries

Key ideas
  • A join pairs rows by key. Join types differ only in what happens to a row with no partner.
  • JOIN (inner) keeps matched pairs only and drops the rest without telling you. LEFT JOIN keeps every row of the first table, with NULL where there is no partner.
  • The anti-join answers "which ones are missing?": LEFT JOIN ... WHERE right.key IS NULL. NOT EXISTS does the same job.
  • Count after every join. Four numbers to remember: 739 orders have no customer row; 1,058 customers never ordered; 609 order lines have no product row; 8 products never sold.
  • The fan-out trap: joining to a "many" side repeats the "one" side. Sum a column at the level where it lives; when you need two levels, aggregate first (a subquery or CTE), then join.
  • Subqueries return a value, a list or a table depending on where they sit. CTEs (WITH name AS (...)) give the steps names, so a long query reads top to bottom.
  • A recursive CTE (anchor, UNION ALL, recursive part) walks a hierarchy of any depth. It stops when a round finds no new rows.
  • CASE is if / elif / else. Inside SUM or COUNT it makes side-by-side columns. Multiply by 100.0, not 100, or integer division gives you zeros.
  • NULL means unknown. = NULL never matches (use IS NULL); a condition and its opposite do not add up to everything; NOT IN with a NULL in the list returns nothing. COALESCE(x, y) is the SQL fillna.

Worked example: return rate by loyalty tier, with every order accounted for

Does the return rate differ by the customer's loyalty tier? The tier is in customers, the status in orders. An inner join would quietly leave out the 739 orders from closed accounts, so this uses a LEFT JOIN and names those rows with COALESCE. (conn and show are the lesson's.)

show("""
    SELECT COALESCE(c.loyalty_tier, '(closed account)') AS tier,
           COUNT(*)                                     AS orders,
           SUM(CASE WHEN o.status = 'returned' THEN 1 ELSE 0 END) AS returned,
           ROUND(100.0 * SUM(CASE WHEN o.status = 'returned' THEN 1 ELSE 0 END)
                 / COUNT(*), 1)                         AS return_pct
    FROM orders AS o
    LEFT JOIN customers AS c ON c.customer_id = o.customer_id
    GROUP BY tier
    ORDER BY orders DESC
""")
show("""
    SELECT COUNT(*) AS rows_with_inner_join
    FROM orders AS o
    JOIN customers AS c ON c.customer_id = o.customer_id
""")
            tier  orders  returned  return_pct
            Gold    8491       403         4.7
          Silver    7132       383         5.4
           Basic    3940       316         8.0
(closed account)     739        41         5.5
 rows_with_inner_join
                19563

Reading it. The orders column adds up to 20,302: every order is counted once. The second query shows what an inner join would have kept: 19,563. Basic customers' orders come back 8.0% of the time against 4.7% for Gold. Before calling that a finding, ask how the tier is made: it is earned from COMPLETED spend, and a returned order does not count. A customer who returns a lot is held in a lower tier, so the tier partly reflects returns rather than causing them. SQL got the numbers right; the reading needs Lesson 4.4's question: how was this data generated? The pattern to keep: LEFT JOIN from the table you care about, COALESCE to name the unmatched, conditional aggregation for the rate, and a row-count check at the end.

Glossary

SQL: the language for asking a relational database for data. SQLite: a complete SQL database engine that lives in one file; included in Python as sqlite3. Connection: an open line from your program to a database. Cursor: a pointer that runs one statement and walks forward through its result. Aggregate function: a function that turns many rows into one value: COUNT, SUM, AVG, MIN, MAX. GROUP BY: split rows into groups and return one row per group. HAVING: a filter on groups, applied after GROUP BY. Placeholder: a ? or :name in the SQL text where a value will be supplied separately. SQL injection: an attack in which text supplied as a value becomes part of the SQL command. Transaction: a batch of changes that is saved all together (commit) or not at all (rollback). Engine (SQLAlchemy): an object made from a database URL that hands out connections. Key: a column whose value identifies a row, or points at a row in another table. Inner join: keeps only rows that found a partner. Left join: keeps every row of the first table; unmatched rows get NULL on the other side. Anti-join: the rows of one table that have no partner in another. Fan-out: the repetition of "one"-side rows when joined to a "many" side; it inflates sums. Subquery: a SELECT in parentheses inside another query. CTE: common table expression: a named query defined with WITH and used like a table in the statement that follows. Recursive CTE: a CTE that refers to itself to walk a hierarchy level by level. CASE: SQL's if / elif / else expression. NULL: the marker for an unknown or missing value; comparisons with it are unknown. COALESCE: returns its first argument that is not NULL.
