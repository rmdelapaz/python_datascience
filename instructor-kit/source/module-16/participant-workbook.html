5.5

NoSQL with MongoDB

Key ideas
  • A document is one record that can hold nested objects and lists: one website visit with its device, its pages and its cart. A collection is a set of documents, and they need not all have the same fields.
  • A query is a dictionary: {"converted": True}. Several pairs mean AND. Reach inside nested objects with dot notation in quotes: "device.type".
  • Anything other than "equals" uses an operator that starts with $: {"cart.value": {"$gte": 500}}, $in, $exists, $regex.
  • Missing is not null. In a query, None matches both. {"$exists": False} asks precisely "is the field absent?"
  • A condition on a list field ("pages.path") is true when any element matches. Two conditions on the same element need $elemMatch.
  • The aggregation pipeline is a list of stages. $match filters (WHERE, or HAVING after a group), $group summarizes (GROUP BY), $unwind makes one document per list element (pandas explode), $sort and $limit order and cut.
  • Inside a pipeline, a field's value is written with a leading dollar: "$device.type". In a query, the field name is just the key, with no dollar.
  • A wrong field name does not raise an error. It returns zero. Be suspicious of zero: look at one document with find_one() first.
  • Finish in pandas: pd.DataFrame(list(cursor)) for flat results, pd.json_normalize(docs) for nested ones.

Step 2. The same audience, grouped in one pipeline. $ifNull supplies a label when the campaign is missing; $cond inside $sum counts only the sessions that converted. The percentage is finished in pandas.

rows = list(web.aggregate([
    {"$match": news},
    {"$group": {"_id": {"$ifNull": ["$utm.campaign", "(no campaign)"]},
                "sessions": {"$sum": 1},
                "orders": {"$sum": {"$cond": ["$converted", 1, 0]}},
                "avg_cart": {"$avg": "$cart.value"}}},
    {"$sort": {"sessions": -1}},
]))
table = pd.DataFrame(rows).rename(columns={"_id": "campaign"})

table["order_pct"] = (100 * table["orders"] / table["sessions"]).round(1)

6.1

HTTP with Requests

The six ground rules (every session of Module 6 starts here)
  1. Read robots.txt and obey it. It is the owner's published request to programs: where they may go and how fast.
  2. Read the terms of use. If they forbid automated collection, the answer is no, however easy the code would be.
  3. Prefer an API or a download when one exists. It is the front door.
  4. Go slowly and say who you are. Pause between requests; send a User-Agent with a way to contact you.
  5. Never go around a login, a paywall or a block. If you are asked to stop, stop.
  6. Do not collect personal data. Names, emails, profiles and photos of real people are protected by law in many places.
Key ideas
  • HTTP is request and response. Out: a method (GET to read), a URL, headers, maybe a body. Back: a status code, headers, a body.
  • Status codes by first digit: 2xx success, 3xx look elsewhere (handled for you), 4xx your request has a problem, 5xx the server has a problem.
  • A 404 or a 500 is not an exception until you call r.raise_for_status(). The pattern is: get → raise_for_status() → use the body.
  • Rules first. Fetch robots.txt, parse it with RobotFileParser, ask can_fetch() and crawl_delay().
  • Send a User-Agent that names your project and gives a contact address. Never pretend to be a browser.
  • r.content is bytes; r.text is those bytes decoded with r.encoding. Junk like â˜… means the wrong encoding: set r.encoding = "utf-8".
  • Pass query parameters as a dictionary (params=) and read JSON with r.json(). A list of flat dictionaries goes straight into pd.DataFrame.
  • Every request gets a timeout. Without one, requests waits forever.
  • A Session reuses the connection and remembers your headers (not your timeout). Save r.content to disk once; parse the saved copy as often as you like.

2xxSuccessUse the body
3xxLook elsewhereNothing: requests follows redirects
4xxYour request has a problem (400, 401, 403, 404, 429)Fix the request (429: wait first)

Worked example: does this product exist?

Question: the shop has a page for SLP-1004. Does it have one for SLP-9004? Ask the website, then ask the API, and compare how each one says "no".

Step 1. Ask the website. The function checks the status before it touches the body. For a missing page it returns the status and None: it never tries to read a title out of an error page. (Setup: BASE_URL, HEADERS, urljoin and time as in the demo.)

def product_page(sku):
    """Return (status, title) for one product page; title None if missing."""
    url = urljoin(BASE_URL, f"products/{sku}.html")
    resp = requests.get(url, headers=HEADERS, timeout=10)
    try:
        resp.raise_for_status()
    except requests.exceptions.HTTPError:
        return resp.status_code, None
    resp.encoding = "utf-8"
    html = resp.text
    title = html[html.index("<title>") + 7 : html.index("</title>")]
    return resp.status_code, title

for sku in ["SLP-1004", "SLP-9004"]:
    print(sku, product_page(sku))
    time.sleep(1)
SLP-1004 (200, 'Larkspur Ridge Backcountry Sleeping Pad | Pinecrest Outfitters (practice site)')
SLP-9004 (404, None)

Step 2. Ask the API. Same question, one line of parsing. The API answers a missing product with status 404 and a JSON body that explains itself. (API = "http://127.0.0.1:8000"; start it with python data/mock_api.py.)

for sku in ["SLP-1004", "SLP-9004"]:
    r = requests.get(f"{API}/products/{sku}", headers=HEADERS, timeout=10)
    body = r.json()
    print(sku, r.status_code, body.get("name") or body["error"]["message"])
SLP-1004 200 Larkspur Ridge Backcountry Sleeping Pad
SLP-9004 404 No product with SKU 'SLP-9004'.

Both sources agree, and neither needed you to guess: the status code told the program what happened, and the message told you.

Glossary

Document: one record in MongoDB: like a Python dictionary, and it may hold nested objects and lists.

Collection: a set of documents (the counterpart of a table). Its documents need not share a shape.

Dot notation: "device.type": the name of a field inside a nested object, written in quotes.

Operator: a key that starts with $ ($gt, $in, $exists, $set) and says how to compare or change.

Projection: the second argument of find: which fields to return (1) or leave out (0).

Aggregation pipeline: a list of stages ($match, $unwind, $group, $sort...) that each transform the documents and pass them on.

mongomock: a library that imitates a MongoDB server inside Python, with pymongo's methods. Data lives in memory only.

HTTP: the request-and-response conversation every web page and API is built on.

Status code: the three-digit summary of a response: 2xx success, 3xx look elsewhere, 4xx your request, 5xx the server.

Header: a name-and-value note that travels with a request or a response (User-Agent, Content-Type).

robots.txt: a site's published request to programs: where they may go and how fast.

Query parameters: the ?name=value&name=value part of a URL. Pass them to requests as a dictionary (params=).

Timeout: the longest requests will wait to connect, and between bytes. Without one it waits forever.

Mojibake: junk such as â˜… that appears when bytes are decoded with the wrong encoding.

API: addresses that return data (usually JSON) for programs instead of pages for people.
