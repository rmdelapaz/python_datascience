Your working notebook for the session where the calendar becomes part of your data. 2.7

Time Series

90 min solo
Key ideas
  • Dates are a ruler, not labels. Text that looks like a date has no order, no distances and no months. Parse it: pd.read_csv(..., parse_dates=["date"]) or pd.to_datetime(column). Check df.dtypes after every load.
  • .dt reads the parts of a date column: .dt.year, .dt.month, .dt.dayofweek (Monday is 0), .dt.day_name(). The new columns are ordinary columns you can group by.
  • Put dates in the index and .loc understands strings: .loc["2025-07-04"] is a day, .loc["2025-07"] a month, .loc["2025"] a year. A string range includes both ends.
  • Check against the calendar. pd.date_range(start, end, freq="D") is every day; calendar.difference(table.index) is the days you do not have; asfreq("D") gives each of them a row of NaN.
  • A gap is a decision. Closed store: a true 0. Export failed or value blank: unknown, so leave it NaN, or estimate it and say so. The data cannot tell you which is which; documentation can.
  • resample() is groupby for the calendar. Sums skip NaN without telling you, so print count beside every sum.
  • Change means "compared with an earlier row". shift(1) shows the previous row, diff() subtracts it, pct_change() divides by it. They count rows, so they mean "earlier in time" only on a complete calendar.
  • The order of operations: parse → index → complete the calendar → decide each gap → then resample, shift or compare.

2.8

Window Functions

90 min solo
Key ideas
  • A window function returns one value for every row, computed from nearby rows. groupby().agg() and resample() return one value per group.
  • rolling(n) is a fixed pane sliding down the rows: this row and the n - 1 before it. Follow it with .mean(), .sum(), .max(), .std(). Match n to the cycle you want to remove: 7 for a weekly rhythm.
  • A window must be full by default. The first n - 1 rows are NaN, and one missing value blanks n results. min_periods= relaxes that. Choose a threshold you can defend (6 of 7, 21 of 28), not 1.
  • center=True puts the row in the middle of its window, so it uses future rows. Fine for describing history; never for predicting or flagging.
  • Expanding windows only grow: cumsum() is a running total, cummax() the best so far, expanding().mean() the average so far. Year to date is a running total within each year: groupby(index.year).cumsum().
  • On a long table: sort, group, window. groupby("store")["revenue"].transform(lambda s: s.rolling(7).mean()) keeps the rows lined up. Quick test: the first rows of each group are NaN.
  • rank() gives positions. ascending=False makes the largest value rank 1; method= settles ties; pct=True gives percentiles; groupby(...).rank() ranks inside each group.
  • Look-ahead leakage: a baseline must not contain the row it judges, or anything after it. Ask of every window: "On that day, could I have known every number in it?" Shift first: s.shift(1).rolling(7).mean().

Worked example: smoothing temperatures, and a record that keeps being broken

Daily high temperatures in Boise jump around from day to day. A window makes the season visible. (This example uses data/store_weather.csv, which has no gaps, so it needs no calendar repair.)

One row per day for Boise, then a trailing 7-day mean. The first six rows have no full window yet.

boise_high = weather[weather["city"] == "Boise"].set_index("date")["high_f"]

Was July 13, 2025 unusual? Compare it with the 7 days before it, not with a window that contains it.

before = boise_high.shift(1).rolling(7).mean()
with_today = boise_high.rolling(7).mean()
day = "2025-07-13"
print(boise_high.loc[day], "| before:", round(before.loc[day], 1),

The honest baseline (the seven days before) is lower than the one that includes the day itself, so the hot day stands out more against it. Any day you want to judge has to stay out of its own baseline.

Glossary

TermMeaning
TimestampOne point in time. A datetime64 column holds one per row; it knows its year, month and weekday.
TimedeltaA length of time: what you get when you subtract two timestamps.
NaT"Not a time": the missing value for dates, as NaN is for numbers.
DatetimeIndexRow labels that are dates. It lets .loc["2024-07"] select a month and makes resample possible.
asfreqGive the table one row for every period ("D" = every day). Rows that did not exist appear as NaN.
ResampleGroupby for the calendar: drop rows into weeks, months or quarters, then aggregate each bucket.
Frequency aliasThe code for a bucket size: "D", "W", "ME", "QE", "YE", "h". The old "M", "Q", "Y", "H" raise an error.
shift / diff / pct_changeThe previous row's value beside this one; this row minus that; that change as a fraction.
Year over yearA period compared with the same period one year earlier: 12 rows back in monthly data, 4 in quarterly.
Window functionA calculation that returns one value for every row, computed from nearby rows.
Rolling windowA fixed-size window that slides down the rows: rolling(7) is this row and the six before it.
min_periodsHow many real values a window needs before it gives an answer. The default is all of them.
Expanding windowA window that starts at the first row and only grows: running totals, best so far.
Year to dateA running total that restarts each January 1: groupby(index.year).cumsum().
RankA value's position in sorted order. method= settles ties; pct=True gives a percentile.
Look-ahead leakageUsing information in a calculation that was not available at the moment the calculation describes.
