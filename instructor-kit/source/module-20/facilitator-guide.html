Session 20: Bokeh and Streamlit

How to teach the last tools session. Before the break, Bokeh: several charts looking at one table, so that selecting rows in one lights them up in the others. After it, Streamlit: an app whose controls run pandas, built on one idea, the script reruns. The session ends with the capstone kickoff: every learner chooses a question and leaves with a written plan.

2 lessons 3 hrs session Lessons 7.3–7.4 Session 20 of 21 Capstone question chosen

How to Use This Guide

  • Same rhythm, one addition. Warm-up; for each lesson a frame, a live demo, a guided kit lab and the first step of the lesson project; then, in place of the usual last stretch, a 20-minute capstone kickoff before the wrap-up.
  • The lessons are the reference. Keep visualization_bokeh.html, visualization_streamlit.html and the top of capstone_project.html open in browser tabs. Labs are in labs/module-20/.
  • Two tools, two working styles. Bokeh is demonstrated from a notebook or script that writes HTML files. Streamlit is demonstrated from an editor and a terminal: it cannot run in a notebook cell.
  • Every output in this guide is from a real run on the course data (Bokeh 3.10.0, Streamlit 1.65.0). Streamlit outputs come from its testing tool, AppTest, so you can reproduce them without a browser.
  • Checkpoint 2 is not in this session. The Modules 5 to 6 data-access checkpoint sits in Session 18. Tonight's assessment moment is the capstone plan.
The one risk of Session 20: running out of time before the kickoff

Both tools are new, both are fun, and each demo can swallow forty minutes. The capstone kickoff at 2:30 is not optional: learners who leave without a chosen question and a written plan arrive at the Session 21 studio with nothing to work on. Protect it by cutting demo steps (the lists under If You Run Long name them), never by shortening the kickoff. The second risk is conceptual and lives after the break: learners carry the notebook's mental model (variables persist) into Streamlit, where the whole script reruns. Say that sentence until they finish it for you.

Before the Session

  • ☐ Run the kit check: python3 labs/check_labs.py module-20. Expect 9 passed, 0 failed (four starters, four solutions, one pytest file). It starts no servers and opens no browser.
  • ☐ Hand out starters only (margin_brush_starter.py, category_picker_starter.py, gear_shortlist_starter.py, catalog_browser_starter.py) with labs/labs_paths.py. Keep the solutions and test_catalog_browser.py on your machine until the lab is done.
  • ☐ Versions: python -c "import bokeh, streamlit; print(bokeh.__version__, streamlit.__version__)" should print versions starting with 3 and 1. streamlit version in the terminal is the same check for learners.
  • ☐ Streamlit's first run may ask for an email address in the terminal: press Enter to skip. Do one streamlit run on the projector machine before class so the prompt does not appear live. To silence it on shared machines, create ~/.streamlit/config.toml with [browser] and gatherUsageStats = false.
  • ☐ Port 8501. streamlit run serves on http://localhost:8501. If a learner has an app still running, the next one takes 8502 and the old tab shows the old app: teach Ctrl+C early. Venue firewalls are not an issue: everything is on localhost. If the browser does not open by itself, copy the Local URL from the terminal.
  • ☐ No internet in the room? Bokeh's default mode="cdn" files open blank offline: have learners pass mode="inline" to output_file (about 1.4 to 1.8 MB per file). Streamlit works offline; its charts do too.
  • ☐ Projector: editor and terminal side by side for the second half, font 18 pt or larger; a notebook or second terminal for the AppTest checks.
  • ☐ Whiteboard: "share a range → same view", "share a source → same rows"; for after the break, "the whole script reruns".
  • ☐ Capstone: print the four questions (from Lesson 8.1, Choose Your Question) one set per table, bring sticky notes, and read the answer notes in ../../final-assessment.html beforehand so that you can ask good questions without giving anything away.
  • ☐ Skim the Session 19 homework in the warm-up: store_brief.png (four panels) and sales_explorer.html (three charts, about 174 KB).

Warm-up

0:00

Warm-up: Retrieval from Session 19

10 min
How to run it

Six minutes on paper, no notes; two minutes of answers; two for the homework check.

Five questions (with answers)
  1. Which kind of seaborn function takes ax=, and what does the other kind return? Answer: Axes-level functions (scatterplot, barplot, histplot, ...) take ax= and return that Axes. Figure-level functions (relplot, displot, catplot) make their own figure and return a FacetGrid.
  2. sns.barplot draws a black line on each bar. With default settings, what is it? Name one setting that shows spread instead. Answer: A bootstrapped 95% confidence interval for the mean (uncertainty of the estimate). errorbar="sd" or errorbar=("pi", 50) shows spread of the data.
  3. You pass 2,903 daily rows to px.bar(sales, x="store", y="revenue"). What do you get, and what should you have done? Answer: 2,903 bar segments stacked into four piles, with no error: Plotly Express does not aggregate. Group with pandas first (groupby("store", as_index=False)["revenue"].mean()), then plot four rows.
  4. monthly has one row per store and month (4 stores, 24 months). What does this print? 
    fig = px.line(monthly, x="month_start", y="revenue", color="store")
print(len(fig.data), fig.data[0].type, len(fig.data[0].x))
    Answer: 4 scatter 24: one trace per store, each a scatter trace in lines mode holding 24 points. A figure is data: you can count it before you look at it.
  5. You wrote a chart with fig.write_html("chart.html", include_plotlyjs="cdn"). Name two things that are true of that file. Answer: It is small because the reader's browser fetches plotly.js from a public server, so the reader must be online; and it contains the data you passed to the figure (every x, y and hover column) as readable text.
Homework check (2 min)

Two volunteers put sales_explorer.html on the projector. Ask the room: "Find the best single day. Now find that same day in the trend chart." Let them struggle for ten seconds. "Three charts that ignore each other. Fixing that is the first half of today."

Interactive Charts with Bokeh

65 min
Objectives (from the lesson page)
  • Build a Bokeh figure by adding glyphs (lines, markers, bars) and save it with output_file

Mental model to say (10 min frame)

"Picture your data as one large table in the middle of a room, and each chart as a window in the wall looking at that table from a different side. One window shows revenue against visitors, another shows revenue against the date. Walk in and put red stickers on thirty rows of the table: every window shows those thirty rows in red, because there is only one table. Live demo (you type, they follow) · 25 min

One notebook or one script, session20_bokeh, started from the course folder. show(...) writes the HTML file named by output_file and opens it in a browser tab; on the machine that produced the outputs below no browser opens, and the printed lines are identical. To draw inside a notebook instead, run from bokeh.io import output_notebook; output_notebook() once and skip the output_file lines.

  1. A figure, then a glyph (2m). Say: "Two moves. Make an empty plot, then add marks to it. If Plotly Express felt like ordering from a menu, this feels like Matplotlib." In a notebook or script, show writes the file and opens it in a browser tab. 
    import numpy as np
import pandas as pd
import bokeh
from bokeh.plotting import figure, output_file, save, show

sales = pd.read_csv("data/daily_sales.csv", parse_dates=["date"])
boise = sales[sales["store"] == "Boise"]
p = figure(width=800, height=320, x_axis_type="datetime",
           title="Boise daily revenue")
p.line(boise["date"], boise["revenue"], line_width=1.5, color="#667eea")
p.yaxis.axis_label = "revenue ($)"
output_file("first.html", title="Boise daily revenue")
show(p)
print(bokeh.__version__, type(p).__name__, "with", len(p.renderers), "renderer")
    3.10.0 figure with 1 renderer
    Walk the toolbar on the right: pan, box zoom, wheel zoom (click it on first), save, reset. Everything on the plot is an object with properties: p.yaxis.axis_label, p.title.text.
  2. Layers: one line and one set of markers per store (3m). Say: "Bokeh does not pick colors for you. A palette is a list of color codes. legend_label builds the legend." Ask before the print: "Four stores. How many renderers? How many legend entries?" 
    from bokeh.models import NumeralTickFormatter
from bokeh.palettes import Colorblind

stores = ["Boise", "Bend", "Flagstaff", "Asheville"]
store_palette = [Colorblind[8][i] for i in (0, 1, 3, 6)]
colors = dict(zip(stores, store_palette))
sales["month_start"] = sales["date"].dt.to_period("M").dt.to_timestamp()
monthly = sales.groupby(["store", "month_start"], as_index=False)["revenue"].sum()
p = figure(width=800, height=360, x_axis_type="datetime",
           title="Monthly revenue by store")
for store in stores:
    one = monthly[monthly["store"] == store]
    p.line(one["month_start"], one["revenue"], line_width=2, color=colors[store],
           legend_label=store)
    p.scatter(one["month_start"], one["revenue"], size=6, color=colors[store],
              legend_label=store)
p.yaxis.formatter = NumeralTickFormatter(format="$0,0")
p.legend.location = "top_left"
p.legend.click_policy = "hide"
output_file("monthly.html", title="Monthly revenue by store")
show(p)
print(len(p.renderers), "renderers,", len(p.legend.items), "legend items")
    8 renderers, 4 legend items
  3. The table in the middle of the room: ColumnDataSource (3m). Say: "Until now I passed columns straight to each glyph. Making the source myself unlocks everything else today. And look at what I do first: I keep only the columns the page needs." 
    from bokeh.models import ColumnDataSource

sales["day"] = sales["date"].dt.strftime("%a %b %d, %Y")
sales["promo"] = sales["promo_day"].map({0: "no", 1: "yes"})
tidy = sales[["date", "day", "store", "visitors", "revenue", "promo"]].dropna()
source = ColumnDataSource(tidy)
print(source.column_names)
print(len(source.data["revenue"]), "rows;", type(source.data["revenue"]).__name__)
    ['index', 'date', 'day', 'store', 'visitors', 'revenue', 'promo']
2897 rows; ndarray
    A source is a dictionary of equal-length columns. The DataFrame's index came along as a column named index. Six store-days with no revenue were dropped: a marker with no y cannot be drawn.
  4. Glyph arguments become column names (3m). Say: "With a source, a string means: look this column up. A number still means: this value for every mark." Ask: "One call to scatter. How many renderers, how many markers?" 
    from bokeh.transform import factor_cmap

store_color = factor_cmap("store", palette=store_palette, factors=stores)
p = figure(width=800, height=400, title="Daily revenue against foot traffic",
           x_axis_label="visitors per day", y_axis_label="revenue ($)")
p.scatter("visitors", "revenue", source=source, size=5, alpha=0.5,
          color=store_color, legend_group="store")
p.legend.location = "top_left"
p.yaxis.formatter = NumeralTickFormatter(format="$0,0")
output_file("scatter.html", title="Revenue and foot traffic")
show(p)
print(len(p.renderers), "renderer draws", len(tidy), "markers")
    1 renderer draws 2897 markers
  5. A hover that names the day (3m). Say: "@name is this row's value in that column. A format goes in braces. Any column in the source can appear, plotted or not." Hover the top point live: the Saturday of the 2024 Labor Day sale, in Boise. Note the fresh source: a new page needs new objects. 
    from bokeh.models import HoverTool

tips = [("Day", "@day"), ("Store", "@store"),
        ("Visitors", "@visitors{0,0}"), ("Revenue", "@revenue{$0,0}")]
hover = HoverTool(tooltips=tips)
source = ColumnDataSource(tidy)
p = figure(width=800, height=400, title="Hover a point to identify the day",
           tools=["pan", "wheel_zoom", "box_zoom", "reset", hover])
p.scatter("visitors", "revenue", source=source, size=5, alpha=0.5,
          color=factor_cmap("store", palette=store_palette, factors=stores))
output_file("hover.html", title="Hover")
show(p)
print([type(t).__name__ for t in p.toolbar.tools])
    ['HoverTool', 'PanTool', 'WheelZoomTool', 'BoxZoomTool', 'ResetTool']
  6. Break it on purpose: a typo that raises nothing (2m). Say: "Watch. I misspell a column." Run it. "No exception. When I show this plot I get axes and no points, and one line in the terminal: E-1001, BAD_COLUMN_NAME. An empty Bokeh plot is nearly always this." 
    p = figure(width=400, height=250)
renderer = p.scatter("visitors", "revenu", source=ColumnDataSource(tidy))

      "| column exists:", "revenu" in tidy.columns)

  7. Linked panning: share a range (3m). Say: "Two ways to connect plots, and they connect different things. First, the view. Give the second plot the first plot's range object." Zoom the top plot with the wheel; the bottom follows. 
    from bokeh.layouts import column

boise_source = ColumnDataSource(tidy[tidy["store"] == "Boise"])
top = figure(width=800, height=230, x_axis_type="datetime", title="Boise: revenue",
             tools="xpan,xwheel_zoom,reset", active_scroll="xwheel_zoom")
top.line("date", "revenue", source=boise_source, color="#667eea")
bottom = figure(width=800, height=230, x_axis_type="datetime",
                title="Boise: visitors", x_range=top.x_range,      # the link
                tools="xpan,xwheel_zoom,reset", active_scroll="xwheel_zoom")
bottom.line("date", "visitors", source=boise_source, color="#d97706")
output_file("linked_pan.html", title="Linked panning")
show(column(top, bottom))
print(bottom.x_range is top.x_range)
    True
  8. Linked brushing: share a source (5m). This is the reason to learn Bokeh. Say: "Second, the rows. Two plots, one source, a selection tool. I write no linking code at all." Drag a box around the busiest days on the left and wait. Ask: "What are the orange days on the right?" (Sale weekends, summer Saturdays, the weeks before Christmas.) Then let two learners drive: select December on the right. 
    from bokeh.layouts import row

boise_2025 = tidy[(tidy["store"] == "Boise") & (tidy["date"] >= "2025-01-01")]
brush_source = ColumnDataSource(boise_2025)
select_tools = "box_select,lasso_select,tap,reset"
style = dict(source=brush_source, size=6, color="#667eea",
             nonselection_alpha=0.15, selection_color="#d97706")
left = figure(width=400, height=360, title="Drag a box here...", tools=select_tools,
              active_drag="box_select", x_axis_label="visitors",
              y_axis_label="revenue ($)")
left_dots = left.scatter("visitors", "revenue", **style)
right = figure(width=500, height=360, title="...and see when those days were",
               tools=select_tools, active_drag="box_select", x_axis_type="datetime")
right_dots = right.scatter("date", "revenue", **style)
output_file("linked_brush.html", title="Linked brushing")
show(row(left, right))
print(len(brush_source.data["revenue"]), "rows shared by 2 plots |",
      "same source:", left_dots.data_source is right_dots.data_source)
    363 rows shared by 2 plots | same source: True
    Say: "One drag answered: when were the busiest days? No filter, no query, no new chart." Then the opposite slip: "If I had written ColumnDataSource(boise_2025) twice, I would have two tables. No error, and no brushing."
  9. A dropdown that works in a plain HTML file (4m). Say: "When the reader moves a widget in a saved file, what code runs? There is no Python on their machine. Only JavaScript can run. Read these two lines of JavaScript as you would read Python." The plot draws through a view that shows only rows passing a filter; the dropdown changes the filter. 
    from bokeh.models import CDSView, CustomJS, GroupFilter, Select

source = ColumnDataSource(tidy)
store_filter = GroupFilter(column_name="store", group="Boise")
view = CDSView(filter=store_filter)
p = figure(width=800, height=360, title="Boise: daily revenue against foot traffic",
           tools="pan,wheel_zoom,reset")
p.scatter("visitors", "revenue", source=source, view=view, size=5, alpha=0.5)
picker = Select(title="Store", value="Boise", options=stores, width=200)
picker.js_on_change("value", CustomJS(args=dict(flt=store_filter, plot=p), code="""
    flt.group = cb_obj.value;
    plot.title.text = cb_obj.value + ": daily revenue against foot traffic";
"""))
output_file("select.html", title="Store picker")
show(column(picker, p))
print(view.filter.column_name, "=", view.filter.group)
    store = Boise
    cb_obj is the widget that changed. flt and plot exist because they were passed in args. A Python callback (picker.on_change) is silently ignored in a saved file: it needs a running Bokeh server, or the next lesson's tool.
  10. Two ways to save, and what travels (2m). Say: "Same choice as Plotly. cdn is small and needs the internet; inline works offline. And the same warning: every column of every source is in the file." 
    from pathlib import Path

days = ["Mon", "Tue", "Wed", "Thu", "Fri", "Sat", "Sun"]
sales["weekday"] = sales["date"].dt.day_name().str[:3]
by_day = sales.groupby("weekday")["revenue"].mean().loc[days]
for mode in ["cdn", "inline"]:
    name = f"weekday_{mode}.html"
    p = figure(width=600, height=300, x_range=days, title="Mean revenue by weekday")
    p.vbar(x=days, top=by_day.values, width=0.8, color="#667eea")
    output_file(name, title="Weekday", mode=mode)
    save(p)
    print(f"{name:<20} {Path(name).stat().st_size / 1024:8,.0f} KB")
print(by_day.round(0).tolist())

weekday_inline.html     1,362 KB
[6138.0, 5716.0, 5985.0, 6321.0, 7713.0, 10933.0, 9211.0]
Three mistakes to expect
  • A blank plot from a misspelled column. No Python exception: axes, no points, and E-1001 (BAD_COLUMN_NAME) in the terminal that nobody reads. Coach: "Print source.column_names. Read your glyph call aloud, string by string."
  • `RuntimeError: Models must be owned by only a single document` when a cell is rerun or a source is reused on a second saved page. Coach: "Which objects were made in an earlier cell? A new page needs new objects." The habit: create figures and sources in the same cell (or function) that saves them.
  • Two sources where one was meant (no brushing, no error), and its cousin, old-tutorial arguments (plot_width, p.circle(size=...)). Coach the first with: "How many times does ColumnDataSource( appear on this page?" For the second, read the message: it names the replacement (width, scatter).

7.4

Dashboards with Streamlit

65 min
Objectives (from the lesson page)
  • Write a Streamlit app as a plain Python script and run it locally with streamlit run
  • Explain the rerun model, and predict what a variable holds after a widget is used
  • Keep values across reruns with st.session_state and avoid repeated work with st.cache_data
  • Lay out a dashboard with a sidebar, columns and tabs, showing metrics, charts, a table and a download button
  • Test an app without a browser, and describe what it takes to put an app in front of other people
In the room / at home

Room (65 min): the frame, the nine-step demo, lab 7.4-B (the shortlist) and then 7.4-A (the catalog browser) as far as time allows, and Step 1 of the Pinecrest Sales Dashboard. Home: the rest of the project (dashboard.py with filters, four metrics, three tabs, a download and the AppTest check), Exercises 1 to 3 (4 is a stretch), quiz and journal. Deployment is two minutes of talk in the room and a careful read at home: the lesson's six conditions and its three checks before anyone else can open an app.

Mental model to say (10 min frame)

"Think of a spreadsheet with an input cell at the top and formulas below it. Change the input and every formula recalculates at once: you never tell the sheet which cells to update. A Streamlit app behaves the same way, except that the sheet is your script. Whenever a reader changes any widget, Streamlit runs the whole script again, from the first line to the last, with the widget's new value, and replaces what is on the page."

Three mistakes to expect
  • `python app.py` in place of `streamlit run app.py`. The terminal fills with missing ScriptRunContext warnings and nothing opens. Coach: "Read the first word of your command." (The kit's two Streamlit labs are the one exception, by design: run with python they test themselves; see the lab notes.)
  • Expecting a variable to remember. A list, a counter or a flag assigned in the script body is assigned again on every rerun. There is no error, only a number that will not grow. Coach: "Put your finger on line 1 and trace one click to the last line. What is the list at the top?" Then: "Where must it live?"
  • Changing a widget's value after it was drawn (st.session_state["x"] = 0 inside if st.button(...)), and two identical widgets without keys. Both give a red box whose first sentence says exactly what happened. Coach: have the learner read the first sentence aloud, then ask "what runs before the script does?" (A callback.)
