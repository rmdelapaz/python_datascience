7.3 · Interactive Charts with Bokeh: self-check

Q1
A glyph is drawn with p.scatter("visitors", "revenue", source=source, size="visitors"). What does size="visitors" do?
A) Raises an error: a size must be a number
B) Reads each marker's size from the visitors column of the source
C) Writes the word visitors next to each marker
D) Sets every marker to the average number of visitors
Why: With a source, a string argument is always read as a column name, so each row gets its own value. A plain number means the same value for every mark.
A is wrong: A string is allowed: it means a column. size=5 would be the fixed-size form.
C is wrong: Labels are a different glyph (text) or a hover tool.
D is wrong: Nothing is averaged: each row uses its own value, so markers would be hundreds of pixels wide here.
Q2
What does this print?
p = figure(width=300, height=200)
for store in ["Boise", "Bend"]:
    p.line([1, 2], [3, 4], legend_label=store)
    p.scatter([1, 2], [3, 4], legend_label=store)
print(len(p.renderers), len(p.legend.items))
4 2
Why: Every glyph call adds a renderer: two stores times a line and a set of markers is 4. Glyphs that share a legend_label share one legend entry, so the legend has 2 items.
Q3
Two stacked time-series plots draw different columns. You want panning or zooming either one to move both along the date axis. What do you write?
A) Put both plots in one gridplot
B) Give both plots the same title
C) Build each plot from its own copy of the source
D) Create the second plot with x_range=top.x_range
Why: A range object describes what is in view. Two plots holding the same range object can never show different views.
A is wrong: A grid arranges plots and merges toolbars; it does not link their views.
B is wrong: A title is text; it links nothing.
C is wrong: Separate sources break linked selection and do nothing for panning.
Q4
On one page you wrote ColumnDataSource(df) twice, once for each plot. A box selection in the left plot changes nothing in the right one, and there is no error. Why?
A) The selection is stored in a source, and the two plots have two separate sources
B) Selections only link plots that also share an x_range
C) box_select works on one plot per page
D) The DataFrame was not sorted the same way in both plots
Why: Two sources are two tables with the same contents. Selected row numbers are recorded on one of them and the other never hears about it. Create the source once and pass the same variable to every glyph that should be linked.
B is wrong: Ranges link views (panning). Selection travels through the shared source.
C is wrong: Any number of plots can carry selection tools.
D is wrong: Row order is identical here; the problem is that there are two objects.
Q5
What does this print?
source = ColumnDataSource(pd.DataFrame({"x": [1, 2, 3], "y": [4, 5, 6]}))
print(source.column_names, len(source.data["x"]))
['index', 'x', 'y'] 3
Why: Building a source from a DataFrame copies each column in and adds the DataFrame's index as a column named index. Every column in the source travels inside the saved HTML file, shown or not.
Q6
Which Bokeh tooltip shows a row's revenue as $12,345?
A) ("Revenue", "$revenue")
B) ("Revenue", "@revenue:$,.0f")
C) ("Revenue", "@revenue{$0,0}")
D) ("Revenue", "%{revenue}")
Why: In a Bokeh tooltip @name means this row's value in column name, and a format in braces controls the display.
A is wrong: A $ prefix is for special fields such as $x and $index; $revenue is not one.
B is wrong: That is the Plotly hover_data style (a colon and a d3 format). Bokeh uses braces.
D is wrong: %{...} is Plotly's hovertemplate placeholder.

7.3 · Predict, then run

P1
Prints:
p = figure(width=300, height=200)
p.vbar(x=[1, 2, 3], top=[4, 5, 6], width=0.8)
p.line([1, 2, 3], [4, 5, 6])
print(len(p.renderers), [type(r.glyph).__name__ for r in p.renderers])
2 ['VBar', 'Line']
Why: Each glyph call adds exactly one renderer, however many marks it draws: three bars are one VBar renderer, the line is one Line renderer.
P2
Prints:
a = ColumnDataSource(pd.DataFrame({"x": [1, 2, 3]}))
b = ColumnDataSource(pd.DataFrame({"x": [1, 2, 3]}))
a.selected.indices = [0, 2]
print(a.selected.indices, b.selected.indices, a is b)
[0, 2] [] False
Why: A selection is a list of row numbers stored on one source. A second source with the same contents is a different table and knows nothing about it: this is why two plots built from two sources do not brush each other.

7.3 · The lesson page's own quiz

  1. A. Selection is recorded on the ColumnDataSource; glyphs that draw from the same source object show the same selected rows.
  2. C. A date is stored as milliseconds; give the field a date format and name the formatter: formatters={"@date": "datetime"}.
  3. B. A saved file has no Python process behind it; only JavaScript (CustomJS or js_link) can react in the reader's browser.
  4. C. Two glyph calls make two renderers; the second one's glyph is a Scatter.
  5. B. Charts that respond to each other through a shared source are Bokeh's strength. Facets with trendlines and static export are easier in Plotly.

7.4 · Dashboards with Streamlit: self-check

Q7
Line 5 of your app is sales = pd.read_csv(...) on a 200 MB file, with no decorator. A reader opens the page and then ticks a checkbox 10 times. How many times is the file read?
A) 1
B) 11
C) 10
D) 0
Why: The script runs once when the page opens and once more for every widget change: 1 + 10. That is why slow loading belongs in a function decorated with @st.cache_data.
A is wrong: That is what caching would give you. Without it, every rerun repeats line 5.
C is wrong: The first run, when the page opens, also reads the file.
D is wrong: Nothing is skipped: the whole script runs each time.
Q8
What does this print? (The check clicks the button twice.)
at = AppTest.from_string("""
import streamlit as st
if "n" not in st.session_state:
    st.session_state["n"] = 5
if st.button("Double"):
    st.session_state["n"] *= 2
st.write(st.session_state["n"])
""").run()
at.button[0].click().run()
at.button[0].click().run()
print(at.markdown[0].value)
`20`
Why: The starting value 5 is set once, because the if "n" not in st.session_state guard is false on every later rerun. Each click reruns the script with the button returning True, so 5 becomes 10, then 20. st.write shows a number as code, which is why the value prints inside backticks.
Q9
A Reset button must put a slider (which has a key) back to 0. Where does the line that sets the slider's value belong?
A) In a function passed as on_click=, which Streamlit runs before the rerun starts
B) In an if st.button("Reset"): block placed after the slider
C) Inside the function decorated with @st.cache_data
D) Nowhere: a widget's value cannot be changed from code
Why: A callback runs before the script, so the widget has not been created yet in that run and its value in session state may be changed.
B is wrong: By then the slider exists for this run; Streamlit raises cannot be modified after the widget with that key is instantiated.
C is wrong: Cached functions must not touch widgets or per-user state; the cache is shared by all users.
D is wrong: It can, through its key in session state, in a callback.
Q10
Which step of a dashboard is the right one to wrap with @st.cache_data?
A) Filtering the table by the stores and dates the reader chose
B) The whole app, so that nothing ever runs twice
C) A function that draws the sidebar widgets
D) Loading and preparing the CSV file, which is slow and the same whatever the widgets say
Why: Cache the slow steps that do not depend on widgets. The result is stored per set of arguments and returned without running the body again.
A is wrong: Filtering in memory is fast and must reflect the current widget values on every run.
B is wrong: A cached app could not react to its widgets.
C is wrong: Widgets do not belong inside cached functions.
Q11
What does this print? (Two numbers.)
at = AppTest.from_string("""
import streamlit as st
stores = st.multiselect("Stores", ["Boise", "Bend"], default=["Boise"])
if not stores:
    st.warning("Pick a store.")
    st.stop()
st.metric("Stores chosen", len(stores))
""").run()
at.multiselect[0].set_value([]).run()
print(len(at.warning), len(at.metric))
1 0
Why: With no store chosen the script shows the warning and st.stop() ends that run, so the metric line is never reached: one warning, zero metrics. That is the polite way to handle an empty or half-finished input.
Q12
What does st.button("Go") return?
A) True from the first click onward
B) The number of times it has been clicked
C) True only during the one rerun caused by a click, otherwise False
D) The label of the button
Why: A button is not a switch. It reports "I was just clicked" for a single run of the script. Anything that must persist after that run goes into session state.
A is wrong: That would be a toggle or checkbox (st.toggle, st.checkbox).
B is wrong: Streamlit keeps no count; keep one yourself in session state.
D is wrong: Widgets return the reader's input, not their own label.

7.4 · Predict, then run

P1
Prints:
at = AppTest.from_string("""
import streamlit as st
total = st.session_state.get("total", 0)
if st.button("Add 10"):
    total += 10
st.write("Total:", total)
""").run()
for _ in range(3):
    at.button[0].click().run()
print(at.markdown[-1].value)
Total: `10`
Why: Reading from session state is not enough: the new total is never written back, so every rerun starts from 0 again and one click's worth is all that ever shows. The fix is st.session_state["total"] = total inside the if, or a callback.
P2
Prints:
at = AppTest.from_string("""
import streamlit as st
@st.cache_data
def square(n):
    st.session_state["runs"] = st.session_state.get("runs", 0) + 1
    return n * n
answers = [square(3), square(3), square(4)]
st.write(st.session_state["runs"])
""").run()
print(at.markdown[0].value)
`2`
Why: The cache stores one result per set of arguments. square(3) runs the body once and the second square(3) is answered from the cache; square(4) is a new argument, so the body runs again: 2 runs for 3 calls.

7.4 · The lesson page's own quiz

  1. B. Any widget change reruns the whole script from the top; the widget returns its new value.
  2. A. total is reset to 0 on every rerun and the button is True for one run only, so it shows 10 after each click, never more.
  3. C. With the same argument and code, st.cache_data returns a copy of the stored result and skips the function body.
  4. A. An app is a running Python process: it must run on a machine she can reach, with the packages and the data there.
  5. C. Recalculating totals for any stores and dates and downloading the rows needs Python behind the controls. Hover and legend clicks (A) and linked highlighting (B) work in standalone files.

Lab Reference Solutions

Lab 7.3-A · labs/module-20/l7_3-bokeh/margin_brush_solution.py

234 products with a rating; margin runs from 34% to 58%. Source columns: index, name, category, price, margin, rating, review_count (no cost). renderers: 1 + 1 | same source: True. The left plot has seven tools (BoxSelect, LassoSelect, Tap, WheelZoom, Pan, Reset, Hover). margin_brush.html is about 29 KB. Margin of 50% or more: 67 products, mean rating 4.17; under 50%: 167 products, mean rating 4.12; Spearman correlation of margin and rating +0.01.

How the solution works. margin is computed in pandas and cost is left out of table before ColumnDataSource(table) is made, so cost never reaches the file. One style dictionary (source=source, nonselection_alpha=0.1, selection_color="#d97706") is passed to both scatter calls, which guarantees the two glyphs share the source. Both figures get tools="box_select,lasso_select,tap,wheel_zoom,pan,reset" with active_drag="box_select", and a HoverTool whose tooltips use @price{$0,0.00} and @margin{0%}. The page is row(left, right), written with output_file(...) and save(...).

What to accept. Any two plots on one source with a working selection. The finding is a null: mean rating 4.17 against 4.12 and a rank correlation of +0.01. Learners who report "high-margin products are rated higher" from the 0.05 gap have not looked at the spread; it is a useful rehearsal for the capstone's honest-null standard. Common wrong turn: ColumnDataSource(table) typed inside each scatter call: the page works, the brush does not.

Lab 7.3-B · labs/module-20/l7_3-bokeh/category_picker_solution.py

234 rated products in 9 categories. view shows: category = Tents | 24 products to start with. category_picker.html (cdn) is about 21 KB; category_picker_offline.html (inline) about 1,750 KB. Counts the page should show: Accessories 30, Apparel 35, Camp Kitchen 28, Climbing 24, Footwear 25, Packs 22, Sleeping 24, Snow 22, Tents 24.

How the solution works. The scatter draws through view=CDSView(filter=GroupFilter(column_name="category", group="Tents")). The Select widget's CustomJS sets flt.group = cb_obj.value, rewrites the plot title, then loops over source.data["category"] to count matches and writes the sentence into a Div. The slider needs no JavaScript from the learner: slider.js_link("value", line, "location") moves a Span. Everything is built inside build_page() so that the second save (with mode="inline") gets fresh objects; reusing the first page's objects raises RuntimeError: Models must be owned by only a single document.

Checking a learner's page: pick each category and compare the counter with the printed table (Apparel 35 is the largest, Packs and Snow 22 the smallest). A counter that never changes usually means count was not passed in args; the browser console (F12) says count is not defined.

Lab 7.4-B · labs/module-20/l7_4-streamlit/gear_shortlist_solution.py

24 tents. The first metric reads 0 at the start, 1 after adding the first tent, still 1 after adding it again and after choosing a second tent, 2 after adding the second ($259.90 in total: $41.95 + $217.95), and 0 after Clear. The third metric, the ordinary counter, reads 1 on every line. The unfinished starter prints 0, 1, 0, 1, 0: the list forgets.

How the solution works. st.session_state["shortlist"] is created once (if "shortlist" not in st.session_state). The selectbox has key="choice", so the callback add_to_shortlist can read the current choice from session state and append it if it is new; clear_shortlist assigns an empty list. Both buttons use on_click=; neither is wrapped in if. The page is drawn from tents[tents["name"].isin(st.session_state["shortlist"])]. The ordinary variable reruns_plain is left in on purpose: it reads 1 on every line of the check.

What the unfinished starter teaches. Its check prints 0, 1, 0, 1, 0: the click's rerun shows one tent, and the very next rerun (choosing another tent) empties the list. Common wrong answers: keeping if left.button(...) and adding on_click= (the tent is appended twice per click, hidden only by the duplicate guard); creating the list without the if ... not in guard (it is emptied on every rerun, the same bug in new clothes).

Lab 7.4-A · labs/module-20/l7_4-streamlit/catalog_browser_solution.py and test_catalog_browser.py

Start (Tents): Products 24, Median price $298.45, Mean rating 4.25. Tents and Sleeping under $100: 12 products, median $46.95, mean rating 4.07; with In stock only: 11. No category: the warning shows, 0 metrics, 0 errors. After Reset: ['Tents'], (0, 620), False, 24 products. test_catalog_browser.py: 3 tests pass.

How the solution works. load_products is decorated with @st.cache_data and returns only the eight columns the page uses. Three sidebar widgets have keys (categories, price, in_stock); their starting values are set through session state by reset_filters(), which is also the Reset button's on_click callback. After filtering, if view.empty: st.warning(...); st.stop() ends the run politely. Three st.metric calls sit in st.columns(3); the table is st.dataframe(table, hide_index=True, width="stretch"); the download is table.to_csv(index=False).

The file's last lines decide how it was started: get_script_run_ctx(suppress_warning=True) is not None under streamlit run (and under AppTest), so main() runs; under plain python the file calls self_check(), which drives the app with AppTest.from_file(__file__). The pytest file is the same idea in three named tests: opens with Tents (24 products), an empty selection warns without an error, Reset restores all three filters.

Common wrong answers: resetting with st.session_state["price"] = (0, 620) inside if st.button("Reset"): after the slider (the red box says the key cannot be modified after the widget is instantiated); giving the multiselect both default= and a session-state value (Streamlit warns); dollar signs in st.caption text, which Markdown reads as math.

7.3 · a source, bars and a formatted hover
import pandas as pd
from bokeh.models import ColumnDataSource, NumeralTickFormatter
from bokeh.plotting import figure, output_file, save

weather = pd.read_csv("data/store_weather.csv", parse_dates=["date"])
ash = weather[weather["city"] == "Asheville"].copy()
ash["month"] = ash["date"].dt.strftime("%b")
ash["rainy"] = ash["precip_in"] >= 0.10
months = ["Jan", "Feb", "Mar", "Apr", "May", "Jun",
          "Jul", "Aug", "Sep", "Oct", "Nov", "Dec"]
table = ash.groupby("month").agg(high=("high_f", "mean"), rainy=("rainy", "mean"))
table = table.loc[months].reset_index()
source = ColumnDataSource(table)
tips = [("Month", "@month"), ("Rainy days", "@rainy{0%}"),
        ("Mean high", "@high{0} F")]
p = figure(width=700, height=300, x_range=months, tools="save", tooltips=tips,
           title="Asheville: July is the rainiest month")
p.vbar(x="month", top="rainy", width=0.8, source=source, color="#667eea")
p.yaxis.formatter = NumeralTickFormatter(format="0%")
p.y_range.start = 0
output_file("asheville_rain.html", title="Asheville rain")
save(p)
print(source.column_names, "|", len(p.renderers), "renderer,", len(table), "bars")
print(table.round(2).iloc[[0, 5, 6, 7, 11]].to_string(index=False))

7.4 · a small app and its test
import pandas as pd
import streamlit as st

@st.cache_data
def load_weather(path):
    return pd.read_csv(path, parse_dates=["date"])

weather = load_weather("data/store_weather.csv")
city = st.selectbox("City", ["Boise", "Bend", "Flagstaff", "Asheville"])
inches = st.slider("A rainy day has at least this many inches",
                   0.05, 1.00, 0.10, step=0.05)
one = weather[weather["city"] == city]
rainy = one["precip_in"] >= inches
st.metric("Rainy days", f"{rainy.mean():.0%}",
          help="Share of the 731 days in 2024 and 2025")
st.caption(f"{int(rainy.sum())} of {len(one)} days in {city}")
from streamlit.testing.v1 import AppTest

Capstone Kickoff: What a Good Plan Looks Like

There is no answer to mark tonight. Read each plan for five things, in the order of the frame in the workbook: (1) a question with a decision behind it, not a topic; (2) the tables named and the unit of analysis stated (one row per store-day, per customer, per product); (3) one main comparison and a measure with a method that fits it (proportions, medians of a skewed amount, a ratio); (4) a named risk to fairness with a check; (5) an expected chart and what would change the learner's mind. A plan with all five is at Proficient on the first rubric row; one that also says in advance what result would change the reader's mind is heading for Exemplary. Warm-up and Exit Ticket Answers

Warm-up (retrieval from Session 19)
  1. Which kind of seaborn function takes ax=, and what does the other kind return? Answer: Axes-level functions (scatterplot, barplot, histplot, ...) take ax= and return that Axes. Figure-level functions (relplot, displot, catplot) make their own figure and return a FacetGrid.
  2. sns.barplot draws a black line on each bar. With default settings, what is it? Name one setting that shows spread instead. Answer: A bootstrapped 95% confidence interval for the mean (uncertainty of the estimate). errorbar="sd" or errorbar=("pi", 50) shows spread of the data.
  3. You pass 2,903 daily rows to px.bar(sales, x="store", y="revenue"). What do you get, and what should you have done? Answer: 2,903 bar segments stacked into four piles, with no error: Plotly Express does not aggregate. Group with pandas first (groupby("store", as_index=False)["revenue"].mean()), then plot four rows.
  4. monthly has one row per store and month (4 stores, 24 months). What does this print? 
    fig = px.line(monthly, x="month_start", y="revenue", color="store")
print(len(fig.data), fig.data[0].type, len(fig.data[0].x))
    Answer: 4 scatter 24: one trace per store, each a scatter trace in lines mode holding 24 points. A figure is data: you can count it before you look at it.
  5. You wrote a chart with fig.write_html("chart.html", include_plotlyjs="cdn"). Name two things that are true of that file. Answer: It is small because the reader's browser fetches plotly.js from a public server, so the reader must be online; and it contains the data you passed to the figure (every x, y and hover column) as readable text.
Exit ticket
  1. Two Bokeh plots on one page. What must they share for a box selection in one to highlight the same rows in the other? What must they share to pan together? Answer: The same ColumnDataSource object for linked selection (brushing). The same range object (x_range=first.x_range) for linked panning and zooming.
  2. A reader changes one widget in your Streamlit app. What runs? Name the place for a value that must survive, and the decorator for a slow step that must not repeat. Answer: The whole script reruns from the top with the widget's new value. st.session_state keeps values across reruns (per browser tab); @st.cache_data stores a function's result so the slow body runs once.
  3. Write your capstone question letter (A, B, C or D) and the one comparison your plan is built on. Answer: No single answer. Check that it is a comparison (two or more groups, or before and after against something), not a topic, and that the learner can say what would make it unfair. Use the cards to balance your coaching time in Session 21.

Common Wrong Answers and What They Reveal

  • Q2 answered `2 2` or `4 4`: renderers and legend entries are being confused. One glyph call, one renderer; one label, one legend entry.
  • Q3 answered A (gridplot): thinks layout links plots. Layout arranges; a shared range links.
  • Q4 answered B: has merged the two kinds of link. Ask: "What did we share for panning? What for brushing?"
  • Q6 answered B: carried Plotly's :$,.0f into Bokeh. The braces are the tell.
  • Q7 answered 1: has not yet accepted the rerun model; assumes line 5 is skipped once the data is loaded, as it would be in a notebook kernel.
  • Q8 answered `10` or `5`: believes the if "n" not in block runs every time (5) or that the second click starts over (10). Trace the guard.
  • Q9 answered B: will meet the red box in the lab. Let them, then ask what runs before the script.
  • Q12 answered A: treats a button as a switch; the shortlist lab will expose it.
