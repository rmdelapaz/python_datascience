7.3

Interactive Charts with Bokeh

By the end you can
  • Build a figure by adding glyphs and save it with output_file and save
  • Put data in a ColumnDataSource and name its columns in glyph calls
  • Write a hover tool with formatted fields
  • Link plots by a shared range (panning) and by a shared source (brushing)
  • Add a dropdown or slider that works in a plain HTML file
Key ideas
  • Two moves: p = figure(...) makes an empty plot; p.line, p.scatter, p.vbar add glyphs. Each glyph call adds one renderer.
  • Everything is an object with properties: p.yaxis.formatter, p.legend.location, p.title.text.
  • `output_file(name)` then `save(p)` writes the HTML; show(p) also opens it in a browser.
  • A `ColumnDataSource` is the table behind the page. With source=source, a string argument is a column name; a number is the same value for every mark.
  • Hover: ("Revenue", "@revenue{$0,0}"). @name is this row's value; the format goes in braces. Dates need formatters={"@date": "datetime"}.
  • Share a range, share the view: figure(x_range=top.x_range). Share a source, share the rows: pass the same source variable to both glyphs and add box_select.
  • In a saved file only JavaScript can react: js_link copies a widget value into a property; CustomJS runs a few lines. A Python callback needs a server.
  • Every column of every source travels in the file. Build the source from a table that holds only what the page needs. A new page needs new objects (a source belongs to one document).

Worked example: a source, bars and a formatted hover

Asheville is the rainy store city. Summarize two years of weather to twelve rows, put them in a source, and draw bars whose hover shows the share as a percentage. The source holds three columns besides the index, and nothing else travels in the file.

import pandas as pd
from bokeh.models import ColumnDataSource, NumeralTickFormatter
from bokeh.plotting import figure, output_file, save

weather = pd.read_csv("data/store_weather.csv", parse_dates=["date"])
ash = weather[weather["city"] == "Asheville"].copy()
ash["month"] = ash["date"].dt.strftime("%b")
ash["rainy"] = ash["precip_in"] >= 0.10
months = ["Jan", "Feb", "Mar", "Apr", "May", "Jun",
          "Jul", "Aug", "Sep", "Oct", "Nov", "Dec"]
table = ash.groupby("month").agg(high=("high_f", "mean"), rainy=("rainy", "mean"))
table = table.loc[months].reset_index()
source = ColumnDataSource(table)
tips = [("Month", "@month"), ("Rainy days", "@rainy{0%}"),
        ("Mean high", "@high{0} F")]
p = figure(width=700, height=300, x_range=months, tools="save", tooltips=tips,
           title="Asheville: July is the rainiest month")
p.vbar(x="month", top="rainy", width=0.8, source=source, color="#667eea")
p.yaxis.formatter = NumeralTickFormatter(format="0%")
p.y_range.start = 0
output_file("asheville_rain.html", title="Asheville rain")
save(p)
print(source.column_names, "|", len(p.renderers), "renderer,", len(table), "bars")
print(table.round(2).iloc[[0, 5, 6, 7, 11]].to_string(index=False))
['index', 'month', 'high', 'rainy'] | 1 renderer, 12 bars
month  high  rainy
  Jan 47.87   0.21
  Jun 84.33   0.28
  Jul 82.81   0.39
  Aug 83.39   0.34

One vbar call drew twelve bars and added one renderer. The strings "month" and "rainy" are column names in the source; width=0.8 is a plain number, the same for every bar. The tooltip reads @rainy{0%} from the same row. Open asheville_rain.html and hover July: 39% of July days had at least a tenth of an inch of rain.

7.4

Dashboards with Streamlit

By the end you can
  • Write an app as a plain script and start it with streamlit run
  • Explain the rerun model and predict what a variable holds after a click
  • Keep values with st.session_state and avoid repeated work with @st.cache_data
  • Lay out a page with a sidebar, columns and tabs
  • Test an app without a browser, and say what sharing one takes
Key ideas
  • An app is a script. Start it with streamlit run app.py from the folder that holds data/. Stop it with Ctrl+C. Not python app.py, and not in a notebook.
  • The whole script reruns from the top every time a reader changes a widget. Ordinary variables start over. Widgets keep their values.
  • Showing and asking. st.title, st.metric, st.dataframe, st.plotly_chart show things. st.selectbox, st.multiselect, st.slider, st.date_input, st.toggle ask, and return the answer.
  • `st.button` is True for one rerun only. It is not a switch.
  • `st.session_state` is a dictionary kept per browser tab across reruns. A widget with key="x" lives there as st.session_state["x"]. Change a widget's value only in a callback (on_click=).
  • `@st.cache_data` stores a function's result per set of arguments. Use it for slow loading that does not depend on widgets. The cache is shared by all users.
  • `st.stop()` ends the current run after a message: for an empty selection or a half-chosen date range.
  • Sharing means a Python process kept running where readers can reach it, with the packages, the data, access control and no secrets in the code.

Worked example: a small app and its test

How many days count as rainy depends on where you draw the line. This app lets the reader choose the city and the line. The loading is cached; the filtering is not, so it always reflects the widgets.

File rain_app.py:

import pandas as pd
import streamlit as st

@st.cache_data
def load_weather(path):
    return pd.read_csv(path, parse_dates=["date"])

weather = load_weather("data/store_weather.csv")
city = st.selectbox("City", ["Boise", "Bend", "Flagstaff", "Asheville"])
inches = st.slider("A rainy day has at least this many inches",
                   0.05, 1.00, 0.10, step=0.05)
one = weather[weather["city"] == city]
rainy = one["precip_in"] >= inches
st.metric("Rainy days", f"{rainy.mean():.0%}",
          help="Share of the 731 days in 2024 and 2025")
st.caption(f"{int(rainy.sum())} of {len(one)} days in {city}")

Check it without a browser:

from streamlit.testing.v1 import AppTest

def report():
    print(at.selectbox[0].value, at.slider[0].value, "->", at.metric[0].value,
          "|", at.caption[0].value)

at = AppTest.from_file("rain_app.py", default_timeout=30).run()
report()
at.selectbox[0].select("Asheville").run()
report()
at.slider[0].set_value(0.5).run()
report()
Boise 0.1 -> 9% | 68 of 731 days in Boise
Asheville 0.1 -> 24% | 172 of 731 days in Asheville
Asheville 0.5 -> 6% | 44 of 731 days in Asheville

Three runs of the script, three different pages. AppTest ran the script in memory, changed a widget and ran it again, exactly as a reader's click would. Boise is rainy on about one day in ten at the default line; Asheville on about one in four; raise the line to half an inch and Asheville's share falls to 6%. No value was carried from one run to the next except the widgets' own.

Glossary

  • Glyph: a family of marks added to a Bokeh figure: line, scatter, vbar.
  • Renderer: what one glyph call adds to a figure; p.renderers lists them.
  • ColumnDataSource (CDS): the table behind a Bokeh page: a dictionary of equal-length columns.
  • Linked panning: two plots that share a range object, so they always show the same view.
  • Linked brushing: two plots that share a source, so a selection in one highlights the same rows in the other.
  • View (CDSView): a filter between a source and a glyph that shows only some rows.
  • CustomJS: a few lines of JavaScript attached to a widget or property, run in the reader's browser.
  • Rerun: one top-to-bottom run of a Streamlit script, triggered by opening the page or changing a widget.
  • Widget: a control (selectbox, slider, button) whose function returns the reader's input.
  • Session state: st.session_state: a dictionary Streamlit keeps for one browser tab across reruns.
  • Callback: a function passed as on_click= or on_change=; Streamlit runs it before the rerun.
  • Cache: stored results of a function decorated with @st.cache_data, reused when the arguments repeat.
  • AppTest: Streamlit's testing tool: runs an app in memory and lets code read the page and operate widgets.
  • Deploying: keeping an app running on a machine other people can reach.
