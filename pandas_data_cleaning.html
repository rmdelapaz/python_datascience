🧰 The Repair Bench

Someone at Pinecrest exported the orders from an old system, a few people edited the file by hand, two branch offices appended their own rows, and now it has landed on your desk as orders_messy.csv. This is what real data looks like. Working analysts routinely report that preparing data takes more of their time than analyzing it, and the reason is simple: every chart, average and model downstream inherits whatever is wrong with the table it was built on.

💡 Mental Model: The Gear Repair Bench

Every Pinecrest store has a repair bench for rental tents that come back damaged. The technician follows the same routine every time. Inspect the whole tent and write down every problem before fixing any. Repair one thing at a time, the structural damage first (poles, then seams, then small holes). Check each repair before starting the next. Never throw away the damage report. And some stains do not come out: the honest move is to note them on the tag, not to paint over them.

Cleaning data is the same routine. The raw file is the tent as it came back, and you never alter it. Your code is the repair log.

graph TD A["Audit: list every problem"] --> B["Pick one problem"] B --> C["Fix it in code, on a copy"] C --> D{"Check: did it work?"} D -->|"not yet"| C D -->|"yes, next problem"| B D -->|"nothing left to fix"| E["Verify, then save"]

🤔 Why This Matters

If you compute average order value on this file as it stands, pandas will refuse, because the totals are text. If you force the conversion carelessly, you will get an average inflated by a row that says 55690.00 where the customer paid $556.90. Neither result announces itself as wrong. The method in this lesson, audit, fix, check, is how you make sure you find such things before your readers do.

✅ Two Rules for the Whole Lesson

The raw file is read-only. Never open it in a spreadsheet program and fix cells by hand: nobody could tell afterward what was changed. Every fix is a line of code, so the whole job can be rerun, reviewed and corrected.

An Audit You Can Rerun

Looking at rows finds problems by luck. Counting finds them systematically. This small function summarizes any table, and you will run it again at the end to measure what changed.

def audit(df):
    """One row per column: its dtype, how many values are missing, how many are distinct."""
    return pd.DataFrame({
        "dtype": df.dtypes.astype(str),
        "missing": df.isna().sum(),
        "distinct": df.nunique(),
    })

before = audit(raw)
print(before)
print("rows:", len(raw), " exact duplicate rows:", raw.duplicated().sum())

Work on a copy called clean, and leave raw exactly as loaded so you can always compare. Column names are text, and the .str methods work on them just as they do on a column: strip the spaces from both ends, make everything lowercase, and replace inner spaces with underscores.

💡 Why Structure Comes First

Had you tried .astype("int64") on order_id before removing the TOTAL row, it would have failed. Fix the shape of the table (names, rows) before the contents of its cells: later steps become simpler, and counts such as "how many rows have a bad date" are not inflated by duplicates.

🔢 Numbers Stored as Text

Find What Is Not a Number

as_number = pd.to_numeric(clean["order_total"], errors="coerce")
not_number = as_number.isna() & clean["order_total"].notna()

📅 Dates in Three Formats

Three groups of people typed dates into this file, each in their own way.

d = clean["order_date"]
print(d[d.str.contains("/", na=False)].head(2).tolist())
print(d[d.str.contains(",", na=False)].head(2).tolist())

Output

['01/01/2024', '01/01/2024']
['January 3, 2024', 'January 3, 2024']

A robust way to handle several known formats is to parse the column once per format, with errors="coerce" so that values in the other formats become NaT ("not a time", the missing value for dates).

iso = pd.to_datetime(d, format="%Y-%m-%d", errors="coerce")
us = pd.to_datetime(d, format="%m/%d/%Y", errors="coerce")
long = pd.to_datetime(d, format="%B %d, %Y", errors="coerce")
print(iso.notna().sum(), us.notna().sum(), long.notna().sum())

Output

17632 1827 812

Each attempt understood its own format and nothing else: 17,632 ISO dates, 1,827 in month/day/year form, 812 written out. Now combine them. fillna() accepts another Series and fills each gap with the value at the same row.

parsed = iso.fillna(us).fillna(long)
print(parsed.isna().sum())
print(d[parsed.isna()].value_counts(dropna=False))

2. Converting Before Cleaning

ValueError: could not convert string to float: '$107.90'

What it means: astype stops at the first value it cannot convert and shows it to you. Fix: remove the symbols first, or use pd.to_numeric(..., errors="coerce") to find all the offenders at once.

3. A Dollar Sign Is Special in a Pattern

['$1,249.00', '$87.50']

What happened: no error, and no change. With regex=True the replacement text is treated as a pattern, in which $ means "end of the text", not a dollar sign. Fix: leave regex at its default of False for plain text, as in the second line, and always look at the result.

🛠️ Step 1: Structure (5 min)

Each function takes a DataFrame and returns a new one. The mappings go at the top as named constants, where they are easy to find and extend.

import pandas as pd

pd.set_option("display.width", 150)
pd.set_option("display.max_columns", 20)

STORE_FIXES = {"Web": "Online", "Website": "Online", "Bosie": "Boise",
               "Flagstaf": "Flagstaff", "Ashville": "Asheville", "Bend Or": "Bend"}
STATUS_FIXES = {"complete": "completed", "refunded": "returned", "canceled": "cancelled"}


def fix_structure(df):
    """Tidy the headers, drop the TOTAL row and exact duplicates, type the two id-like columns."""
    df = df.copy()
    df.columns = df.columns.str.strip().str.lower().str.replace(" ", "_")
    df = df.rename(columns={"discount_%": "discount_pct"})
    df = df[df["order_id"] != "TOTAL"].drop_duplicates().reset_index(drop=True)
    df["order_id"] = df["order_id"].astype("int64")
    df["discount_pct"] = df["discount_pct"].astype("int64")
    df["customer_id"] = pd.to_numeric(df["customer_id"], errors="coerce").astype("Int64")
    return df

def fix_numbers(df, item_subtotal):
    """Make totals and shipping numeric; repair negative and 100-times-too-large totals."""
    df = df.copy()
    total = pd.to_numeric(df["order_total"].str.replace("$", "").str.replace(",", "")).abs()
    lost_decimal = total / df["order_id"].map(item_subtotal) > 50
    df["order_total"] = total.where(~lost_decimal, (total / 100).round(2))

    ship = pd.to_numeric(df["shipping_cost"].str.strip().str.lower().replace({"free": "0"}))
    df["shipping_cost"] = ship.where(~((df["channel"] == "store") & ship.isna()), 0.0)
    return df

def fix_dates(df):
    """Parse the three date formats; blank and impossible dates become NaT."""
    df = df.copy()
    d = df["order_date"]
    parsed = pd.to_datetime(d, format="%Y-%m-%d", errors="coerce")
    for fmt in ["%m/%d/%Y", "%B %d, %Y"]:
        parsed = parsed.fillna(pd.to_datetime(d, format=fmt, errors="coerce"))
    df["order_date"] = parsed
    return df

🛠️ Step 5: Validate and assemble (5 min)

df.pipe(func) is simply func(df), written so that steps read top to bottom in the order they happen. Extra arguments go after the function name. The last step, validate, lets nothing through that breaks a rule.

def validate(df):
    """Raise an AssertionError if the cleaned table breaks a rule. Return it unchanged otherwise."""
    assert df["order_id"].is_unique, "duplicate order ids"
    assert set(df["store"]) == {"Online", "Boise", "Bend", "Flagstaff", "Asheville"}, "unexpected store"
    assert set(df["status"]) == {"completed", "returned", "cancelled"}, "unexpected status"
    assert df["order_total"].dropna().between(0, 5000).all(), "order total out of range"
    assert df["shipping_cost"].dropna().isin([0, 6.95, 14.95]).all(), "unexpected shipping cost"
    return df


def clean_orders(path="data/orders_messy.csv", items_path="data/order_items.csv"):
    """Read the messy orders export and return a cleaned DataFrame."""
    items = pd.read_csv(items_path)
    item_subtotal = (items["quantity"] * items["unit_price"]).groupby(items["order_id"]).sum()
    return (
        pd.read_csv(path)
        .pipe(fix_structure)
        .pipe(fix_text)
        .pipe(fix_numbers, item_subtotal)
        .pipe(fix_dates)
        .pipe(validate)
    )

❓ Common Questions at This Stage

Would it not be faster to fix the file by hand in a spreadsheet?

For three cells, once, perhaps. But a hand edit leaves no record of what changed, cannot be reviewed, and has to be repeated from scratch when a new export arrives. It is also how many of this file's problems got there. Twenty lines of code are slower today and faster every day after.

How do I know when the data is clean enough?

"Clean" is relative to a question. For revenue by store, the store names and totals must be right, and a missing payment method does not matter. A practical stopping rule: every column has the dtype it should, every category column has only values you recognize, your assertions pass, and you can state how many values are missing and why. Perfection is not on offer. Documented, checked and good enough for the question is.

Should I remove outliers?

Not for being outliers. Remove or correct a value when you have evidence that it is an error, as with the eight totals that were 100 times their item subtotals. The twelve bulk orders are extreme and true, and deleting them would remove real revenue. Sometimes an analysis is better without extreme values, and then you say so and show the result both ways. Lesson 4.2 returns to outliers with proper tools.

What is the difference between NaN, NaT and <NA>?

They all mean "missing", for different dtypes: NaN in float and text columns, NaT in datetime columns, and <NA> in the nullable types such as Int64. You rarely need to care which one you have, because .isna(), .notna(), .fillna() and .dropna() treat them all alike.

The cleaned file still has 620 blanks. Can they be recovered?

Some can, with information from outside the file. You recovered 30 dates from neighboring rows in Exercise 4, and the bonus challenge recovers order totals from the item lines. The rest (customer ids, payment methods) exist only in another table. Bringing two tables together on a shared key is exactly what Lesson 2.5 teaches.

📝 Lesson Summary

🎓 Key Takeaways

  • Audit first: dtypes, missing counts and distinct counts reveal most problems before you read a single row
  • Work on a copy, in code, in order: structure (headers, stray rows, duplicates), then text, then numbers, then dates, then missing values
  • Text: .str.strip(), then case, then a mapping dictionary with .replace(); turn placeholders such as none into real missing values
  • Numbers: pd.to_numeric(errors="coerce") finds what is not a number; .describe() finds what is not plausible
  • Dates: parse each known format with errors="coerce" and combine with fillna()
  • An outlier is a question: correct it only on evidence. A missing value is a decision: repair, leave and report, or drop with subset=, and write the decision down
  • Finish with a before-and-after audit and assertions, and package the job as a function
