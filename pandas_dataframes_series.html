🧭 From Arrays to Tables

In Module 1 you worked with NumPy arrays: fast blocks of numbers of one type. They have two limits that real business data runs into immediately. An array holds one type, but a product has a name (text), a price (a decimal), a review count (a whole number) and a launch date. And an array knows its values only by position: position 5 means nothing until you remember what you put there.

pandas removes both limits. It gives every value a label, and it lets columns of different types sit side by side in one table. Underneath, each column is still an array, so everything you learned about dtypes and whole-array arithmetic still applies. You are adding names to the race cars, not giving them up.

💡 Mental Model: The Labeled Shelf

Picture the stockroom at a Pinecrest store. A Series is one shelf of bins, and every bin has a label on the front: you can ask for "the bin labeled TNT-1002" instead of "the second bin from the left". A DataFrame is a whole shelving unit: several shelves (columns) lined up so that the same label runs across all of them. Pull the label TNT-1002 and you get that product's name, price and rating together.

🤔 Why This Matters

Loading, cleaning, grouping, merging, plotting, statistics, SQL results, scraped pages: in this course they all arrive as a DataFrame or leave as one. The handful of moves in this lesson (look at it, pick columns, pick rows, add a column, sort, count) are the ones you will type hundreds of times. Learn them slowly here and everything after gets easier.

The New Idea: Alignment by Label

Here is the first thing a Series does that an array cannot. Suppose Bend's figures arrive for only four days, and in a different order.

bend = pd.Series([6719.33, 7083.36, 4132.92, 3675.57],
                 index=["Sun", "Sat", "Mon", "Tue"], name="bend")
print(boise + bend)

Output

Fri         NaN
Mon    10094.92
Sat    19471.93
Sun    16080.92
Thu         NaN
Tue    10258.70
Wed         NaN
dtype: float64

pandas did not add the first value to the first value. It matched labels: Monday with Monday, Saturday with Saturday, wherever they sat. Days that exist in only one Series have nothing to be added to, so the result is NaN, pandas's marker for "missing" (the same nan you met in Lesson 1.1). Two NumPy arrays of lengths 7 and 4 would simply have raised an error.

⚠️ Alignment Is a Feature and a Trap

Alignment protects you from adding Monday to Sunday by accident. It also means that if two Series have labels that do not match (different spellings, or one was re-sorted and renumbered), arithmetic quietly fills the result with NaN. When a calculation produces unexpected NaNs, compare the two indexes first.

📋 The DataFrame

A DataFrame is a table: several Series standing side by side, sharing one index. The most direct way to build one by hand is from a dictionary whose keys become the column names.

Three things are worth understanding here.

  • Text columns are str. pandas has a dedicated string dtype and uses it for text automatically. Older tutorials and older versions of pandas show object for text columns. If you see object on a column today, it usually means the column holds a mixture of types, which is a problem to investigate.

🔖 The Index

Every DataFrame has two sets of labels: the index for rows and the columns for, well, columns.

💡 Row Labels Are Not Row Numbers

With the default index, a row's label and its position are the same number, so it is easy to believe they are the same thing. They are not. After you filter or sort, the labels travel with their rows, and the row labeled 19 may now be sitting first. The next section gives you one tool for labels and another for positions, so you can always say which you mean.

🎯 Selecting: [], .loc and .iloc

Columns with Square Brackets

prices = products["price"]

print(type(small), small.shape)

Output

<class 'pandas.Series'> (242,)

One name gives a Series. A list of names gives a DataFrame, which is why you see double brackets: the outer pair is "select", the inner pair is the list. products[["price"]], a list with one name in it, is a one-column DataFrame.

Rows and Cells by Label: .loc

.loc takes row labels, then a comma, then column labels, in the same "rows, comma, columns" order as a 2-D NumPy array.

print(by_sku.loc["TNT-1002", "price"])                 # one row label, one column label
print(by_sku.loc["TNT-1002", ["name", "price", "rating"]])
print(by_sku.loc["TNT-1001":"TNT-1003", "category":"brand"])

Output

217.95

rating                                    3.7

TNT-1003    Tents  3-Person Tent     Pinecrest

Read the three results in turn. One row label and one column label give a single value. One row label and a list of columns give a Series, whose index is the column names. (Its dtype is object because a row mixes text and numbers: the legitimate use of that dtype.) And two slices give a DataFrame.

⚠️ A .loc Slice Includes Its End

"TNT-1001":"TNT-1003" returned three rows, including TNT-1003, and "category":"brand" included brand. Label slices are inclusive at both ends, because with labels there is no obvious "one past the end". This is the one place where Python's usual stop-is-excluded rule does not hold.

Rows and Cells by Position: .iloc

print(products.iloc[0, 5])              # row 0, column 5
print(products.iloc[:3, :2])            # first 3 rows, first 2 columns
print(products.iloc[-1, 0])             # last row, first column

Output

299.95
        sku                                 name
0  TNT-1001     Granite Fork Drift 1-Person Tent
1  TNT-1002  Cedar Notch Ridgeline 2-Person Tent
2  TNT-1003     Pinecrest Solstice 3-Person Tent

.iloc ignores labels completely and counts from 0, with negative numbers counting from the end and slices that exclude their stop. It behaves exactly like indexing a NumPy array.

The two rules meet in this one-line experiment on the default index, where labels and positions happen to be the same numbers:

print(len(products.loc[0:3]), len(products.iloc[0:3]))

Output

4 3

.loc[0:3] means "labels 0 through 3", four rows. .iloc[0:3] means "positions 0 up to but not including 3", three rows. Neither is wrong. They are answering different questions, and now you know which is which.

🔍 Filtering Rows

The question you will ask most often is "which rows satisfy this condition?". The answer is the boolean mask from Lesson 1.2, now with labels. It takes two steps: a comparison builds a Series of True/False, and that Series, placed in square brackets, keeps the rows where it is True.

is_tent = products["category"] == "Tents"
print(is_tent.head(3))
print(is_tent.sum())

tents = products[is_tent]
print(tents.shape)

Output

0    True
1    True
2    True
Name: category, dtype: bool
24
(24, 13)

Because True counts as 1, .sum() of a mask counts the matching rows and .mean() gives the fraction that match. You will use both constantly.

Join conditions with & (and), | (or) and ~ (not), and put each condition in its own parentheses.

Four helper methods cover the conditions that are awkward to write with comparison operators:

sleep_out = products[products["category"].isin(["Tents", "Sleeping"])]
mid_price = products[products["price"].between(50, 100)]
not_in_stock = products[~(products["stock_status"] == "in_stock")]

Output

  • .isin([...]): the value is one of a list (cleaner than a chain of |)
  • .between(a, b): from a to b, both ends included
  • ~: flips a mask, so "not in stock" is the 44 products that are low or out
  • .str.contains("..."): the text contains this. The .str accessor opens up string methods for a whole column, and Lesson 2.3 uses it heavily

The .str accessor has many more methods. Two you will meet again soon are .str.startswith() and .str.endswith(): every tent's SKU begins with TNT, so this finds the same 24 products as the category filter did.

➕ Adding and Changing Columns

Assign to a column name that does not exist yet and pandas creates it. The right-hand side is usually arithmetic on other columns, done on every row at once.

products["margin"] = products["price"] - products["cost"]
products["margin_pct"] = (products["margin"] / products["price"] * 100).round(1)
print(products[["sku", "price", "cost", "margin", "margin_pct"]].head(3))

Output

        sku   price    cost  margin  margin_pct
0  TNT-1001  299.95  187.74  112.21        37.4
1  TNT-1002  217.95  131.94   86.01        39.5
2  TNT-1003  459.95  301.97  157.98        34.3

No loop. products["price"] - products["cost"] subtracts two Series row by row (aligned on the index), and the result is stored as a new column on the right-hand edge of the table.

A Column That Depends on a Condition

np.where(condition, value_if_true, value_if_false) is the vectorized if/else.

products["price_band"] = np.where(products["price"] >= 200, "premium", "standard")
print(products["price_band"].value_counts())

Output

price_band
standard    198
premium      44
Name: count, dtype: int64

To change some rows of an existing column, use .loc with a mask for the rows and the column name, on the left of the =:

products.loc[products["price"] < 25, "price_band"] = "budget"
print(products["price_band"].value_counts())

Output

price_band
standard    166
premium      44
budget       32
Name: count, dtype: int64

Read products.loc[mask, "price_band"] = "budget" as "in products, for the rows where the mask is true, in the price_band column, store this". One object, one .loc, one assignment. Remember this shape: it is the answer to the trap in the next section.

assign(): A New Table with an Extra Column

with_tax = products.assign(price_with_tax=(products["price"] * 1.06).round(2))
print(with_tax.shape, products.shape)

Output

(242, 17) (242, 16)

.assign() returns a new DataFrame with the extra column and leaves the original untouched (16 columns still). Use it when you want to try something without changing the table you are working on, or when you chain several steps together.

🧬 Copy-on-Write

In Lesson 1.1 you learned that a slice of a NumPy array is a view: a window onto the same memory, so writing through the window changes the original. For arrays that is efficient. For tables it used to be a constant source of bugs, because it was hard to predict whether a filtered piece of a DataFrame was a window or a photocopy.

pandas settles the question with one rule, called copy-on-write:

💡 The Rule

Every DataFrame or Series you derive from another one behaves as an independent copy. Changing one object never changes another. The only way to change a DataFrame is to operate on that DataFrame itself.

Watch the rule at work. Take the tents out, put them on sale, and check the catalog.

tents = products[products["category"] == "Tents"]
tents["price"] = tents["price"] * 0.9          # a 10% sale, on the subset only
print(tents["price"].head(2).round(2).tolist())
print(products.loc[products["category"] == "Tents", "price"].head(2).tolist())

Output

[269.96, 196.16]
[299.95, 217.95]

The subset changed. The catalog did not. tents behaves as its own table from the moment it is created, no warning, no surprise.

💡 Why "Copy-on-Write"?

Copying a large table every time you filter it would be slow and wasteful. So pandas cheats, safely: a derived object may quietly share memory with its parent for as long as nobody changes anything. The moment you write to one of them, pandas makes the real copy first. You get the speed of a view and the safety of a copy, and you never have to think about which one you have.

The Consequence: Chained Assignment Never Works

The rule has one consequence that catches everybody once. This line looks like it sets every tent's price to zero:

import warnings

with warnings.catch_warnings(record=True) as caught:
    warnings.simplefilter("always")
    products[products["category"] == "Tents"]["price"] = 0      # chained assignment
print(caught[0].category.__name__)
print(str(caught[0].message).splitlines()[1])
print(products.loc[products["category"] == "Tents", "price"].head(2).tolist())

Output

ChainedAssignmentError
Such chained assignment never works to update the original DataFrame or Series, because the intermediate object on which we are setting values always behaves as a copy (due to Copy-on-Write).
[299.95, 217.95]

It does nothing to products, and pandas raises a ChainedAssignmentError warning to tell you so. (The warnings code around it is only there to capture the warning so that the lesson can print it. In your notebook you would simply see the warning in red.) Here is why. The line is really two steps:

  1. products[products["category"] == "Tents"] creates a new, temporary DataFrame of 24 tents.
  2. ["price"] = 0 writes into that temporary table, which is then thrown away.

Two sets of brackets, one after the other, with an = at the end: that is chained assignment, and under copy-on-write it can never reach the original. The fix is the shape you already learned, a single .loc on the table you want to change:

demo = products.copy()
demo.loc[demo["category"] == "Tents", "price"] = demo["price"] * 0.9
print(demo.loc[demo["category"] == "Tents", "price"].head(2).round(2).tolist())
print(products.loc[products["category"] == "Tents", "price"].head(2).tolist())

Output

[269.96, 196.16]
[299.95, 217.95]

This time the change lands on demo. (We worked on demo, a deliberate full copy made with .copy(), so that products keeps its real prices for the rest of the lesson.)

✅ Two Sentences to Keep

To change a table, write df.loc[rows, "column"] = value or df["column"] = ... on that table. To work on a piece without touching the original, just take the piece: it is already independent.

⚠️ Common Mistakes

These are the six messages (and one silence) that nearly every pandas learner meets in the first week. Each one is pandas telling you precisely what it could not do. Read from the bottom of the traceback, as you practiced in Lesson 0.1.

1. A Column Name That Is Almost Right

products["Price"]

Error

KeyError: 'Price'

What it means: there is no column with exactly that name. Names are case-sensitive, and a stray space counts. Fix: print the real names and copy one.

print(products.columns.tolist())

Output

['sku', 'name', 'category', 'product_type', 'brand', 'price', 'cost', 'weight_kg', 'color', 'rating', 'review_count', 'stock_status', 'launch_date', 'margin', 'margin_pct', 'price_band']

2. Using and / or Between Masks

products[products["price"] > 100 and products["rating"] > 4.5]

Error

ValueError: The truth value of a Series is ambiguous. Use a.empty, a.bool(), a.item(), a.any() or a.all().

What it means: Python's and wants one True or False on each side, and a Series is 242 of them. It is the same message NumPy gave you in Lesson 1.1. Fix: use &, | and ~, which work element by element.

3. Forgetting the Parentheses

products[products["price"] > 100 & products["rating"] > 4.5]

Error

TypeError: Cannot perform 'rand_' with a dtyped [float64] array and scalar of type [bool]

What it means: & binds more tightly than >, so Python tried to compute 100 & products["rating"] first. The message is cryptic; the cause is always missing parentheses. Fix: wrap every condition.

picks = products[(products["price"] > 100) & (products["rating"] > 4.5)]
print(len(picks))

Output

14

4. A Position Where a Label Was Expected

by_sku.loc[0]

Error

KeyError: 0

What it means: .loc looks for a row labeled 0, and the labels of by_sku are SKUs. Fix: .iloc for positions, .loc for labels.

print(by_sku.iloc[0]["name"])
print(by_sku.loc["TNT-1001", "name"])

Output

Granite Fork Drift 1-Person Tent
Granite Fork Drift 1-Person Tent

5. A New Column of the Wrong Length

products["on_sale"] = [True, False, True]

Error

ValueError: Length of values (3) does not match length of index (242)

What it means: a list assigned to a column must have one value per row. Fix: build the column from other columns (products["price"] < 50 has 242 values automatically), or assign a single value, which is repeated for every row.

6. Comparing with NaN

print(products["rating"].mean().round(3))
print((products["rating"] == np.nan).sum(), products["rating"].isna().sum())

Output

4.138
0 8

What happened: no error, but a wrong answer. == np.nan found 0 missing ratings when there are 8, because NaN is defined as not equal to anything, itself included. Fix: always test with .isna() or .notna(). (The first line also shows that .mean() quietly skips missing values, unlike NumPy's mean.)

7. Chained Assignment

You saw this one in Copy-on-Write: df[mask]["col"] = value changes nothing and raises a ChainedAssignmentError warning. A warning does not stop your program, so it is easy to scroll past. Fix: df.loc[mask, "col"] = value.

❓ Common Questions at This Stage

Tutorials I find online show object for text columns and talk about a SettingWithCopyWarning. Why does mine look different?

Those were written for earlier versions of pandas. Text columns now get the dedicated str dtype, and copy-on-write replaced the old, unpredictable view-or-copy behavior, so that warning no longer exists. Advice such as "add .copy() after every filter to silence the warning" is no longer needed: a filtered table is already independent. The code in such tutorials usually still runs. When it does not, the fix is nearly always the single .loc assignment from this lesson.

Can I write products.price instead of products["price"]?

For reading, yes, when the name is a valid Python identifier and does not collide with a DataFrame method. It fails for names with spaces (Order Total), and for names such as count or shape it silently gives you the method or attribute instead of the column. You also cannot create a new column that way. This course uses square brackets everywhere because they always work.

When should I set an index, and when should I leave the default?

Leave the default unless you have a reason. A meaningful index earns its place when you look rows up by a key often (by_sku.loc["TNT-1002"]), when you want arithmetic between tables to line up on that key, or for dates in time series, which Lesson 2.7 covers. For filtering, sorting and grouping, an ordinary column works just as well.

Is there a way to loop over the rows?

There is (for row in df.itertuples():), and you should treat it as a last resort. A loop over rows gives up the compiled, whole-column speed you measured in Module 1, often by a factor of a hundred. Almost anything you would do in a row loop can be written as column arithmetic, a mask, np.where or, soon, a groupby. If you catch yourself writing a row loop, pause and ask what the column version would be.

📝 Lesson Summary

🎓 Key Takeaways

  • A Series is an array plus an index of labels; a DataFrame is a set of Series sharing one index, each with its own dtype
  • Arithmetic between Series aligns on labels, and labels without a partner produce NaN
  • Greet every table with shape, head(), info() and describe(); text is str, and dates stay text until converted
  • df["col"] is a Series, df[["a", "b"]] a DataFrame; .loc selects by label (slices include the end), .iloc by position (slices exclude it)
  • Filter with a boolean mask; combine conditions with &, |, ~ and parentheses; test for missing values with .isna()
  • New columns come from whole-column arithmetic; change selected rows with df.loc[mask, "col"] = value
  • Copy-on-write: every derived object behaves as a copy, so chained assignment never changes the original
  • sort_values() orders rows (labels travel with them) and value_counts() counts categories
