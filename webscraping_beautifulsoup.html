🌳 A Page Is a Tree

In Lesson 6.1 you downloaded the practice shop's front page and got back about twelve thousand characters of HTML. Somewhere in that string are twenty product names and twenty prices. You could hunt for them with string methods, and for one page on one day it might even work. There is a much better way, and it starts with seeing the page the way a browser does.

HTML is made of elements. An element has a tag name, optional attributes, and content, which can be text or more elements. Here is one product from the shop's catalog, exactly as the server sends it:

<li class="product-card" data-sku="TNT-1001">
    <h2 class="product-name"><a href="products/TNT-1001.html">Granite Fork Drift 1-Person Tent</a></h2>
    <p class="product-category">Tents</p>
    <p class="price" data-price="299.95">$299.95</p>
    <p class="rating" data-rating="4.0">★ 4.0 <span class="review-count">(8 reviews)</span></p>
    <p class="stock low-stock">Low stock</p>
</li>

The li (list item) element contains an h2 heading and four p paragraphs. The heading contains an a link. One paragraph contains a span. Elements inside elements inside elements: that is a tree, and the page as a whole is one big tree with html at the root.

💡 Mental Model: A Labeled Filing Cabinet

Think of the page as a filing cabinet. Drawers hold folders, folders hold sheets, and nearly everything has a label on it: class="price", data-sku="TNT-1001". You do not find a document by counting "third drawer, second folder, fifth sheet". You read the labels: "the sheet labeled price inside the folder labeled product-card". Scraping well is mostly the skill of choosing good labels.

The whole job follows one pattern, which you will build piece by piece in this lesson.

graph TD A["Fetch the page with requests"] --> B["Parse the HTML into a tree"] B --> C["Select the repeated block"] C --> D["One dictionary per block"] D --> E["List of dictionaries"] E --> F["DataFrame, then check it"]

✅ You Do Not Need to Know HTML Well

You need to recognize tags, attributes and nesting, and you just did. Your browser does the rest: right-click anything on a page and choose Inspect to see the element behind it, with its labels. Keep the practice shop open in a browser tab for this whole lesson and inspect as you go.

🍲 Making the Soup

Beautiful Soup is the library that turns an HTML string into a tree you can search. It is installed as beautifulsoup4 and imported from bs4. Start a new notebook with the same polite setup as last time, and one helper that fetches a page and parses it. (Working offline? Serve pinecrest-practice-site.zip as described in Lesson 6.1: unzip it in your project folder, run python -m http.server 8001 there, and set BASE_URL = "http://127.0.0.1:8001/practice/shop/".)

import re
import time
from urllib.parse import urljoin

import pandas as pd
import requests
from bs4 import BeautifulSoup

pd.set_option("display.width", 150)
pd.set_option("display.max_columns", 20)

BASE_URL = "https://rays-python-datascience.netlify.app/practice/shop/"
HEADERS = {"User-Agent": "pinecrest-course-bot/1.0 (learning project; contact: you@example.com)"}
DELAY = 1        # seconds between requests: the Crawl-delay in the shop's robots.txt


def get_soup(url):
    """Fetch one page politely and return it as a parsed tree."""
    resp = requests.get(url, headers=HEADERS, timeout=10)
    resp.raise_for_status()
    return BeautifulSoup(resp.content, "html.parser")


soup = get_soup(BASE_URL)
print(type(soup))
print(soup.title)
print(soup.title.string)

Output

<class 'bs4.BeautifulSoup'>
<title>All products, page 1 | Pinecrest Outfitters (practice site)</title>
All products, page 1 | Pinecrest Outfitters (practice site)

BeautifulSoup(markup, "html.parser") builds the tree. The second argument names the parser: "html.parser" comes with Python and is all you need here. The result, by tradition called soup, stands for the whole document. soup.title is a shortcut for "the first title element", and .string is the text inside it.

💡 Why resp.content and Not resp.text

You met the encoding problem in Lesson 6.1: when a server does not announce a charset, resp.text can come out scrambled. Given the raw bytes, Beautiful Soup reads the page's own <meta charset="UTF-8"> tag and decodes correctly whatever the server said. Passing resp.content is the habit that never bites.

An Element Has a Name, Attributes and Text

card = soup.find("li")

print(card.name)
print(card.attrs)
print(card["data-sku"])
print(card.get_text(" | ", strip=True))

Output

Granite Fork Drift 1-Person Tent | Tents | $299.95 | ★ 4.0 | (8 reviews) | Low stock

soup.find("li") returns the first li element in the page, which is the product card you saw above. It is a Tag object. Its attributes behave like a dictionary, so card["data-sku"] reads one. Notice that class is a list: an element can carry several classes, separated by spaces in the HTML.

get_text() collects all the text inside an element and its descendants. The two arguments used here are worth remembering: a separator to put between the pieces, and strip=True to trim the whitespace around each one.

🔎 Finding Elements

Two methods do most of the searching. find() returns the first match, or None. find_all() returns a list of every match, possibly empty. Both can filter by tag name and by attributes.

cards = soup.find_all("li", class_="product-card")
print(len(cards))

first = cards[0]
link = first.find("a")
print(link.get_text())
print(link["href"])
print(first.find("p", class_="price").get_text())

Output

20
Granite Fork Drift 1-Person Tent
products/TNT-1001.html
$299.95

Three things to notice.

  • The keyword is class_, with an underscore, because class is a reserved word in Python.
  • You can search inside any element, not only inside soup. first.find("a") looks only within the first card. This is the key move in scraping: find the repeated block, then search within each block.
  • The link's href is relative: products/TNT-1001.html, not a full URL. You will turn it into a full one with urljoin, as you did for robots.txt.

🎯 CSS Selectors That Last

Web designers pick out elements to style with a compact pattern language called CSS selectors. Fragile and Sturdy

There are always many selectors that reach the same element. Both of these find the price of the third product:

fragile = soup.select_one("main > ul > li:nth-of-type(3) > p:nth-of-type(2)")
sturdy = soup.select_one('li[data-sku="TNT-1003"] p.price')

print(fragile.get_text(), sturdy.get_text())

Output

$459.95 $459.95

The first is a set of directions by position: "inside main, the list, the third item, the second paragraph". Browser tools will happily generate selectors like this for you with "Copy selector". It works today. It breaks the day the shop adds a "New!" badge above the price, reorders the products, or wraps the list in one more div, and it breaks silently, by returning some other paragraph.

The second reads the labels: "the price inside the card for TNT-1003". It keeps working through all of those changes, because it depends on what the element means, not where it happens to sit.

💡 Choosing a Selector That Survives

  • Prefer names that describe meaning: classes such as price and product-card, ids, and data- attributes. Site owners put them there for their own code, so they tend to stay.
  • Avoid position (nth-of-type, nth-child, long > chains) unless nothing else identifies the element.
  • Keep it short. Every extra step in a selector is one more thing that can change. li.product-card p.price is enough.
  • Avoid classes that describe looks, such as blue or col-4. Those change with the next redesign.

Read Data from Attributes When You Can

price_tag = first.select_one("p.price")

print(price_tag.get_text())
print(price_tag["data-price"])

Output

The visible text is formatted for people: a dollar sign today, perhaps "From $299" or a thousands separator tomorrow. The data-price attribute holds the plain number for the site's own scripts. When a page offers a machine-readable value, take it. Either way, what you get from HTML is always a string, and converting it with float() is your job.

🗂️ One Card, One Dictionary

You can now reach every field of a card. The next step is the one that makes scraping manageable: write one function that turns one block into one dictionary. The function knows about the HTML. The rest of your code never has to.

def parse_card(card):
    """Turn one product card into a flat dictionary. First version."""
    link = card.select_one("h2.product-name a")
    return {
        "sku": card["data-sku"],
        "name": link.get_text(strip=True),
        "category": card.select_one("p.product-category").get_text(strip=True),
        "price": float(card.select_one("p.price")["data-price"]),
        "rating": float(card.select_one("p.rating")["data-rating"]),
        "url": urljoin(BASE_URL, link["href"]),
    }

print(parse_card(first))

🕳️ When Something Is Missing

A function that works on page 1 has been tested on twenty products. Try it on page 3.

soup3 = get_soup(urljoin(BASE_URL, "page-3.html"))
cards3 = soup3.select("li.product-card")
print(len(cards3))

Output

20
rows = [parse_card(c) for c in cards3]

Error

KeyError: 'data-rating'

Some card on this page has a rating paragraph with no data-rating attribute. Do not guess which. Ask the page.

for c in cards3:
    tag = c.select_one("p.rating")
    if "data-rating" not in tag.attrs:
        print(c["data-sku"], tag)

Output

PCK-1002 <p class="rating no-rating">No reviews yet</p>
PCK-1009 <p class="rating no-rating">No reviews yet</p>

Two packs have no reviews yet, so the shop shows different HTML for them: no number, no data-rating, no review count. Real sites are full of this. A product with no reviews, no image, no sale price, a "call for price" label: the markup changes whenever the data does.

💡 The Two Ways Lookups Fail, and the Two Ways to Ask Safely

  • A missing attribute: tag["data-rating"] raises KeyError. Ask with tag.get("data-rating") instead, which returns None.
  • A missing element: select_one() and find() return None, and the next thing you do to that None raises AttributeError. Check if tag (or if tag is None) before using it.

Now decide, field by field, what missing should mean. A product without a rating is normal: record a missing value. A product without a SKU or a price is not something you expected: let that crash, loudly, so that you find out. Here is the version that draws that line, and picks up two more fields while it is at it.

def parse_card(card):
    """Turn one product card into a flat dictionary."""
    link = card.select_one("h2.product-name a")
    rating = card.select_one("p.rating").get("data-rating")      # None when there is no rating
    count_tag = card.select_one("span.review-count")             # None when there are no reviews
    reviews = int(re.search(r"\d+", count_tag.get_text()).group()) if count_tag else 0
    stock_classes = card.select_one("p.stock")["class"]          # ['stock', 'low-stock']
    return {
        "sku": card["data-sku"],
        "name": link.get_text(strip=True),
        "category": card.select_one("p.product-category").get_text(strip=True),
        "price": float(card.select_one("p.price")["data-price"]),
        "rating": float(rating) if rating else None,
        "review_count": reviews,
        "stock_status": stock_classes[1].replace("-", "_"),
        "url": urljoin(BASE_URL, link["href"]),
    }

page3 = pd.DataFrame([parse_card(c) for c in cards3])
print(page3.loc[page3["rating"].isna(), ["sku", "name", "rating", "review_count"]])
print(page3["stock_status"].value_counts().to_dict())

Output

         sku                               name  rating  review_count
9   PCK-1002    Pinecrest Headwater 30L Daypack     NaN             0
16  PCK-1009  Juniper Vane Sawtooth 30L Daypack     NaN             0
{'in_stock': 16, 'out_of_stock': 3, 'low_stock': 1}

The two unrated packs are now rows with NaN in rating and 0 reviews, which is exactly what they are. The review count came from the text (8 reviews) with a small regular expression, \d+, meaning "one or more digits". The stock status came from the element's second class, which is steadier than its display text.

✅ That Crash Was the Process Working

Nobody writes a parser that handles every case on the first try, because nobody can see every case on the first page. Write it for what you can see, run it on more pages, and let the errors show you what you assumed. Each fix makes the function a little more honest about the data.

📄 Following Pagination

The catalog is spread over several pages. At the bottom of each is a navigation block. Compare the first page's with the last page's:

<!-- index.html -->
<nav class="pagination" aria-label="Pages">
    <span class="prev disabled">← Previous</span>
    <span class="current">Page <span class="page-number">1</span> of <span class="page-total">13</span></span>
    <a class="next" rel="next" href="page-2.html">Next →</a>
</nav>

<!-- page-13.html -->
<nav class="pagination" aria-label="Pages">
    <a class="prev" rel="prev" href="page-12.html">← Previous</a>
    <span class="current">Page <span class="page-number">13</span> of <span class="page-total">13</span></span>
    <span class="next disabled">Next →</span>
</nav>

On every page but the last, "Next" is a link (a.next) with an href. On the last page it is a plain span, so the selector nav.pagination a.next finds nothing. That gives you a loop that needs no page count and no guessing at URL patterns: follow the next link until there is none.

graph TD A["Start at the first page"] --> B["Fetch and parse the page"] B --> C["Parse every card"] C --> D{"Is there a next link?"} D -->|yes| E["Wait, then follow it"] E --> B D -->|no| F["Done: return all rows"] 
def scrape_catalog(start_url, max_pages=50):
    """Follow 'next' links from start_url. Returns (rows, pages_fetched)."""
    rows, url, pages = [], start_url, 0
    while url and pages < max_pages:
        soup = get_soup(url)
        rows.extend(parse_card(c) for c in soup.select("li.product-card"))
        pages += 1
        next_link = soup.select_one("nav.pagination a.next")
        url = urljoin(url, next_link["href"]) if next_link else None
        time.sleep(DELAY)
    return rows, pages

rows, pages = scrape_catalog(BASE_URL)
print(pages, "pages,", len(rows), "products")

Output

13 pages, 242 products

That took about fifteen seconds, nearly all of it the one-second pauses. That is the right speed. You are a guest on this server, the whole job is 13 requests, and nothing about your analysis gets better if it finishes in two seconds instead.

Read the loop once more for its details:

  • urljoin(url, next_link["href"]) resolves the relative link against the page it was found on, so it works wherever the pages live.
  • max_pages is a seat belt. If a site's "next" link ever points back to an earlier page, a loop without a limit would run forever, sending requests the whole time.
  • If any page fails, raise_for_status() inside get_soup() stops the loop with an error instead of quietly returning a partial catalog.

⚠️ Do Not Count Pages by Hand

Writing for n in range(2, 14) and building f"page-{n}.html" works today. When the shop adds its 261st product there will be a page 14 that your loop never visits, and nothing will tell you. Let the site say where the end is.

🔬 Detail Pages

A listing shows a summary. The full record is usually one click away, on a page of its own, and you collected the address of each one in the url column. Open a product page in your browser and inspect it. The parts worth having are a description and a specifications table:

<p class="description">Granite Fork 1-person tent in moss. Pitches fast, ...</p>
<table class="specs">
    <tbody>
        <tr><th scope="row">Brand</th><td>Granite Fork</td></tr>
        <tr><th scope="row">Type</th><td>1-Person Tent</td></tr>
        <tr><th scope="row">Weight</th><td>1.34 kg</td></tr>
        ...
    </tbody>
</table>

Each row of the table is a label in a th and a value in a td. A dictionary comprehension turns the whole table into a lookup, and then the same pattern as before applies: one function, one page, one dictionary.

def parse_product_page(soup):
    """Turn one product detail page into a flat dictionary."""
    specs = {tr.th.get_text(strip=True): tr.td.get_text(strip=True)
             for tr in soup.select("table.specs tr")}
    return {
        "sku": soup.select_one("span.sku-value").get_text(strip=True),
        "brand": specs.get("Brand"),
        "weight": specs.get("Weight"),
        "color": specs.get("Color"),
        "launched": specs.get("Launched"),
        "description": soup.select_one("p.description").get_text(strip=True),
    }

snow = products[products["category"] == "Snow"].head(5)

detail_rows = []
for url in snow["url"]:
    detail_rows.append(parse_product_page(get_soup(url)))
    time.sleep(DELAY)

details = pd.DataFrame(detail_rows)
print(details.drop(columns="description"))

⚠️ Count the Requests Before You Loop

Five detail pages took five seconds. All 242 would take four minutes and send 242 requests to get fields you may not need. On a real site with a hundred thousand products the same loop is a day of traffic. Before you write a loop over detail pages, ask whether the listing already has what your question needs, and fetch details only for the rows that matter.

📊 Tables with read_html

When the data you want is already an HTML <table>, you can skip the selectors. pandas.read_html() finds every table in a page and returns a list of DataFrames. The shop's price list page has two tables. Fetch the page yourself, so that your User-Agent and timeout apply, and hand pandas the bytes.

import io

resp = requests.get(urljoin(BASE_URL, "price-list.html"), headers=HEADERS, timeout=10)
resp.raise_for_status()

tables = pd.read_html(io.BytesIO(resp.content), encoding="utf-8")
print(len(tables), "tables")
print(tables[0].head(3))
print(tables[1])

💡 read_html or Beautiful Soup?

Use read_html when the data is a real <table> and the visible text is all you need. Use Beautiful Soup when the data is in cards, lists or scattered elements, when you need attributes such as href or data-price, or when rows need special handling. Many projects use both.

⚠️ Common Mistakes

These five messages account for most of the errors you will see while scraping. Each is short once you know what it is pointing at.

1. Using the Result of a Search That Found Nothing

soup.select_one("p.sale-price").get_text()

Error

AttributeError: 'NoneType' object has no attribute 'get_text'

What it means: there is no p.sale-price on the page, so select_one() returned None, and None has no get_text. The error names NoneType, not your selector, which is why it confuses people. Fix: check the selector against the page in your browser (a typo in a class name is the usual cause), and if the element is truly optional, test for None before using it.

2. Treating a List of Elements as One Element

soup.select("p.price").get_text()

Error

AttributeError: ResultSet object has no attribute "get_text". You're probably treating a list of elements like a single element. Did you call find_all() when you meant to call find()?

What it means: select() and find_all() return a list, even when it holds one element. Beautiful Soup's message tells you exactly that. Fix: use select_one() for a single element, or loop: [p.get_text() for p in soup.select("p.price")].

3. Writing class Instead of class_

exec('soup.find_all("p", class="price")')

Error

SyntaxError: invalid syntax (<string>, line 1)

What it means: class is a Python keyword and cannot be an argument name. (The exec() wrapper is only here so that this page can show you the error; in your notebook the cell simply refuses to run.) Fix: class_="price", or use a selector: soup.select("p.price").

4. Requesting a Relative Link

requests.get(link["href"], headers=HEADERS, timeout=10)

Error

MissingSchema: Invalid URL 'products/TNT-1001.html': No scheme supplied. Perhaps you meant https://products/TNT-1001.html?

What it means: the href in the page is products/TNT-1001.html, which only makes sense relative to the page it came from. Fix: urljoin(page_url, link["href"]), always, even when a site's links happen to be absolute today.

5. Looking for Content That Is Not in the HTML

deals = get_soup(urljoin(BASE_URL, "deals.html"))
print(len(deals.select("li.deal")), "deals found")
print(deals.select_one("p#loading").get_text())

Output (no error, and no data)

0 deals found
Loading deals…

What happened: in your browser the deals page shows a list of offers. In the HTML that requests received there are none, only a "Loading" message, because the list is added by JavaScript after the page loads, and requests does not run JavaScript. Your selector is fine. The data simply is not there yet. Fix: that is the whole of Lesson 6.3. The clue to remember is this one: visible in the browser, absent from resp.text.

❓ Common Questions at This Stage

How do I find the right selector on a page I have never seen?

Open the page in a browser, right-click the value you want and choose Inspect. Look at the element and walk up through its parents until you find the repeated block (here, li.product-card). Note the classes and data- attributes on the way. Then test in Python on one page: len(soup.select("your selector")) should equal the number of items you can see. If it is 0, check for typos, then check whether the content is added by JavaScript.

Should I use "html.parser" or "lxml"?

"html.parser" is built into Python and handles ordinary pages well. "lxml" is faster on very large pages and is already installed in the course environment (pandas uses it for read_html). The two can build slightly different trees from badly broken HTML, so pick one per project and stay with it. Everything in this lesson works the same with either.

Why not pull values out with regular expressions?

A regular expression is a good tool for a small pattern inside a piece of text you have already isolated, as with \d+ on (8 reviews). It is a poor tool for finding that piece in the first place, because HTML nests, attributes come in any order, and whitespace varies. Use the tree to locate, and string tools to clean.

My scraper worked last month and returns nothing today. What happened?

Almost certainly the site changed its HTML and a selector no longer matches. This is the normal cost of scraping, and it is why the count check in this lesson matters: it turns a silent failure into a loud one. Inspect the page again, update the selector in your one parsing function, and rerun. If the site offers an API, this is a good moment to switch to it.

🎓 Key Takeaways

  • A page is a tree of elements with tags, attributes and text; BeautifulSoup(resp.content, "html.parser") builds it
  • find() and select_one() return one element or None; find_all() and select() return a list
  • Good selectors use meaning (classes, ids, data- attributes), not position, and are as short as they can be
  • Find the repeated block, then write one function that turns one block into one dictionary
  • Missing attributes raise KeyError and missing elements give None: decide per field whether missing is normal or an error
  • Follow the "next" link until there is none, with a pause between requests and a page limit
  • Check a scrape before trusting it: the site's own count, unique keys, plausible values
  • pd.read_html() reads real tables in one call; fetch the page yourself and pass it the bytes
